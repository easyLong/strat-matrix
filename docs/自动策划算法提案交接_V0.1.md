2026-11-03 更新：本文件保留首轮只读交接设计。提案现已升级为算法库内不可变冻结对象，Java 正式提交与 Python 幂等确认已实现，当前契约与发布条件以[Java正式提交与确认](自动策划Java正式提交与确认_V0.1.md)为准。

日期：2026-11-03。当前只建立 Java 读取 Python 算法提案的只读契约，**尚未切换正式结果写入方**。`planning.auto-schedule.enabled` 继续保持关闭。

## 调用与职责

```text
宿主调度 → Java 自动策划任务 → Python Pipeline 计算
                               ↓
Java 携带冻结业务配置读取提案 ← Python 只读提案接口
                               ↓
待实现：Java 校验并提交业务库批次／槽位 → Python 确认算法任务已被接收
```

Java 使用 `AutoSchedulePort.proposal` 调用受内部令牌保护的 `POST /api/internal/planning-pipelines/{pipeline_id}/proposal`。请求只有 `business_config_version` 和 `business_config`；业务配置包含每周策划日、调度星期和时刻、营销上限、热点占比。接口只支持 `ordinary_only` Pipeline，不创建或修改正式批次、槽位与内容状态。

返回的 `schema_version=1`、`pipeline_id`、周期、策略和匹配任务 ID／指纹、业务及算法配置版本、账号快照、槽位数组、热点普通选题兜底和 `proposal_hash` 构成可复核交接对象。每个槽位带稳定的 `slot_id`、账号快照、投放日、选题资料、经营作用及槽位类型。`proposal_hash` 对整个返回对象（不含它自身）做规范 JSON 的 SHA-256；同一冻结输入和业务配置重复读取应得到相同指纹。

Python 复用旧正式提交代码中的冻结输入、策略、匹配任务、组合结果校验与 `build_final_plan`，避免另写一套组合规则。若 Java 传入的五项业务配置与 Python 已冻结输入不一致，接口明确拒绝；这意味着配置迁移和冻结传递未对齐时不能启用 Java 自动策划。

## 尚需实现，不能据此启用 Java 自动策划

1. Pipeline 固定记录正式结果归属，Java 归属的任务在组合完成后停在“待业务提交”，Python Worker 不再自行写正式结果；旧 Python 归属任务仍按旧路径完成，避免升级窗口中途改写归属。
2. Java 在同一个业务库事务中校验 `schema_version`、`proposal_hash`、周期、账号与槽位唯一性、选题／热点状态和配置版本，并幂等写入自动批次、槽位及任务提交凭证；不得仅凭 Python 的 `succeeded` 状态将业务任务标为完成。
3. Java 成功落库后向 Python 发送幂等确认。确认失败时 Java 保留“待确认”，宿主调度重试确认；Python 只保存 Java 批次引用和算法任务状态，不触碰 Java 业务库。
4. 接通 Java 统一结果查询、热点 T-1 补题和内容状态对账；发布业务库 V3 槽位迁移与自动任务表，完成跨服务失败恢复验收后才开启调度。

当前运行中的旧 Python 正式提交路径保留，以上步骤全部完成前不能把提案接口视为正式业务闭环。
