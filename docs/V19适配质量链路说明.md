# V19适配质量链路

2026-11-02。本轮实现账号映射、选题主关联标签、五路召回和模型联合精判。它以独立策略`builtin-v19-quality-v1`运行，复用现有匹配任务、租约、冻结输入、向量适配及结果接口。

## 1. 范围

```text
准备记录冻结账号、选题及日期
  → 创建匹配任务，同时冻结规则、词表、模型及提示词版本
  → Worker分批处理主关联标签、账号映射、需求向量、五路召回、配对精判
  → 只保留通过精判的Top30
  → 临时复用V2容量与组合分配，输出匹配提案
```

本轮不是完整V19排期系统：未实现独立7～8条备用候选池、历史T2补缺、CP-SAT两阶段排期或热点局部重优化。现有本周流量／转化位置规则仍保留。当前策略固定`evaluation_only=true`，禁止提交正式策划批次；没有切换全局周自动策划策略，也不触发内容生产。

## 2. 账号映射

- 先使用`godp_account_mapping_rule`中生效且版本匹配的规则；分类继承、末级覆盖、明确OFF及条件文本沿用已有解析服务。
- 未知专业描述可由受限模型选择现有末级ID，输出关系和逐字原文证据。模型只能补充UNKNOWN，不能覆盖人工规则，不自动把派生结果发布成全局规则。
- 完整冻结画像优先于旧资料中的人设简称。输入模型的账号资料只包含人设、家庭身份、兴趣、性别和风格，不包含账号ID、属主UM号、昵称、组织、粉丝数或互动元数据。
- 无年龄／职业字段，不推断对应身份；年轻家庭不等于已知年龄、有娃须有明确依据；性别只能来自性别字段。风格独立保留，不变成主题标签。
- 未知维持Known=0，不作为明确OFF。主主题能力未知时暂缓该关系，记录`unmapped_primary_topic`，不宣称已判为不适合。

现有50条初始映射仍为草稿。五个长描述测试账号在`reviewed`模式下使用受限映射，未启用或修改这些草稿。该样本未实际覆盖人工生效OFF，相关保护由回归测试验证。

## 3. 主关联标签

根据标题、大纲、摘要及内容类型，在同版发布词表中选择：

- T3：1个主主题、0～4个关联主题。
- T4／T5：各0～6个明确标签，无依据可为空。
- 主标签系数1.0，关联标签0.5，父分类不额外计分。

禁止新造ID、返回分类节点、跨维度或重复标签；整批缺失、额外选题或不合法输出均不作为成功结果入缓存。

本轮多标签保存在V19派生缓存和任务质量报告中，未覆盖原有T1～T6单选标签、历史向量或前端选题详情展示。

## 4. 五路召回

先检查当前普通非营销范围、地域、可用日期、已知历史及T3内容边界；主／关联主题中的明确OFF不可被高分恢复。

默认配额为T3=60、T6=60、T4=30、T5=30、探索=20，共200条配额。各路独立排序，按选题ID合并去重，再统一打分，最多输出100条；不足按实际数量。

```text
S3 = 已知末级能力与选题主关联系数的加权平均
S4／S5 = 已知标签上的平均适配；无可判断信息时为0.5
S6 = (1 + cosine(账号需求能力向量, 选题需求向量)) / 2

RecallScore = 0.45×S3 + 0.15×S4 + 0.15×S5 + 0.25×S6
```

T3主主题必须有有效能力，未知关联不直接按0分惩罚；明确OFF仍阻断整个关系。探索优先已知历史较少出现的允许主题，历史不足时稳定排序，不虚构新颖度信息。T2不进入召回加分。

需求路复用已有选题T6向量；账号需求服务能力使用全项目共享向量模型生成并缓存。此路不使用整份画像向量冒充需求向量。

## 5. 模型精判

模型联合阅读账号原始信息、能力边界、条件、需求及风格，与选题标题、大纲、完整标签路径和需求进行配对判断。

输出`PRIORITY／ACCEPT／DROP`、主题／需求／客群／场景／风格五项分数、条件成立与否、具体原因。模型DROP或条件未明确成立时均不能入选。

```text
BasePrecision = 0.40×J_topic + 0.25×J_need + 0.15×J_aud
              + 0.10×J_scene + 0.10×J_style
FinalPrecision = BasePrecision - repeat_weight×RepeatPenalty
```

基础重复检查采用冻结历史标题的字符二元组Jaccard相似度；完全同标题直接排除。它是当前可解释的基础实现，未宣称已完成历史内容语义降重。历史重复惩罚独立于静态模型缓存，每任务重新计算，不重复扣分。

当前测试策略参数：总精判最低0.65、核心主题最低0.60、相邻方向主题最低0.80、重复惩罚权重0.10。相邻方向的专门门槛是在五账号人工复核时增加的实验参数，用于避免其他高分补偿专业方向偏弱；它不是客户已确认的统一标准，仍需更大标注样本校准。

通过者按最终分排序保留Top30。不为流量／转化类型加适配分，也不以热度兜底恢复不适合的选题。旧V2余弦分和新精判分含义不同，不能拿分数均值直接计算“准确率提升”。

## 6. 持久化及冻结

新增两个策划自有派生表，全部字段有中文注释：

| 表 | 用途 |
| --- | --- |
| godp_matching_ai_cache | 校验通过的主关联标签、账号映射、需求向量及静态配对精判；同键结果不覆盖，失败不缓存 |
| godp_matching_quality_run | 关联现有匹配任务ID，保存阶段、进度、映射证据、召回路径、精判原因及报告指纹 |

原匹配任务仍是唯一执行队列。创建任务只做数据库读取和快照写入，不在页面请求事务内调用模型。冻结内容包含词表、映射规则实际内容、模型名、参数、各模型任务的提示词版本及T6向量指纹，不保存API Key。

Worker每轮默认最多4次模型调用、120秒后不接纳新的模型调用；正在进行的请求仍使用原客户端超时。模型调用前后沿用现有任务续租。预算耗尽保存缓存和进度，再把同一个任务置回queued；`batch_yield`是分批让出执行，不是业务失败。进程中断后可由现有过期租约领取恢复，重建计算使用已保存缓存。

初始标签按8条一批，账号精判最多30条一批；若召回超过30条，会分批精判完全部召回再取Top30，而不是先截断30条再判断。缓存键包含真实内容、规则／路径指纹、词表、映射、提示词及模型版本；相同ID但标题／大纲变化不能复用。

当前提示词组合为`v19-quality-2`：账号映射使用修正后的第2版，主关联标签、需求向量适配、配对精判保留各自未变的第1版契约，冻结快照中有`prompt_contracts`明细。已有原型任务保留审计，不覆盖历史结果。

暂未新增统一宿主唤醒、常驻执行器或完整大规模任务恢复体系。当前是在已有Worker中接入新执行器，非宣称行内调度改造完成。

## 7. 查询与提交校验

现有内部接口继续使用：

- `GET /api/internal/matching-tasks/{task_id}`：任务状态及执行尝试。
- `GET /api/internal/matching-tasks/{task_id}/inputs`：原冻结输入及规则、模型、提示词版本。
- `GET /api/internal/matching-tasks/{task_id}/result`：策划提案、分数、原因和五阶段摘要。
- 新增`GET /api/internal/matching-tasks/{task_id}/quality`：主关联标签、账号映射、五路召回、逐对精判及缺口。

沿用原内部令牌鉴权。Java可沿用宿主通用转发，不需要新写一套页面业务处理。

质量报告写入受任务租约保护。保存提案时再次校验报告指纹与输入／策略／租约绑定、Top30资格、模型DROP、条件、主题底线、评分及原因、地域、历史、日期、经营作用和重复容量，不能通过直接调用结果提交接口绕过精判。

## 8. 部署及验收

在`python-backend/`应用`matching_quality_schema.sql`，或运行现有`python -m app.init_planner_db`，创建两个派生表。数据源及模型仍使用已有MySQL配置，未新增环境变量或Java模块。

可复用本地验收入口：

```bash
python -m app.run_quality_matching_acceptance --cycle YYYY-MM-DD \
  --output ../run/v19-quality-acceptance.json
```

仅允许本地夹具，固定使用E2E-ORD10-001／003／004／005／010。`--new-test-run`仅可归档本脚本相同五账号、已结束且未正式提交的测试准备记录，保留原任务结果，再创建新测试；不能用于生产数据或进行中的任务。

同一份冻结输入另行运行旧V2纯计算作为对照，不写回旧策略结果。真实测试输出保存在忽略的`run/`目录，业务结论以[对照验收记录](V19五账号对照验收_2026-11-02.md)为准。
