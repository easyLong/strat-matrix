# 选题标签体系升级完整方案 V1.0（评审稿）

日期：2026-10-18。

依据：本次提供的《总体层级及选题标签体系》全文、当前前端和后端实现、接口文档V1.8流程评审稿。本稿提出改造方案，不代表业务规则已批准或功能已实现。

## 1. 先统一“二层变三层”的含义

当前页面基本是“维度 → 平铺标签”，例如“T3 主题域 → 本地生活”。

本次附件明确要求T3、T4、T5采用最多二级标签树，且“不继续向三级扩展”。因此推荐的改造是：

```text
界面第1层：T3 内容主题（维度）
界面第2层：金融与财富（一级分类L1）
界面第3层：信用卡（二级标准标签L2）
```

界面三层展示，业务标签树两级。选题实际绑定L2叶子，L1按标签树自动归属；维度名称不作为可打标节点。

本方案不额外增加“信用卡 → 年费”或“运动 → 骑行”的L3。若确实需要L1、L2、L3三级业务树，那是另一版规则，应重新确认，不能与附件的两级约束混用。

## 2. 本次变化的完整范围

| 维度 | 当前实现 | 建议目标 |
| --- | --- | --- |
| T1 业务属性 | 可维护平铺字典，通常按单个标签处理 | 结构化营销属性、适用范围及属地/组织约束；用于准入校验 |
| T2 经营作用 | 可维护字典，流量/转化按单选处理 | 固定为流量/转化，不由运营新增枚举；参与最终周期内容组合 |
| T3 内容主题 | 主题域平铺，要求单选 | 一级内容领域、二级标准主题；1个主主题，0～2个关联主题 |
| T4 目标客群 | 平铺且单选 | 一级客群维度、二级标准客群；0～3个标签 |
| T5 使用场景 | 生活场景平铺且单选 | 一级场景类型、二级标准场景；0～3个标签 |
| T6 用户需求 | 全局需求词条、稳定ID、相似度复用及向量 | 每条选题1条核心需求自然语言描述，由模型生成，支持修改当前选题结果，不提供客户维护的全局词表 |

六个维度保持不变；T3显示名由“主题域”统一为“内容主题”，T5由“生活场景”统一为“使用场景”。

这轮属于数据与交互升级，不能只在现有标签旁加一个父分类下拉框。

## 4. 六个维度的业务规则

### 4.1 T1：结构化业务属性

| 字段 | 建议规则 |
| --- | --- |
| 营销属性 | 营销/非营销，来自已确认的业务来源事实 |
| 适用范围 | 全国、省级、城市级、分支机构级、自定义范围 |
| 适用区域 | 使用稳定行政区编码；按所选范围填写，支持多个目标区域 |
| 适用组织 | 分支机构范围使用稳定组织编码；不能用城市名称代替组织 |
| 自定义范围 | 保存可执行的区域/组织集合及组合关系；仅填写一句自由文本不能参与准入判断 |

全国不要求附属城市；省级要求明确省编码；城市级要求明确城市编码；分支机构级要求明确组织及上下级口径。账号位置是否属于范围应依据行政区/组织映射判断。

营销资格和地域明确不满足时排除；缺少必要范围信息时标记“信息不足”，不能默认全国，也不能让模型猜测。

“普通/营销/热点”是选题来源或类型；“营销/非营销”是业务属性，两者分别保存。例如热点选题也可能具有营销属性，不能从热点来源直接推断为非营销。普通来源是否允许营销业务属性、营销资格字段由谁提供，需要与最新PRD统一。

本稿沿用附件的准入方向；具体准入条件进入版本化规则，T1不作为软适配加分项。

### 4.2 T2：固定经营作用

只有流量、转化两个值。选题结果单选；固定枚举只读，运营仍可在账号经营策略中配置阶段目标比例。

T2在最终周期内容组合时生效，不作为第一轮账号与选题语义适配的加减分项。附件中的“最终3篇”应理解为示例，实际按账号当前周期N个配置槽位执行。

不能直接约定“所有营销选题都是转化、所有热点都是流量”；具体由规则或识别结果确定。热点尚未定题时如何保留经营作用意图、某类候选不足如何降级，仍需单独确认。

### 4.3 T3：主主题与关联主题

- 正式选题主主题必须且只能1个，关联主题0～2个。
- 全部选择L2叶子，主主题不得同时出现在关联主题中，关联主题不得重复。
- L1只负责归类、管理和规则继承，不能作为正式选题主主题提交。
- 例如主主题“福利与权益 / 消费优惠”，关联主题“金融与财富 / 信用卡”和“本地生活 / 本地餐饮”。

“暂无匹配叶子”属于待处理或识别异常，不得为了完成打标而随便选择一个主题。附件中“选题实际使用二级标签”与旧数据只有一级分类的情况，必须通过迁移解决。

### 4.4 T4：目标客群

总共0～3个L2标签，不是每个分类最多3个。允许跨分类，也允许同分类多个标签；附件已经给出“已婚未育、有娃家庭”同时选择的例子，不额外增加同分类只能单选的限制。

内容没有明确指向时保留空数组；不强行补“普通大众”。账号缺少年龄、性别或家庭信息时不猜测；匹配时作为未知或中性处理。

账号属主的性别、年龄、婚育状态不天然等于账号目标受众。用于受众匹配的事实需要明确来源和用途，不能从昵称、人设名称自行猜测。

### 4.5 T5：使用场景

总共0～3个L2标签。允许多个场景类别，包括独立的时间情境分类。内容无明确场景时允许为空。

例如“郑州周末亲子商圈活动”可选择商圈消费、亲子陪伴、周末。不得强行补齐三个标签，也不按投放日期自动把所有内容标为工作日/周末场景；投放时间与内容语义分别判断。

### 4.6 T6：核心需求描述

由标题、大纲、描述/素材及T3～T5结果生成一条标准化需求文本。已有同步字段只包含标题、大纲时使用实际可得信息，不假装存在额外素材。

运营在选题详情修改的是当前选题的需求结果。正式保存需留版本、修改人和修改前后内容，并更新当前画像；不会修改其他选题的需求。

新机制不要求客户维护需求词库，也不再把“相似度大于80%复用同一T6全局标签”作为生成前置条件。语义向量和相似度仍可用于需求适配与去重，但与全局标签复用分开设计。

## 5. 前端整体布局

沿用现有蓝色体系、字体、紧凑标签、卡片、统一保存和自定义确认弹窗。维度筛选保持默认折叠，不增加登录后台和刷新按钮。

### 5.1 策划配置：默认只读

```text
策划配置                                      编辑配置

账号与自动策划配置
账号经营策略配置
账号生命周期阶段定义

选题标签配置
T1 业务属性 | T2 经营作用 | T3 内容主题 | T4 目标客群 | T5 使用场景   T6 用户需求

T3 内容主题
金融与财富        账户与支付  信用卡  存款  银行理财  基金 …
福利与权益        消费优惠  产品权益  会员权益  生活权益 …
汽车与车生活      购车选车  用车养车  新能源车  加油充电 …
本地生活          本地活动  商圈市集  本地餐饮  城市游玩 …

配置历史
```

保留维度Tab，每个Tab内按L1分组展示L2。这样新增一层归类，仍能直接看到叶子内容；不改成每个标签都要逐层展开的深树。

标签展示建议小圆角、浅色底、无圆点，不常驻“改名/停用”文字。一行放不下自然换行，超长标签悬浮显示全称。

一眼看全指默认看清当前维度的分类与配置重点；不把全部127个叶子、所有维护按钮和平铺说明堆入首屏。长列表保留自然滚动和搜索定位。

### 5.2 编辑态

点击页面统一编辑按钮后进入草稿态；分类与叶子在原位置编辑，统一保存整份配置后生效。取消编辑、离开编辑保留现有自定义二次确认。

| 操作 | 交互方式 |
| --- | --- |
| 新增一级分类 | 当前维度标题旁提供入口，输入名称后加入草稿 |
| 新增二级标签 | 分类行内显示紧凑输入区，直接填写；不增加“新增/取消新增”切换流程 |
| 改名/停用/别名 | 点击选中叶子后，在该标签附近弹出轻量操作面板；只读态不显示维护动作 |
| 移动标签 | 操作面板选择目标一级分类，保留叶子ID；提交前显示受影响规则和路径 |
| 合并标签 | 选择目标叶子，预览受影响选题和适配规则，确认后建立旧ID到新ID映射 |
| 停用分类 | 先展示后代影响，不物理删除；新识别不可选择其后代，历史结果继续可查 |

推荐首版实现分类、叶子新增、改名、停用和别名；移动、合并需要规则引用与迁移能力，放第二阶段，但数据结构首版预留。

### 5.3 T1、T2、T6的页面区别

T1展示结构化字段定义及范围规则，使用业务表单；T2展示固定的流量/转化，不再提供自由新增、改名、停用。

T6在配置页继续保留简短悬浮入口，悬浮说明改为“模型生成核心需求，可在选题详情修正”，不展示共享词库维护功能。选题详情内完整展示T6需求文本，不仅靠悬浮阅读长段落。

### 5.4 配置历史

仍放页面下方，继续使用统一配置历史。详情分组展示分类树、标签变更、适配规则和版本；修改摘要能说明“将信用卡移动至金融与财富”等具体变化。

恢复历史配置必须二次确认，并重新校验当前规则引用；恢复产生新版本，不能覆盖历史快照或修改已执行批次。恢复历史字典不等于恢复业务代码到旧数据协议。

## 6. 选题列表、详情与筛选

### 6.1 选题列表与详情

手动策划选择选题继续用大步骤、列表、分页和滚动条；选题标题与大纲保留。列表主要展示主主题、内容类型、有效期等关键内容，关联主题、客群和场景放在详情，避免横向列数继续增加。

选题详情建议顺序：标题和大纲 → T1业务属性 → T2经营作用 → T3主主题/关联主题 → T4客群 → T5场景 → T6核心需求。内容类型和实际选题来源分别保留。

显示叶子短名为主，悬浮/详情显示完整路径。不能只显示一级分类而隐藏正式叶子标签。

### 6.2 级联选择器

```text
T3主主题
左列：一级分类            右列：二级叶子
金融与财富               ○ 信用卡
福利与权益               ○ 消费优惠
本地生活                 ○ 本地餐饮

已选：福利与权益 / 消费优惠
```

主主题单选；关联主题多选最多2个；T4、T5多选各最多3个。选择器支持搜叶子名称、路径及语义词定位，结果显示完整路径。上限达到后继续选择时给明确局部反馈，不能静默丢弃。

配置页Tab是维度入口，不在弹出的选择器里重复再选一次T3/T4/T5，避免用户走三次点击。

### 6.3 筛选规则

选题筛选与替换选题共用一套控件，默认折叠。原有选题ID、标题、类型、内容类型、产品、活动、属地热点等筛选保留；标签筛选放在同一个折叠区，按实际需求逐步增加。

建议新增内容主题、目标客群、使用场景。默认同维度多个标签按“任一匹配”，不同维度之间按“同时满足”；如果需要全部匹配应提供明确切换，不能不同页面各用一套规则。

选择L1分类作为筛选条件时按当前字典版本展开其后代；选择L2则精确匹配叶子ID。T3主题筛选默认覆盖主主题和关联主题；仅主主题筛选作为显式选项。

T4/T5未限定是合法标签结果，不等于打标失败。筛选未指定客群/场景时不排除这些选题；指定了具体客群/场景时是否包含未限定项，用显式“包含未限定”选项控制。

### 6.4 策划结果与日历

账号/批次日历卡片保持干净，仍以时间、选题标题、策划方式、内容状态为主。完整标签放点击后的单槽位详情；批次详情与账号详情复用展示。

历史槽位使用当时的标签和路径快照。不能因为今天把标签改名或移动，就让过去的策划结果看起来使用了新规则。

## 7. 账号能力与选题匹配

### 7.1 T3能力继承

适配规则建议以内容人设/能力模板维护，再为具体账号提供必要覆盖。模板来源需要行内提供明确的人设类型或经确认的映射，不能仅凭账号名称生成。

| 规则范围 | 示例 |
| --- | --- |
| 一级分类默认规则 | 福利专家对“本地生活”为CORE |
| 二级叶子覆盖规则 | 福利专家对“本地生活 / 城市服务”为ADJACENT |
| 条件适配 | 信用卡专家对泛生活内容要求能够自然回到支付、用卡或权益 |

同一个模板内优先级：叶子明确规则 > 一级分类规则 > 默认规则。账号自身有覆盖时先应用账号覆盖，否则使用模板；首次实现不开放任意多模板叠加，避免无法解释的冲突。

CORE表示核心适配，ADJACENT表示可拓展适配，CONDITIONAL表示满足明确条件后适配。这些是关系类型，不直接假定为100/80/60分。

CONDITIONAL必须保存条件内容、评估方式与评估结果。无法判断时标记待判定或未满足，不自动当成通过。默认未配置的关系如何处理也需要规则确认，不能默认CORE。

标签移动后可能继承新的一级规则，即使叶子ID未变，匹配结果也可能改变。因此移动前应预览影响，保存后需要重新评估相关画像/规则快照；历史批次不重算。

### 7.2 主主题、关联主题及T4/T5

建议主主题用于主要内容能力判断，关联主题补充理解，不因为关联到一个CORE叶子就覆盖主主题的不适配。具体权重和候选阈值暂不填默认值。

T4/T5按实际已知的账号受众、兴趣与场景能力参与适配；未知字段不冒充已匹配，也不直接扣分。附件中的账号映射示例应作为需审核的业务映射，不能从“喜欢运动”自动断言所有运动场景都可承接。

T6用于需求语义适配、去重和组合参考。相似度阈值、向量模型和去重窗口需与正式算法说明一起确认。

### 7.3 与生产闭环的关系

流程仍为定题 → 提交槽位内容生产 → 内容方回传 → 成功使用计数。标签升级增强选题理解，不更改成功回传才计使用次数的口径。

营销选题仍受绑定账号与审核有效期约束；热点仍遵循前一日定题。不能为了统一标签结构就强制改成与普通选题相同的召回排序流程。

内容Agent按已确认的内容类型、平台、生产配置等路由确定，不能仅根据某个T3父分类自动猜Agent。Agent未确定时继续待处理，不提交不完整生产请求。

## 8. 推荐的数据结构

### 8.1 分类树

T3～T5共用节点结构，至少包含：id、dimension、parent_id、level、node_type、name、enabled、sort_order。分类层level=1，标准标签层level=2；只允许叶子被正式选题绑定。

节点ID稳定，改名或移动不换ID；名称不能作为关联主键。一个叶子只有一个父分类，不支持跨维度移动、不允许成环、不允许在L2下新增子节点。

分类名在同维度内唯一，叶子名至少在同父分类内唯一；跨分类同名须完整路径显示。搜索词和别名单独保存，不当作新的正式标签。

## 9. 标签治理：别名、移动、合并、停用

“骑行”是“运动”的细分语义，不是严格同义词。可以作为运动的检索提示或模型归类提示，但不能把所有“运动”内容反推为“骑行”。推荐区分同义词与细分提示词，避免合并后丢失语义。

移动保持叶子ID，更新父分类并产生字典新版本；合并选择保留节点，建立旧ID到新ID映射，影响当前引用与规则，不直接覆盖历史名称快照。

合并后需要重新校验T3主关联去重和T4/T5数量：两个旧标签映射为同一新标签时只保留一次。适配规则冲突先人工处理，不静默采用更高等级。

停用节点及其父分类后，不再参与新识别和新选择，历史仍可查。已排期但未生产是否需要重新定题应按业务影响处理，不能因标签停用自动重算所有历史任务。

## 10. 接口V1.8应如何调整

编号和分类保持IF-01～IF-05、OP-01～OP-05，两个标签接口仍放最后。这次方案不直接覆盖已确认接口文件，字段变化在下一版接口评审中合入。

| 编号 | 需要调整的内容 |
| --- | --- |
| IF-01 账号信息同步 | 补充可判断地域/组织范围的稳定编码；确认营销资格事实、受众事实和人设类型的来源；新增项作为协商字段，不擅自将客户现有字段改为必填 |
| IF-02 普通选题同步 | 接收T1结构化营销属性、范围事实；原选题ID、标题、大纲、内容类型、热度、有效期保留 |
| IF-03 营销选题同步 | 账号绑定、审核事实保留；补充可判断适用范围的字段，营销属性与来源类型分别保存 |
| IF-04 热点选题同步 | 补充T1业务范围/营销属性事实；热点选题来源不直接决定营销属性 |
| IF-05 槽位内容生产任务提交 | 在完整策划结果中携带新标签对象及schema/字典/结果版本；保留账号、选题、大纲、内容类型和内容Agent，不要求内容方自行查树拼装 |
| OP-01 账号周期策划结果查询 | 详情返回槽位当时的新结构标签与路径快照，兼容历史旧结构；列表不必携带全量字典 |
| OP-02 槽位生产结果回传 | 仍以任务、槽位、版本和生产状态回传；不要求内容方回写或重新识别标签 |
| OP-03 选题生产使用次数查询 | 标签结构变化不改变生产成功计数口径；按分类统计时使用相应字典版本展开并按成功槽位事实去重 |
| OP-04 选题标签查询 | 输入继续仅选题ID；输出从六个单字符串升级为新labels对象，并返回schema_version、taxonomy_version、label_version |
| OP-05 选题批量打标效果测试 | 沿用选题详情数组输入；每条返回T3主关联、T4/T5数组和T6需求文本；独立测试，不写正式标签、不进入生产、不增加使用次数 |

OP-04的新返回是破坏性变化，不能直接让旧前端收到对象后显示[object Object]。需要新响应协议/版本化路径或协商响应版本；输入业务字段仍只有选题ID。旧版若无法表达多选，应保留旧快照查询，不能将关联主题随意截断为一个字符串冒充完整结果。

三类来源若存在相同选题ID，OP-04仅传ID查询之前须先解决统一ID映射。这个问题在平铺标签时已存在，改成树后不能忽略。

### 10.1 OP-05效果测试展示

建议测试入口放选题标签配置的编辑区域或运营测试入口，使用大抽屉/独立面板，不插入手动策划三步流程。

左侧提交选题，右侧按行查看：选题ID、标题、T3主主题、关联主题数量、T4/T5标签、T6核心需求、识别结果状态。点击展开查看完整路径和依据。

T1已有来源事实时直接展示；测试仅有标题和大纲、缺少地域/营销属性时返回“来源信息未提供”，不能让模型生成一组事实假装已完成准入判断。整条语义测试可完成，同时保留字段级缺失信息。

支持选定已保存的字典版本，保证重复测试可对照；未保存配置的预览必须标明草稿版本，不能伪装成已发布字典。批量输入逐条返回状态，一条识别失败不会吞掉其他选题的结果。

测试T6允许修改预览文本，但预览修改不等于修改正式选题；正式修改通过选题详情保存并留痕。

## 11. 数据迁移与兼容

1. 保存现有配置、标签结果、字典历史和正在执行的批次快照，建立旧数据基线。
2. 导入附件中的L1/L2分类字典，记录版本，不将建议字典当作客户已确认的最终词表。
3. 为旧标签制作显式映射表，记录唯一映射、多候选、无法映射三种结果。
4. 旧标签已经准确对应新L2时关联到稳定叶子ID；同名但含义不同不能直接按名称合并。
5. 旧T3“金融理财”“本地生活”等宽泛分类通常只能定位新L1，不能自动把它填成“银行理财”或“城市攻略”；进入待映射或经授权重新识别。
6. 旧T4/T5只有一个值时，在唯一映射成功后转为单元素数组；不为凑数量自动补其他标签。
7. 旧T6内容可作为当前需求文本迁移来源，但不能伪造模型新生成记录；保留旧ID供追溯。
8. 新增画像schema与指纹版本，受影响的未执行候选重新生成画像/向量；不拿旧单选向量冒充新多值语义空间。
9. 运行中的旧任务继续按领取时的旧协议、字典版本回写；新任务使用新协议。无法并行兼容时，先排空任务后切换，不让旧结果写进新schema。
10. 历史策划、已提交生产的任务及成功计数不自动重算；新标签规则用于新版本业务。

先迁移展示和结构，再处理正式重新识别。是否允许对历史选题重新打标应明确授权范围，修改旧“首次识别后不重算”规则时必须同步PRD。

回滚通过新旧schema隔离、关闭新任务入口、恢复上一配置版本完成；不删除新版本的审计数据，也不把多选结果直接截成单选后覆盖旧历史。

## 12. 字典版本、画像与并发规则

字典树、标签结果、账号能力规则、模型/提示词分别有版本。批次冻结这些引用，确保同一批次解释一致。

仅修改界面排序不一定需要重建语义向量；标签名称含义、父分类、主关联、需求文本改变时，应重新计算受影响画像指纹并按向量模型契约处理。使用ID不变并不意味着语义未变。

新增叶子自动继承父分类规则；是否适用父分类规则由规则版本决定。创建配置版本时采用期望版本校验，防止两个编辑窗口互相覆盖。

修改T6、合并标签与新批次匹配并发时，冻结旧快照的批次按其版本执行；提交结果前仍要校验当前业务资格和生产安全状态。具体算法使用哪些新字段在策略版本中明确，禁止静默改变评分。

1. 本稿按附件采用“维度+L1+L2”三层展示，不增加业务L3。
2. T3主1关联最多2，T4/T5各最多3且可空，T2固定；是否直接按附件冻结。
3. T1从原语义标签转为准入字段，营销资格、区域/组织编码和冲突事实以谁为准。
4. T6取消全局词库复用作为前置条件，允许正式修正；是否授权重新识别旧选题。
