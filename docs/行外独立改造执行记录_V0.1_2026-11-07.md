## 4. 行外与行内两种构建

以下在`java-backend`执行，使用JDK8和Maven。

```bash
# 行外：公开依赖，默认Maven profile为dev
mvn -Pdev verify
java -jar godp-planning-server/target/planning-business.jar --spring.profiles.active=dev

# 行内模块交付边界检查：普通JAR，无本地启动壳
mvn -Pinside package
```

`dev`产物：`godp-planning-server/target/planning-business.jar`。

`inside`的server产物：`godp-planning-server/target/inside/planning-business.jar`；其余四模块的普通JAR在各自target中。server排除`server.dev`、application配置和Boot启动包装。HikariCP/MySQL驱动不进入inside依赖配置；H2只在dev测试使用。

不要同时启用Maven dev和inside。Maven profile决定交付内容；Spring profile决定运行装配。Spring默认dev仍映射到local，原outside别名保留；业务部署环境仍叫outside/inside。

旧根`java-backend/target/planning-business.jar`可能仍存在，但已不是新版本构建目标。本轮没有覆盖该旧文件，也没有重启运行中的旧服务。现有开发库尚未执行V9，正式重启新版前仍须按DBA发布流程核对。

宿主并入步骤见[五模块并入说明](../java-backend/host-integration/MAVEN_MODULES.md)。inside构建通过只说明公开依赖下的模块隔离成立，不代表Halo、Apollo、Venus、Horae或真实资料SQL已经接通。
