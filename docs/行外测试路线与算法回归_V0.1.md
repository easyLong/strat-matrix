# 行外测试路线与算法回归 V0.1

日期：2026-11-03。目标：主要在行外开发和调整算法，定期携带可复现版本进入无外网的行内环境。

## 当前已落地

| 部分 | 实现 |
| --- | --- |
| 固定测试数据 | `testing/data/`：小集5账号/60选题，规模集100账号/600选题，固定生命周期、日期、层级标签、向量和模型响应 |
| 统一入口 | 根目录`python -m testing`，覆盖算法回放、Python、工具自测、Java和前端；可单独选择工程 |

| 失败识别 | 缺工具、依赖未准备、数据指纹变化、策略错误、约束失败或结果变化均不能自动显示通过 |

具体命令、报告说明和基线更新方式见[测试工具使用说明](../testing/README.md)。

## 固定工作顺序

1. 每次改业务或算法后先跑小集与对应工程回归。
2. 改动召回、权重、精判或组合分配后，对照逐账号结果；总匹配数相同不代表没有退步。
3. 运行规模集检查覆盖、约束、数据量和耗时变化。
4. 真实模型评测应另行显式运行，记录模型、Prompt、标签/映射、数据及策略版本；本工具尚不自动调用真实模型。
5. 行外准备目标环境的依赖、Git版本和增量脚本，先做断网安装与启动演练。
6. 驻场仅替换事实来源、身份、宿主装配和调度，复用相同字段契约和合成样例；最后使用行内实际资料与模型验收。

## 对报告结论的约束

- 当前固定响应是开发者构造的合成回放，不是客户金标，也不证明真实标签/向量或模型Prompt正确。
- 数据哈希或向量空间变化时，报告为“不可比较”，不能与旧基线直接算改善率。
- 具体结果、分数或策略变化为“需复核”；不自动覆盖基线掩盖退步。
- 仅运行V19，与同数据集的V19历史基线比较；实际调用链和替换边界均保存在说明中。
- 单测与算法回放通过，不代替Vue浏览器操作、行内权限、真实内容事实和生产调度验收。
