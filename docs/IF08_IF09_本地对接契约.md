# IF-08 / IF-09 本地对接契约

依据《多账号智能策划_PRD_V1.0.docx》第 8.2.7～8.2.8 节。以下跨系统接口使用 `X-Integration-Token` 请求头；客户最终协议待确认。

## IF-08 普通选题标签查询

`GET /api/integrations/topics/{topic_id}/labels`

仅接受已同步的正式普通选题。查询只读取已保存结果，不触发标签识别。无标签记录时返回“处理中”；营销或热点选题、`DEMO-` 记录返回 404。

```json
{
  "topic_id": "TOPIC-001",
  "label_status": "已完成",
  "labels": {
    "t1": "非营销",
    "t2": "流量",
    "t3": "本地生活",
    "t4": "年轻客群",
    "t5": "周末休闲",
    "t6": "周末出行规划"
  }
}
```

`label_status` 为“处理中 / 已完成 / 失败”。仅“已完成”返回 T1–T6 单选字符串；其余状态返回空对象。项目内的标签识别进程可调用 `PUT /api/internal/topic-tags/{topic_id}` 写入 `tags`、`label_status` 和可选的 `taxonomy_version`，失败时提供 `label_error`。内部入口保存 T1–T5 稳定 ID 和逐版历史，详见[标签字典治理](TAG_TAXONOMY.md)；IF-08 对外返回仍只有名称和状态。离线标签识别任务本身仍待开发。

## IF-09 选题正式使用次数查询

`POST /api/integrations/topics/official-usage/query`

```json
{"topic_type":"普通","topic_ids":["TOPIC-001","TOPIC-002"]}
```

```json
{
  "topic_type": "普通",
  "items": [
    {"topic_id":"TOPIC-001","official_use_count":3},
    {"topic_id":"TOPIC-002","official_use_count":0}
  ]
}
```

每次请求只能有一种 `topic_type`（普通、营销或热点），最多 500 个不重复的 ID，输入顺序保持不变。每个选题必须先有独立计数快照；未同步的选题返回 503，真实零次使用需由计数来源明确写入 0。查询不改变计数；IF-05、IF-06、人工替换也不改变计数。旧的 `GET /api/topics/{topic_id}/usage` 返回内容生成槽位数，不能作为 IF-09 的正式使用次数。

正式使用次数由独立业务逻辑维护。其当前快照由内部入口 `PUT /api/internal/topic-official-usage` 导入，例如：

```json
{
  "topic_type":"普通",
  "source_name":"official-usage-worker",
  "records":[{"topic_id":"TOPIC-001","official_use_count":3,"source_revision":7}]
}
```

同一选题的 `source_revision` 必须递增；重复版本且内容相同视为幂等，旧版本忽略，同版本但内容不同返回 409。当前快照保存在 `godp_topic_official_usage`，每次有效变更保存在 `godp_topic_official_usage_history`。计数来源尚未接入时，IF-09 返回 503，不会把未知数量显示为 0。

部署更新后运行 `cd backend && python3 -m app.init_db`，新增表和字段均有中文说明。
