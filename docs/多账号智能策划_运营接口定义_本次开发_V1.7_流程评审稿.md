# 多账号智能策划运营接口定义（V1.7 流程评审稿）

本稿依据本轮明确的“槽位定题、异步生产、结果回传、使用计数”流程修正接口职责，供运营和开发共同评审。本文是接口业务定义，不代表后端已按本稿完成改造。

## 业务流程与责任

1. 策划系统生成账号的一周槽位，确定账号、投放日期和槽位类型。
2. 普通、营销槽位在当晚确定选题、大纲、内容类型及对应内容Agent后，逐槽位调用IF-07发起内容生产。
3. 热点槽位提前保留；投放前一日确定选题及生产所需信息后，逐槽位调用IF-07。未确定选题的热点槽位继续等待。
4. 内容方受理后异步调用指定内容Agent生成内容；受理成功只表示任务已接收。
5. 内容方通过OP-02回传对应槽位的生产结果。策划侧校验后更新该槽位的内容状态。
6. 槽位内容生产成功并经回传确认后，策划侧记录选题使用事实，供OP-04查询统计。

流程关系：槽位定题 → IF-07提交内容生产 → 内容Agent异步生产 → OP-02回传槽位生产结果 → 更新内容状态及选题使用统计。

OP-01是账号周期策划结果的辅助查询入口；IF-07主动提交生产所需的完整输入。OP-03用于独立测试打标效果；OP-05查询已保存标签。

| 参与方 | 负责内容 |
| --- | --- |
| 策划系统 | 固定槽位、确定选题和内容Agent、提交生产任务、接收回传、维护槽位内容状态和选题使用统计 |
| 平台内容生产方 | 提供IF-07，接收任务、调用指定内容Agent、管理生产执行、通过OP-02回传结果 |
| 行内选题方 / 运营 | 查询策划结果和统计，按需提交选题详情测试打标效果 |

## 状态与统计口径

| 状态 | 业务含义 | 是否计入选题使用次数 |
| --- | --- | --- |
| 待定题 | 槽位尚未确定选题，例如未触发的热点槽位 | 否 |
| 待生产 | 已确定选题及生产输入，尚未成功提交 | 否 |
| 生产中 | 内容方已受理，策划侧等待异步结果 | 否 |
| 已完成 | OP-02确认内容生产成功，该槽位完成本次生产闭环 | 是 |
| 生产失败 | 内容方回传生产失败，等待处理或重试 | 否 |

策划完成与内容生产完成分别记录。一周槽位已规划完成时，热点槽位仍可处于待定题，其他槽位可以先进入生产；一个槽位成功不会直接把整周内容标记为全部完成。

选题使用次数以“内容生产成功并确认回传”为统计时点，覆盖普通、营销、热点选题。初次成功的一个槽位形成一次使用；同一选题用于两个不同槽位并各自生产成功，计两次。任务受理、失败、查询、打标测试不计数；同一次成功结果的重复通知和接口重试不得重复计数。无需等待内容发布。

生产结果回传须对应槽位、结果版本和生产任务；过期版本的回传保留记录，不覆盖当前版本、不为当前版本增加使用次数。当前有效成功回传对应的状态变更和使用事实应一起生效，避免状态已完成但统计遗漏。

待业务确认：同一槽位在已生产成功后重新生成，或更换选题再生产，是否额外计次、历史成功使用是否保留。该项单独确认，不将传输重试视为新增使用。

## 接口总览

按接口提供方分类：IF由行内系统提供，OP由策划系统提供；调用发起方与接口提供方分别说明。沿用已确认编号，共10个接口：IF-01至IF-04、IF-07及OP-01至OP-05。

| ID | 接口名称 | 提供方 | 调用方 | 用途 |
| --- | --- | --- | --- | --- |
| IF-01 | 账号基础信息、人设及互动数据同步 | 行内账号系统 | 按已确认同步机制执行 | 获取账号事实 |
| IF-02 | 普通选题同步 | 行内选题系统 | 按已确认同步机制执行 | 获取普通选题 |
| IF-03 | 营销选题同步 | 行内营销选题系统 | 按已确认同步机制执行 | 获取绑定账号的营销选题 |
| IF-04 | 热点选题同步 | 行内热点选题系统 | 按已确认同步机制执行 | 获取热点选题 |
| IF-07 | 槽位内容生产任务提交 | 平台内容生产方 | 策划系统 | 按槽位主动提交完整生产输入，异步生成内容 |
| OP-01 | 账号周期策划结果查询 | 策划系统 | 行内平台 / 内容方 | 查询指定账号周期的槽位结果和内容状态，辅助查看核对 |
| OP-02 | 槽位内容生产结果回传 | 策划系统 | 平台内容生产方 | 回传生产结果，更新槽位状态并形成成功使用事实 |
| OP-03 | 选题批量打标效果测试 | 策划系统 | 行内选题方 / 运营测试入口 | 提交选题详情并查看测试标签，独立于内容生产流程 |
| OP-04 | 选题内容生产使用次数查询 | 策划系统 | 行内选题系统 / 运营 | 查询生产成功形成的选题使用次数 |
| OP-05 | 选题标签查询 | 策划系统 | 行内选题方 | 按选题ID查询已保存标签 |

## 接口定义

IF-01至IF-04沿用已确认的业务字段；本轮修正内容生产与统计接口。下述生产任务、版本、状态等字段属于本轮建议，最终字段名和状态编码由双方对接时确认。

### IF-01 账号基础信息 + 账号人设 + 互动数据离线同步接口

| 接口用途 | 每日夜间离线同步平台账号池、账号基础信息、账号人设及近3个月历史互动数据，供AI自动策划、手动筛号、生命周期判断、账号画像及新增账号识别使用。账号基础信息包含账号ID、昵称、属主UM号、属主组织、业务线、平台、地域、粉丝量和账号状态。 |

| --- | --- |

| 调用时机 | 每日夜间离线任务执行时同步；自动策划和手动策划执行时不实时调用IF-01，直接读取策划系统最近一次成功同步的数据快照。 |

| 提供方/发起方 | 平台账号系统提供账号事实及近3个月互动数据；策划系统接收并计算策划指标。 |



| 请求字段 | 字段含义 |

| --- | --- |

| 无核心业务请求字段 | 默认同步当前账号池；全量/增量、分页等技术参数由后续接口文档定义。 |



| 返回字段 | 字段含义 |

| --- | --- |

| account_id | 账号唯一标识 |

| account_name | 账号昵称 |

| um_no | 属主UM号 |

| account_status | 账号状态，表示账号是否有效及是否可参与策划 |

| organization | 属主组织 |

| account_persona | 账号人设；描述账号内容定位、身份设定和表达方向，是账号画像、向量生成及选题匹配的核心输入 |

| business_line | 业务线 |

| platform | 账号所属平台 |

| region | 账号地域；当前本地数据层兼容映射为地域/城市字段 |

| follower_count | 账号当前粉丝量 |

| interaction_data | 账号近3个月帖子级互动明细：发帖时间、帖子标题、红星数、收藏数、评论数；用于有效内容篇数、滚动互动、流量趋势、生命周期判断和账号画像。流量趋势由策划系统基于该数据计算，不作为IF-01独立字段。 |

| --- | --- |

| 调用时机 | 每次自动策划执行前完成同步；策划任务运行时直接读取策划系统本地最新同步的普通选题数据。 |

| 提供方/发起方 | 平台普通选题系统提供普通选题及热度数据；策划系统接收并维护本地选题。 |



| 请求字段 | 字段含义 |

| --- | --- |

| title | 选题标题 |

| outline | 选题大纲 / 核心内容 |

| topic_type | 选题类型；IF-02 应为非营销普通选题 |

| content_type | 内容类型，直接继承源系统 |

| topic_heat | 选题热度；用于候选排序和普通选题兜底 |

| valid_from / valid_to | 选题有效期起止时间；为空表示对应边界不限制 |



| 返回字段 | 字段含义 |

| --- | --- |

| topic_id | 普通选题唯一标识 |

| title | 选题标题 |

| outline | 选题大纲 / 核心内容 |

| content_type | 内容类型，直接继承源系统 |

| topic_heat | 普通选题当前可排序热度值；用于普通匹配无结果及热点无合法选题时选择“普通最热”兜底，具体源字段映射由接口文档确定 |

| status | 选题当前是否有效可用 |

### IF-07 槽位内容生产任务提交接口

| 项目 | 定义 |
| --- | --- |
| 接口用途 | 策划侧将一个账号的一个槽位策划结果提交给内容方，调用对应内容Agent生产内容 |
| 提供方 / 调用方 | 平台内容生产方提供；策划系统调用 |
| 调用时机 | 普通、营销槽位当晚定题后提交；热点槽位在投放前一日确定选题后提交；以单槽位为生产与回传单位 |
| 交互方式 | 异步受理。返回受理结果后展示生产中，最终结果通过OP-02回传 |

| 输入字段 | 字段含义 |
| --- | --- |
| production_task_id | 本次生产任务标识，由策划侧提交前生成；内容方原样回传，重复提交同一任务返回已有受理结果 |
| planning_agent_result | 一个账号、一个槽位的完整策划结果对象 |
| planning_agent_result.slot_id | 策划槽位标识，精确对应一次排期位置 |
| planning_agent_result.planning_result_id | 当前槽位的策划结果标识 |
| planning_agent_result.version | 策划结果版本，防止旧结果覆盖新结果 |
| planning_agent_result.planning_cycle | 所属周周期起止日期 |
| planning_agent_result.publish_date | 计划投放日期 |
| planning_agent_result.account_info | 账号信息，包含账号ID、昵称、人设、平台等生产所需账号信息；由策划侧携带生产所需快照 |
| planning_agent_result.content_type | 内容类型 |
| planning_agent_result.topic_id | 已确定的选题ID |
| planning_agent_result.topic_type | 选题类型：普通 / 营销 / 热点 |
| planning_agent_result.title | 选题标题 |
| planning_agent_result.outline | 选题大纲 |
| planning_agent_result.content_agent | 执行生产的内容Agent标识；由双方约定可调用的Agent编码 |
| planning_agent_result.tags | 当前策划结果已有标签 |
| planning_agent_result.content_agent_input | 对应内容Agent所需结构化生产参数 |

| 输出字段 | 字段含义 |
| --- | --- |
| production_task_id | 对应输入的生产任务标识 |
| accepted | 是否受理 |
| status | 受理状态：已受理 / 已存在 / 未受理；已受理和已存在均不等于内容生产成功 |
| message | 未受理原因等必要信息 |

账号、选题、内容类型、大纲和内容Agent未齐备时不提交生产。受理后由内容方执行异步任务；策划侧保存提交记录，避免同一槽位结果版本在传输重试时重复生产。

### OP-01 账号周期策划结果查询接口

| 项目 | 定义 |
| --- | --- |

| 调用时机 | 查看账号周期策划或核对槽位内容状态时调用；主流程由IF-07主动触发生产 |

| 输入字段 | 字段含义 |

| account_id | 账号ID |
| planning_cycle | 需要查看的周周期；建议支持指定周期，未传时默认当前自然周 |

| 输出字段 | 字段含义 |
| --- | --- |
| account_id | 账号ID |
| planning_cycle | 本次查询周周期 |
| planning_contents | 该账号在本周期的槽位结果列表，包含热点待定题槽位 |
| planning_contents[].slot_id | 槽位标识 |

| planning_contents[].account_info | 账号信息 |
| planning_contents[].publish_date | 计划投放日期 |
| planning_contents[].slot_type | 槽位类型：普通 / 营销 / 热点；与实际绑定选题类型区分 |

该查询无生产、状态更新或计数副作用。是否对外保留本接口取决于行内是否需要查看或核对策划结果；仅为生产获取输入时，IF-07已携带完整信息，可不把本接口作为生产必经步骤。

### OP-02 槽位内容生产结果回传接口

| 项目 | 定义 |
| --- | --- |
| 接口用途 | 内容方回传指定生产任务的结果，策划侧更新对应账号槽位内容状态并记录成功使用事实 |
| 提供方 / 调用方 | 策划系统提供；平台内容生产方调用 |
| 调用时机 | 内容生产成功或失败后回传；回传失败可按同一事件标识重试 |

| 输入字段 | 字段含义 |
| --- | --- |
| event_id | 回传事件唯一标识，重复通知不重复生效 |
| production_task_id | IF-07提交时的生产任务ID |
| slot_id | 对应槽位ID |
| version | 对应策划结果版本 |
| topic_id / topic_type | 本任务实际生产使用的选题ID和类型，与提交时的任务快照校验 |
| status | 生产结果：生产成功 / 生产失败；具体技术编码由对接确认 |
| content_id | 生产内容ID；成功时必填 |
| occurred_at | 结果发生时间 |
| failure_reason | 失败原因；失败时提供 |

| 输出字段 | 字段含义 |
| --- | --- |
| accepted | 是否接受本次回传 |
| applied | 是否更新了当前槽位内容状态 |
| current_content_status | 策划侧确认后的槽位内容状态 |
| message | 已处理、重复通知、版本过期或信息不匹配等处理说明 |

生产成功回传通过校验后，槽位内容状态变为已完成，并记录该选题的成功使用事实；生产失败不计使用次数。生产状态与发布状态分别定义，本轮生产闭环以内容生产完成为结束节点；若后续需要发布回传，应单独确认发布接口及状态，不把发布当作本轮成功计数的前置条件。

### OP-03 选题批量打标效果测试接口

| 项目 | 定义 |
| --- | --- |
| 接口用途 | 运营批量提交选题详情，测试标签识别效果并查看每条选题的T1-T6标签 |
| 提供方 / 调用方 | 策划系统提供；行内选题方或运营测试入口调用 |
| 调用时机 | 测试、评估打标效果时按需调用，支持普通、营销和热点选题 |
| 与主流程关系 | 独立测试能力，不创建正式策划槽位、不触发内容生产、不增加选题使用次数 |

| 输入字段 | 字段含义 |
| --- | --- |
| topic_items | 待测试的选题详情数组，沿用之前确认的提交方式 |
| topic_items[].topic_id | 选题ID |
| topic_items[].title | 选题标题 |
| topic_items[].outline | 选题大纲 |
| topic_items[].content_type | 内容类型 |
| topic_items[].topic_heat | 选题热度 |
| topic_items[].status | 选题当前是否有效可用 |

| 输出字段 | 字段含义 |
| --- | --- |
| topic_results | 逐条测试结果数组，与输入选题对应 |
| topic_results[].topic_id | 选题ID |
| topic_results[].labels | 测试识别得到的T1-T6具体标签，包含t1、t2、t3、t4、t5、t6 |
| topic_results[].label_status | 该选题的测试打标状态 |
| topic_results[].label_error | 打标失败原因；失败时提供 |

测试结果供运营查看，不自动覆盖正式标签。上述定义沿用“传入选题详情、试算并查看效果”的已确认方式；若只是查看已有正式标签，使用OP-05。

### OP-04 选题内容生产使用次数查询接口

| 项目 | 定义 |
| --- | --- |
| 接口用途 | 查询某选题已成功用于内容生产的次数；原名称为选题正式使用次数查询，明确统计的是生产成功使用 |
| 提供方 / 调用方 | 策划系统提供；行内选题系统或运营调用 |
| 调用时机 | 查看选题使用效果、筛选选题或核对统计时调用 |
| 数据依据 | OP-02有效成功回传形成的选题使用事实，由策划系统汇总 |

| 输入字段 | 字段含义 |
| --- | --- |
| topic_type | 查询选题类型：普通 / 营销 / 热点，兼容现有三类选题ID命名空间 |
| topic_ids | 同一选题类型下的选题ID集合，支持单个或批量 |

| 输出字段 | 字段含义 |
| --- | --- |
| topic_type | 选题类型 |
| topic_id | 选题ID |
| official_use_count | 内容生产成功并确认回传后形成的选题使用次数；保留既有字段名，修正统计口径 |

查询本身不增加次数。重复通知、传输重试、生产失败和打标测试不计数；同一选题在不同槽位成功生产分别计数。已知选题尚无成功生产事实时为0，不将未获取到统计数据解释为0。

### OP-05 选题标签查询接口

| 项目 | 定义 |

| 接口用途 | 根据选题ID查询策划侧已保存的正式T1-T6标签，适用于所有选题 |
| 提供方 / 调用方 | 策划系统提供；行内选题方调用 |
| 调用时机 | 展示或使用已保存选题标签时调用；查询不触发测试识别 |

| 输入字段 | 字段含义 |
| --- | --- |
| topic_id | 选题ID，沿用已确认的单字段输入 |

| --- | --- |

| label_status | 已保存标签的当前状态 |
