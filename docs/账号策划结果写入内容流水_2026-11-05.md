# 账号策划结果写入内容流水

日期：2026-11-05。已确认：复用行内现成的内容流水表；每天扫描3次；**到生产日期才写入**。当前未拿到该表的结构，也没有现成Java写入方法，因此本轮实现可复用扫描服务、字段对象、写入端口和验证，真实表SQL留在宿主适配层。

## 1. 完整链路

```text
行内调度平台（每天3次，具体时点由宿主配置）
  → PlanningTaskService.run(CONTENT_FLOW, 本次扫描时点, 分页大小, 游标)
  → 查询业务库 godp_planning_item：未删除、待生产
  → 确认已有账号、投放日期和选题
  → 读取Java策划内容配置中对应普通/营销/热点的提前天数
  → 生产日期 = 投放日期 − 提前天数
  → 尚未到生产日期：本轮不写入
  → 已到生产日期：ContentFlowWriter.upsert 写入现成内容流水表
  → 内容侧确认写入后，将流水ID、结果版本、生产时间和配置版本存回策划明细JSON
  → 内容侧后续生产；策划侧原有CONTENT_STATUS任务读取真实状态
```

Java/Python不新增独立定时器，不由页面点击触发。宿主调度提供每天三次的触发配置，复用现有Java任务模块。写入内容流水与执行内容生产是两个阶段；本模块写入成功不把策划状态提前改成生产中或已完成。

## 2. 何时具备写入资格

| 条件 | 处理 |
| --- | --- |
| 正式明细已落库、账号/投放日/选题完整、内容状态待生产、生产日期已到 | 写入内容流水 |
| 热点空槽尚未定题 | 等定题后再扫描 |
| 自动营销还在确认是否引用库存 | 等营销业务处理完成 |
| 已引用过审内容或已生产完成 | 保持引用结果，不再次派发生产 |
| 正在生产或生产失败 | 不在本次初始写入扫描范围内；生产失败后的重试由内容侧负责 |
| 对应类型提前天数未配置 | 报告`unconfigured`，不默认按T−0写入 |
| 生产日期尚未到 | 报告`not_due`，后续轮次再检查 |
| 到期后漏扫、接口暂不可用 | 后续扫描补写；以“生产时间小于等于本次时点”为准，不要求日期恰好相等 |

T为投放日期，提前天数为自然日。当前配置精度为天，因此内容生产时间以该日期北京时间00:00表示“从当日可开始生产”，不代表任务一定在零点触发。例如11月9日投放、普通选题T−3，则11月6日进入写入范围；当日首次调度扫描时写入。

热点配置的生产日期已到但尚未定题时，等定题后补写，仍保留原计算的计划生产时间。人工营销需求尚无账号或投放日期时，不进入账号策划结果扫描；它自身的需求生产流程保持独立。

## 3. 写入对象包含什么

| 字段对象 | 内容 | 来源 |
| --- | --- | --- |
| `planning_result` | 正式策划结果完整快照，含批次、日期、策划方式、阶段/作用等 | Java正式明细JSON，明细ID/版本以锁定行校正 |
| `account_info` | 账号ID、昵称、属主UM、组织、人设等已有账号快照 | 正式结果的`account_snapshot` |
| `topic_info` | 选题ID、标题/大纲或营销活动/产品信息、二级分类、内容Agent等已有选题信息 | 定题或换题后的`topic_snapshot`及正式明细字段 |
| `production_time` | T−x生产时间，带北京时间偏移 | 对应类型提前天数 + 投放日期 |
| `production_lead_days` | 实际采用的提前天数 | Java业务配置 |
| `configuration_version` | 实际采用的业务配置版本 | Java业务配置当前版本，不是算法策略版本 |
| 关联标识 | 策划明细ID、结果版本、槽位ID、批次ID、账号ID、选题ID | 正式策划结果 |
| `idempotency_key` | `PLANNING-明细ID-V结果版本` | 派发服务生成 |

具体目标表列名由行内映射，不强制现成表采用上述英文列名。内容Agent仅透传正式结果已有信息，不根据名称猜造Agent编号。

## 4. 重复扫描、换题和回执

写入方法须以“策划明细ID”关联一条当前有效流水，以“结果版本”区分换题后的新内容。可映射到目标表已有业务关联字段；必须有数据库唯一约束或等价原子幂等保障。不能仅使用一次普通SELECT查重后INSERT。

- 同版本重复扫描：返回原流水及原生产时间，不新增。策划侧已有同版本写入回执时直接跳过。
- 写入已成功但回执丢失：下一轮使用相同幂等键重试，返回原流水；不因期间修改配置重排原流水。
- 待生产时换题：新结果版本更新原等待流水，不追加两条都可能执行的任务；已开始生产或完成的流水不得被覆盖。
- 写入失败、回执缺失或回执版本/日期不匹配：本次不记录成功，保留策划待生产状态，报告后续需重试。
- 改配置影响后续首次下发或新版本的生产时间，不自动重排已成功写入的同版本流水。

成功回执写入既有策划明细的`content_flow_dispatch` JSON字段：无需新增派发表或重复建内容流水表。内容侧应在生产前使用结果版本校验并按宿主事务/状态规则阻止与换题并发执行；真实宿主适配仍需验证该边界。

## 5. 驻场怎么接

1. 实现[ContentFlowWriter](../java-backend/godp-planning-api/src/main/java/com/pab/aitmp/aiis/godp/digital/marketing/api/xiangliang/port/ContentFlowWriter.java)的一个`upsert`方法，对接现成表的MyBatis Mapper或宿主Service。参考[写入骨架](../java-backend/host-integration/BankContentFlowWriter.java.example)，骨架未实现时明确报错，不返回假成功。
2. 映射上述业务结果和生产时间，返回真实流水ID、实际冻结的生产时间/提前天数/业务配置版本及结果版本。需明确目标表如何保存策划关联键、版本及唯一约束。
3. 注册该宿主Bean并设置`planning.content-flow.enabled=true`。未启用不依赖该Bean；启用却缺少真实Writer时启动失败。直接执行未接入的`CONTENT_FLOW`返回明确503。
4. 按[宿主Job骨架](../java-backend/host-integration/ContentFlowHostJob.java.example)接到行内调度平台，每天触发3次。具体三个时点由客户IT配置，本项目没有写死时点或引入内部调度SDK。
5. 每次完整扫描从游标0开始；`has_more=true`时按`next_after_id`继续，使用同一轮扫描时点，并遵守宿主页数/时长预算。未完成轮次保留游标继续；新轮次重扫低ID到期数据。`retry_required`不能当作全部写入成功。

业务库已提供[扫描索引V8](../java-backend/godp-planning-services/src/main/resources/db/migrations/V8__content_flow_scan_index.sql)：`godp_planning_item(content_status,id)`。新库完整DDL已包含；存量库由DBA核查后发布一次。当前未对开发库执行V8，也未对未知的行内内容流水表执行任何DDL/DML。

启用真实写入前，还需确认历史待生产明细是否属于首次扫描范围。目前读取未删除的正式待生产明细，未擅自根据批次名称猜测是否历史或演示数据。
