## 后续开发顺序

1. **手动策划任务记录**：独立记录每次正式发起的执行中、已完成或失败状态。现有“近期手动策划”只展示已生成的批次，失败而没有结果的任务还无法追溯。
2. **经营策略条件配置**：保存字段、运算符、阈值、AND/OR、正常及回退目标；阶段重叠顺序、风险阈值、目标映射到槽位数 N 的规则仍需冻结。
3. **发布计划输入与自动槽位**：客户发布计划决定未来位置和数量，不能凭空按账号固定条数生成。需要确认来源、时间字段、业务时区、展开规则后实现自动任务。
4. **结果的完整业务解释**：补策划时生命周期、选题大纲、内容类型、经营作用、单账号目标与实际结构、后端计算的 `allow_replace`。当前来源数据只有部分字段，页面不编造缺失值。
5. **人工替换与热点执行**：建立结果版本链、二次状态校验、热点执行记录和统一槽位池。热点来源、目标数量、时间窗口、候选资格和多热点优先级需先冻结。
6. **身份权限与跨系统联调**：客户提供 SSO/权限、内容生产及选题库接收地址、正式状态码、重试策略后接入。当前仅为本地对接版。

## 当前需要业务确认的关键事项

PRD 7.12 列有 TODO-01 至 TODO-27 共 27 项 P0。影响下一阶段核心实现的有：业务时区及周边界；自动策划任务时间；参与账号池范围；发布计划来源和槽位展开；内容生产触发窗口；生命周期“稳定”“下滑”“持续恶化”和阶段重叠顺序；10 条目标到实际槽位数 N 的换算；普通兜底规则；热点来源、数量、时间范围和多热点优先级；营销“先来”排序字段；配置生效时点；内容生产外部状态码；手动抽取后失效的补抽规则。未冻结的答案不写死在算法或调度里。

## 数据与接口归属

- **本项目内部**：运营配置及模块版本、策划任务、参与账号池、槽位、当前结果与版本链、页面统计、待投递事件和审计日志。前端调用的 `/api/config`、`/api/planning-cycles`、`/api/manual-plans` 等是项目内 API。
- **跨系统输入**：账号经营事实、发布计划、普通及营销选题、热点需求事件、内容生成和发布状态。当前只有账号、选题、历史内容和状态回传的本地接口。
- **跨系统输出**：内容生成任务及选题标签事件。当前只写入本地待投递队列，客户接收地址尚未给出。

PRD 中“策划结果的选题使用次数”是当前有效策划分配次数；选题库的“正式使用次数”仅在首次有效“已生成”回传后增加。两者不能合并。

当前本地统计仍按周一至周日归并既有演示与手动记录，仅用于开发页面展示。PRD 的业务时区、周起止和跨月归属尚未冻结，不据此启动正式自动策划任务。
