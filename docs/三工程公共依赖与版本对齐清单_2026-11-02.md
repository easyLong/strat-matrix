# 三工程公共依赖与版本对齐清单

日期：2026-11-02。目标：本地使用公开组件开发，现场按客户既有版本和入口适配，减少内部SDK对业务代码的影响。

本轮阅读客户提供的`工程侧技术.md`，并补充读取同目录的`前端和大模型技术栈.txt`、`requirements.txt`；对照当前仓库的前端清单／锁文件、Python运行依赖及实际模型配置。未安装、升级或降级依赖，未创建Java工程。

## 1. 三工程职责基线

最新约定为：Vue全部调用Java；Java负责策划业务、业务任务、规则配置和正式结果；Python提供打标、画像、向量、召回、精判及优化等能力，保留必要计算缓存与执行记录。

当前仓库仍主要实现Vue和Python，Java只有旧交接模板。旧文档中“Java仅预留、仅通配转发，Python保留全部策划业务”的描述属于上一阶段方案；不能作为新Java业务工程的实施要求。本清单按三工程新职责提出依赖建议，不宣称业务迁移已完成。

## 3. Java建议直接依赖

### 最小业务运行包

| Maven坐标 | 版本策略 | 用途 |
| --- | --- | --- |
| org.springframework.boot:spring-boot-starter-web | 实际Boot版本统一管理 | Controller、JSON、标准HTTP接口；已包含常用Jackson和日志基础能力 |
| org.springframework.boot:spring-boot-starter-validation | 同Boot管理 | DTO参数校验，按javax.validation体系 |
| com.baomidou:mybatis-plus-boot-starter | 3.5.7，对齐客户清单 | 业务表和扩展表访问、CRUD及分页 |
| MySQL Connector/J | 宿主统一版本；见下文 | Java业务库驱动，运行时依赖 |
| org.springframework.boot:spring-boot-starter-test | 同Boot管理，test作用域 | 单元测试和接口测试，不打入生产依赖 |

Spring事务和Spring JDBC能力沿用上述依赖体系；不为使用@Transactional再引入另一套事务框架。MyBatis-Plus官方明确建议不要再次引入独立MyBatis／MyBatis Starter／MyBatis-Spring，避免版本冲突。[MyBatis-Plus安装说明](https://baomidou.com/en/getting-started/install/)。

本地独立启动若暂时拿不到内部BOM，可以用公开的Spring Boot2.7.18父POM做兼容开发；入行后替换为宿主的父POM和dependencyManagement。该版本只作为兼容开发参考，生产补丁按客户实际维护线确定；2.7.18已是2.x公开开源支持的最后版本。[官方版本说明](https://spring.io/blog/2023/11/23/spring-boot-2-7-18-available-now/)。

### HTTP调用

Java调用Python使用Spring Web已有的RestTemplate即可，无需引入内部RPC、Feign或WebFlux。需要连接池时可加公开的`org.apache.httpcomponents:httpclient`4.x，并由Boot／宿主管版本；Boot2.7.18管理的版本为4.5.14。Spring5.3的该请求工厂支持Apache HttpClient4.x连接池，不能直接换成Boot3常用的HttpClient5配置代码。[Spring请求工厂](https://docs.spring.io/spring-framework/docs/5.3.39/javadoc-api/org/springframework/http/client/HttpComponentsClientHttpRequestFactory.html)、[Boot依赖版本表](https://docs.spring.io/spring-boot/docs/2.7.18/reference/html/dependency-versions.html)。

### JDBC坐标

客户清单是旧坐标`mysql:mysql-connector-java:8.0.11`。若本地采用公开Boot2.7.18父POM，其管理的是`com.mysql:mysql-connector-j:8.0.33`。这两种不能作为两份驱动一起装入宿主；最终选用哪份，以实际依赖树和驱动版本确认后统一。MySQL从8.0.31起调整过Maven坐标。[MySQL官方说明](https://blogs.oracle.com/mysql/mysql-connectorj-has-new-maven-coordinates)。

### 可选，不作为初始必需依赖

| 包 | 客户版本 | 加入条件 |
| --- | --- | --- |
| org.projectlombok:lombok | 1.18.24 | 团队需要简化POJO时使用，注意编译期配置；普通Java类也可完成 |
| org.apache.poi:poi-ooxml | 4.1.2 | 明确需要.xlsx导入／导出时，再按宿主已管理版本接入 |
| org.apache.httpcomponents:httpclient | 宿主或Boot管理 | 使用HTTP连接池时加入，避免同时堆叠多种客户端 |

当前模板、异常明细及报表输出均为CSV，前端已有原生解析／下载，因此本轮无需新增POI、EasyExcel、Spire或前端xlsx库。

Jackson沿用Web starter，不同时引入Fastjson1和Fastjson2。常用日期、集合、字符串操作优先使用JDK8，不为少量工具方法拉入完整Hutool。

## 4. Python最小依赖

当前运行清单可以保留，四项版本与客户清单一致，另加当前已使用的公开PyMySQL：

```text
fastapi==0.136.1
uvicorn==0.46.0
pydantic==2.13.3
python-dotenv==1.2.2
pymysql==1.1.1
```

| 包 | 用途 |
| --- | --- |
| FastAPI／Uvicorn | 算法能力HTTP服务及运行容器 |
| Pydantic | 输入输出、规则、模型JSON结果校验 |
| python-dotenv | 沿用现有MySQL启动参数读取，不把业务参数新增到.env |
| PyMySQL | Python自有库的标签、画像、向量、缓存及算法执行记录 |

测试环境增加`httpx==0.28.1`即可支撑当前TestClient等验证；客户清单已有同版。运行代码如继续使用标准库HTTP，不强制把httpx加入运行依赖。MySQL若采用sha256／caching_sha2认证，可按实际需要使用`PyMySQL[rsa]`，不要为了减少包而改变数据库认证方式。[PyMySQL官方安装说明](https://pymysql.readthedocs.io/en/latest/user/installation.html)。

客户requirements是较完整环境导出，不是本项目必须全装的功能清单。当前算法无需额外引入LangChain、LangGraph、DeepAgents、LangSmith、Anthropic／Google／OpenAI SDK、对象存储SDK或火山SDK。清单中的`# via automatic-bank-social-media`是依赖来源注释，不代表需要安装一个额外内部包。

现有文本与向量调用已使用共享HTTP适配；数值匹配使用现有计算代码，暂不要求NumPy、SciPy、FAISS、独立向量数据库或Celery／Redis。后续确定CP-SAT阶段时才评估OR-Tools，届时按Python3.11目标环境锁版本。

客户文件最后的`boto3`未锁版本，也不是当前功能依赖，不应把它随完整环境盲目复制。最终交付要为所选最小依赖生成包含传递依赖的目标环境锁文件，不能只把这五行称为完整离线依赖锁。

已对backend/app的167个Python文件做Python3.11语法级检查，未发现语法问题；尚未在真实3.11运行时做依赖安装和完整测试，现有359项回归是在当前本机环境完成。

## 6. 行内专用组件放在哪里

| 行内能力 | 公共业务代码使用方式 | 驻场适配位置 |
| --- | --- | --- |
| 父POM、框架BOM | 本地公共父POM；业务代码不继承内部基础类 | 工程父POM／依赖管理 |
| 数据源中间件 | 注入标准javax.sql.DataSource，Mapper不new内部数据源 | DataSource配置 |
| 登录、UM及权限SDK | 业务接收统一操作人和数据权限对象 | Java身份／权限适配器 |
| 配置中心 | 业务代码面向配置对象，不直接调用内部SDK | 配置适配器 |
| 行内调度 | Java暴露可被调用的业务执行方法 | 调度Job适配器 |
| 网关、注册、RPC | 业务及Python能力保持普通HTTP边界 | 宿主启动、路由及部署配置 |

本地策划模块不直接依赖内部Parent、Halo基础类、用户中心、权限过滤器、RPC、消息、数据中台或调度SDK。这些可能仍是宿主启动的必要组件，进入行内时由宿主加载并完成适配，不能据此承诺整个行内工程完全不需要内部依赖。

Java工程可以沿用客户api／client／entity／server／services层次命名，类内部使用公共类型。Java业务逻辑和Python算法通过能力接口对接，不再沿用旧方案中将全部页面业务透明转发给Python的方式。

## 7. 文档中待核实的版本问题

1. Boot真实版本：打包插件2.7.5不能代替有效依赖版本，内部BOM版本也不是Spring Boot版本。
2. MyBatis-Plus、MyBatis Starter和PageHelper同时出现在宿主清单：本模块不再重复声明另一套，先看现有排除和传递依赖。
3. JUnit Jupiter5.10.0与Platform Launcher1.9.3分属不同版本线。建议Boot测试starter或JUnit BOM统一，不单独拼版本；JUnit5.10对应Platform1.10系列。[JUnit官方版本管理说明](https://docs.junit.org/5.10.0/user-guide/index.html)。
4. Hutool显式5.3.1和属性5.8.4并存：有效版本要以Maven结果为准，本模块暂不依赖它。
5. 客户Python3.11导出环境与本机3.14.5不同，需要独立兼容验证；前端构建插件与TypeScript版本也尚未完整提供。
6. 客户文本模型清单为doubao-seed-2-0-lite-260215，当前真实配置为doubao-seed-2-1-lite-260915；应作为模型配置与契约差异确认，不通过随意换SDK解决。客户材料未给本项目所需的向量模型，当前使用doubao-embedding-vision-251215、2048维，最终需确认内网可用型号及调用方式。另一条Seedream型号不是本阶段文本匹配能力的依赖。

最少需要客户提供的是实际有效依赖信息，不涉及业务表结构：

```bash
java -version
mvn help:effective-pom -Doutput=effective-pom.xml
mvn dependency:tree -DoutputFile=dependency-tree.txt
python --version
node --version
```

再补充前端package.json与lock文件即可精确收口。有效POM及依赖树如含内部仓库地址或其它敏感信息，可只在行内核对相关公开组件的有效版本。

以上是依赖选择和兼容开发建议；当前没有真实Java工程或内部BOM，尚未完成Java依赖解析、编译及行内集成验证。
