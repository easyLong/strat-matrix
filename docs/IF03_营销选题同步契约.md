# IF-03 营销选题同步本地契约

依据《多账号智能策划_PRD_V1.0.docx》第 8.2.3 节。客户最终技术协议尚未提供，当前提供受 `X-Integration-Token` 保护的本地 HTTP JSON 入口。

## 全量同步

`POST /api/integrations/marketing-topics/sync`

```json
{
  "source_batch_id": "MKT-20261008-001",
  "snapshot_at": "2026-10-08T20:00:00+08:00",
  "records": [
    {
      "topic_id": "MKT-TOPIC-001",
      "account_id": "ACCOUNT-001",
      "title": "营销选题标题",
      "outline": "内容大纲",
      "content_type": "图文",
      "approval_status": "approved",
      "approved_at": "2026-10-07T16:00:00+08:00",
      "valid_from": "2026-10-08T00:00:00+08:00",
      "valid_to": "2026-10-31T23:59:59+08:00",
      "enabled": true
    }
  ]
}
```

每次请求代表当前完整营销选题集合，最多 5000 条。`records: []` 是一次有效的空快照；快照未出现的旧营销选题标记为不在当前快照中，不物理删除。`snapshot_at`、`approved_at` 和有效期时间必须带时区。审核通过的选题必须提供 `approved_at`，用于后续按审核通过时间升序使用。同一批次 ID 与相同内容重传返回原结果；同 ID 不同内容或时间未晚于最近成功快照时返回 409。

独立表 `godp_marketing_topic_source` 保存来源选题、账号绑定与审核/有效期事实；`godp_marketing_sync_run` 保存每次成功快照，包括空快照。它不改变普通选题目录。周度规则策划读取该快照安排营销槽位；营销与普通选题即使使用相同来源 ID，也不会互相覆盖。

项目内部可通过 `GET /api/internal/marketing-topics/sync-status` 查询最近一次成功快照，区分尚未同步（`synced=false`）和成功同步但无选题（`synced=true, received=0`）。这是内部诊断接口，不是 IF-03。

周度规则策划先规划全局热点空槽，再安排营销槽位。部署更新后运行 `cd backend && python3 -m app.init_db`。新表及全部字段均有中文说明。
