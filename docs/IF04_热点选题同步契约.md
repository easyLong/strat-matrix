# IF-04 热点选题同步本地契约

依据《多账号智能策划_PRD_V1.0.docx》第 8.2.4 节。客户最终技术协议尚未提供，当前提供受 `X-Integration-Token` 保护的本地 HTTP JSON 入口。

## 全量同步

`POST /api/integrations/hotspot-topics/sync`

```json
{
  "source_batch_id": "HOT-20261008-001",
  "snapshot_at": "2026-10-08T20:00:00+08:00",
  "records": [
    {
      "topic_id": "HOT-TOPIC-001",
      "title": "热点选题标题",
      "outline": "内容大纲",
      "content_type": "图文",
      "valid_from": "2026-10-08T00:00:00+08:00",
      "valid_to": "2026-10-09T23:59:59+08:00",
      "enabled": true
    }
  ]
}
```

每次请求代表当前完整热点选题集合，最多 5000 条。`records: []` 是一次有效的空快照；未出现的旧热点选题标记为不在当前快照中，不物理删除。时间字段必须带时区。同一批次 ID、相同内容重传返回原结果；同 ID 不同内容或时间未晚于最近成功快照时返回 409。

`godp_hotspot_topic_source` 独立保存热点选题，`godp_hotspot_sync_run` 保存成功快照。普通、营销和热点选题的来源 ID 可相同，不会互相覆盖。项目内部可通过 `GET /api/internal/hotspot-topics/sync-status` 区分尚未同步与成功空快照。

周度规则策划已先规划热点空槽；目标槽位前一天 22:00 的任务仍待接入，届时读取最近有效热点、确定选题或使用普通最热兜底。部署更新后运行 `cd backend && python3 -m app.init_db`。新表及全部字段均有中文说明。
