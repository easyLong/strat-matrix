## 2. 生命周期可直接整理进 PRD 的规则

五个阶段名称保持固定，按成熟度从高到低首次命中即停止，冷启验证期为唯一兜底；每个账号必须且只能属于一个阶段。条件支持字段、比较符、阈值及 AND/OR。

| 判定顺序 | 阶段 | 当前默认进入条件 |
| --- | --- | --- |
| 1 | 稳定经营期 | 粉丝数 ≥ 1000，且滚动篇均互动 ≥ 20，且有效内容数 ≥ 5 |
| 2 | 转化放大期 | 粉丝数 ≥ 500，且滚动篇均互动 ≥ 10，且有效内容数 ≥ 5 |
| 3 | 转化试探期 | 粉丝数 ≥ 200，且滚动篇均互动 ≥ 5，且有效内容数 ≥ 5 |
| 4 | 流量增长期 | 粉丝数 ≥ 50，或有效内容数 ≥ 5；同时未命中更高阶段 |
| 5 | 冷启验证期 | 未命中其他阶段；当前默认下等价于粉丝数 < 50 且有效内容数 < 5 |

这组数值是垂直细分账号的运营起始配置，尚未经过实际经营效果验证。经营目标仍由五阶段独立配置，不能因删除生命周期定义表内的“目标/回退”列而从账号画像或正式匹配输入中删除经营目标。

建议补充指标口径：

- 有效内容数：以本次指标计算时点向前回溯三个月，统计同步数据中的已发布内容；不以本策划周的计划槽位数计算。
- 当前代码按同日同时间回溯三个月，并处理月末日期，不是按完整三个自然月取数。PRD 写“近三个月”即可，但配套阈值说明中“近三个自然月”需要修正。
- 滚动窗口 X 默认 10 篇；从近三个月有效内容中取最近 X 篇，不足时按实际篇数计算。
- 单篇互动 = 红星/点赞 + 收藏 + 评论；滚动篇均互动 = 所取内容互动总量 / 实际篇数。它是均值，不是互动总数。
- 本周期槽位数 N = 选中的每周策划日数量，默认周一/三/五，N=3；X 与 N 无关。
- 更新代码默认值不覆盖数据库里的已保存配置。已有实例须经配置保存或明确迁移生效，新批次读取新版本，旧画像和历史结果保留旧快照。

参照实现：[models.py](../backend/app/models.py)、[account_metrics.py](../backend/app/account_metrics.py)、[生命周期阈值说明](LIFECYCLE_DEFAULTS.md)。

## 3. 周期状态与完成口径

建议将运营周期状态与技术任务执行状态分别定义：

| 周期状态 | 判定要求 |
| --- | --- |
| 已规划 | 基础槽位规划已完成，普通/营销槽位已确定可用选题，热点空槽已合法规划，且尚未进入目标周期。 |
| 热点空槽待填充 | 已进入目标周期，仍有尚未确定选题的合法热点槽位；展示“已确定热点槽位 / 已规划热点槽位”，例如 4/20。 |
| 已完成 | 已进入目标周期，所有应规划槽位均已确定有效选题，包括热点选题或合法普通兜底；完成策划不等于内容已发布。 |

调度尚未到时间时属于“待调度”，不能视为已经规划。没有热点槽位的周期，在进入执行期且其余槽位已完成时可直接进入已完成。

异常任务不能归为“热点空槽待填充”。PRD 3.6 已明确“兜底仍无合法选题则槽位失败”，同步失败也不能解释为空数据。即使常见情况下有兜底，仍应保留内部异常、重试及最后更新时间；失败账号入口如何呈现，需要与简化后的运营页面一起收口。

原 PRD 的“成功账号数”指基础规划成功，热点未填也可成功；当前周期接口的 `success_accounts` 排除了热点待填账号，语义已经变化。建议明确拆为“基础规划完成账号数”和“全部选题确定账号数”，不要继续用一个字段表达两种含义。总表是否展示这些指标可独立决定。

需同步更新 3.3、3.11、3.13、7.1、7.8 及相应页面验收，不把标签识别、向量准备或内部执行提案状态映射为运营策划完成。

## 4. 结果页字段与统计

建议周期汇总显示：策划周期、自动策划账号数、自动策划槽位数、手动追加槽位数、总槽位数、常规槽位数、营销槽位数、热点槽位数、去重选题数、最后更新时间、操作。

统计等式：

```text
总槽位数 = 自动策划槽位数 + 手动追加槽位数
自动策划槽位数 = 常规槽位数 + 营销槽位数 + 热点槽位数
```

三种槽位数量按规划意图计算。营销槽位绑定普通兜底后仍计营销槽位；热点空槽后续确定选题不新增槽位。最终普通/营销/热点选题数量另按当前有效选题统计，尚未填充的热点槽位不计入任何最终选题类型。选题使用次数不在该表展示，IF-09 的正式使用次数仍保留独立业务语义。

周度归集包含该周期内的各技术批次和手动追加；“批次详情”当前实际查询的是周期汇总结果，并非仅一个数据库技术批次。PRD 应明确这层含义及直接查询条件，避免接口误按单批次过滤。

账号详情需描述：无需从上层进入即可查询；按账号查看历史批次，按投放日期范围过滤，历史从新到旧排列；每条显示投放日期及星期。经营阶段展示对应历史快照，不能把账号当前阶段覆盖到所有历史批次。替换选题和查看调整记录保留两个独立入口。

## 6. 正式 AI 主链与部署改动的文档边界

最近增加的准备记录、账号/选题向量、冻结输入、策略版本、执行租约和提案留痕属于内部执行基础。PRD 3.4.6、3.6、6.5、7.10 可增补：准备就绪只代表输入有效；提案通过契约校验只代表结构合法；只有算法与完整槽位组合执行完毕、结果原子提交成功后，才形成正式策划结果。

算法服务、评分与全局分配参数、完整组合及结果原子提交仍未完成，不能将规则热度兜底批次称为真实 AI 匹配成功。现有开发对照应继续保留这项限制。

`0.0.0.0` 监听、端口从 `.env` 读取、脚本可执行权限、前端构建和服务重启属于部署文档。它们不改变 PRD 的业务规则；演示数据刷新也不应改变真实历史完成判定或成为业务验收依据。

## 7. 建议修订顺序与验收补充

1. 先更新生命周期、状态和槽位统计三个 P0 口径及对应验收表、流程图。
2. 收口手动账号改选、月内周次、结果页导航及历史查询，再更新原型截图和第 4、5 章。
3. 修复第 5 节的实现问题；补齐初始化默认值与已保存配置的生效说明。
4. 保留算法参数待定项和内部执行基础说明，正式 AI 结果提交完成后再验收主链。

新增验收至少覆盖：生命周期阈值等号边界与唯一命中；少于 X 篇的均值；同一账号不同批次阶段变化；下周已规划与本周热点逐步填充；没有热点的周期；真实依赖异常不会显示为正常热点等待；普通兜底不改变槽位计数；跨月不拆周与 2026-08-31 月内周次；随机后调整仍严格满足 M；本地与服务器的已保存配置及前后端契约一致。
