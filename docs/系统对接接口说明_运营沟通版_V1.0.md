# 多账号智能策划系统对接接口说明（运营沟通版）

版本：V1.0
用途：需求澄清会、运营协同与接口分工确认
业务口径：本期对外接口共 7 个：IF-01～IF-06、IF-08。普通选题标签查询不再作为独立对外接口；原 IF-09“选题正式使用次数查询”调整编号为 IF-08。另有 1 个项目内部运营查询 OP-01，用于查看普通选题批量打标效果，不计入对外接口数量。

> 本文面向策划、运营和项目协作人员，保留已确认的主要业务字段，说明数据从哪一方流向哪一方，以及双方各自负责什么。字段名称用于和现有需求、已确认接口口径对照；本文不定义字段类型、接口地址或鉴权方式。

## 1. 如何看接口方向

“平台侧”指客户已有的账号、选题、内容生产和选题使用次数相关系统；“策划系统”指多账号智能策划项目。

- **同步和状态回传：** 箭头表示业务数据由提供方流向接收方。
- **查询接口：** 平台先向策划系统发起查询，策划系统再把查询结果返回平台，因此会同时标出请求方向和结果方向。
- **平台提供业务事实，策划系统负责策划计算。** 例如平台提供账号互动原始数据，账号阶段、流量趋势和选题分配由策划系统计算。

## 2. 接口总览

| 接口 | 业务方向 | 平台侧提供或发起 | 策划系统提供或处理 |
| --- | --- | --- | --- |
| IF-01 账号与互动数据同步 | 平台账号系统 → 策划系统；策划系统 → 平台账号系统（同步结果） | 提供账号名单、账号资料、认证与粉丝信息，以及近三个月内容和互动情况 | 保存账号数据；计算有效内容数、互动表现、流量趋势和生命周期，并反馈本次同步处理情况 |
| IF-02 普通选题同步 | 平台选题库 → 策划系统；策划系统 → 平台选题库（同步结果） | 提供普通选题内容、内容类型、热度及当前可用情况 | 保存并维护普通选题目录，供自动策划、手动策划和选题兜底使用；反馈同步处理情况 |
| IF-03 营销选题同步 | 平台营销选题库 → 策划系统；策划系统 → 平台营销选题库（同步结果） | 提供营销选题、适用账号、审核情况和有效时间 | 保存营销选题；校验账号绑定、审核与有效期，供符合条件的营销槽位使用 |
| IF-04 热点选题同步 | 平台热点选题库 → 策划系统；策划系统 → 平台热点选题库（同步结果） | 提供热点内容、可用情况和有效时间，并在约定策划时间前更新 | 保存热点信息；在热点槽位执行时间为账号选择热点，无合适热点时按策划规则使用普通选题兜底 |
| IF-05 策划结果查询 | 平台内容生产方 → 策划系统（查询）；策划系统 → 平台内容生产方（结果） | 按账号发起查询；内容生产前及正式发布前获取最新结果 | 返回该账号当前可进入内容生产的策划结果和选题信息；查询本身不锁定结果 |
| IF-06 发布状态回传 | 平台内容生产方 → 策划系统 | 内容发布后回传实际发布的选题和发布状态 | 核对回传内容是否与当前策划结果一致；一致后更新为已发布，并关闭该结果的替换操作 |
| IF-08 选题正式使用次数查询 | 平台选题系统 → 策划系统（查询）；策划系统 → 平台选题系统（次数结果） | 按普通、营销或热点选题类别，查询一个或多个选题的正式使用次数 | 返回已同步的正式使用次数；不根据策划、人工替换或发布回传自行推算次数 |

## 3. 各接口业务说明

### IF-01 账号与互动数据同步

**方向：** 平台账号系统提供数据给策划系统；策划系统向平台反馈同步处理情况。

**主要字段（平台提供）：** `account_id`（账号 ID）、`account_name`（账号名称）、`account_alias`（账号别名）、`account_status`（账号状态）、`certification_status`（认证状态）、`account_persona`（账号人设）、`is_marketing_account`（是否营销账号）、`account_tags`（账号标签）、`follower_count`（粉丝数）、`interaction_data`（内容及互动数据，包含发布时间、标题、红星/点赞、收藏、评论等）。

**主要结果（策划系统反馈）：** 本次同步处理结果及新增、更新、停用等处理数量；阶段、趋势和有效内容等策划指标由策划系统计算并在项目页面查看。

**平台提供：** 当前账号名单、账号名称和别名、账号是否有效、认证情况、粉丝量、账号定位，以及近三个月已发布内容的时间和红星、收藏、评论等互动情况。

**策划系统处理：** 保存本地账号数据，计算有效内容数、滚动互动表现、流量趋势和生命周期阶段，供自动策划与手动筛选使用。

**责任边界：** 平台提供账号事实和原始互动数据；生命周期、流量趋势等策划指标由策划系统计算，不要求平台先行计算。

### IF-02 普通选题同步

**方向：** 平台普通选题库提供数据给策划系统；策划系统向平台反馈同步处理情况。

**主要字段（平台提供）：** `topic_id`（选题 ID）、`title`（标题）、`outline`（内容大纲）、`content_type`（内容类型）、`topic_heat`（选题热度）、`status`（选题状态）。

**主要结果（策划系统反馈）：** 本次同步处理结果及新增、更新、停用等处理数量。

**平台提供：** 普通选题标题、内容大纲、内容类型、热度和当前可用情况。

**策划系统处理：** 保存本地普通选题目录，供自动策划、手动策划、热点兜底和运营替换选题使用。

**责任边界：** 平台维护选题来源信息和热度；策划系统维护本地策划可用状态，并负责后续的选题筛选与分配。

### IF-03 营销选题同步

**方向：** 平台营销选题库提供数据给策划系统；策划系统向平台反馈同步处理情况。

**主要字段（平台提供）：** `topic_id`（选题 ID）、`account_id`（适用账号 ID）、`title`（标题）、`outline`（内容大纲）、`content_type`（内容类型）、`status`（选题状态）、`audit_status`（审核状态）、`approved_at`（审核通过时间）。

**主要结果（策划系统反馈）：** 本次同步处理结果及新增、更新、停用等处理数量。

**平台提供：** 营销选题内容、绑定账号、审核状态、审核通过时间及有效时间。

**策划系统处理：** 保存营销选题，并在策划时检查账号绑定、审核状态和有效期，再用于符合条件的营销账号与槽位。

**责任边界：** 平台负责营销选题和审核事实；策划系统负责按策划规则判断是否可用。

### IF-04 热点选题同步

**方向：** 平台热点选题库提供数据给策划系统；策划系统向平台反馈同步处理情况。

**主要字段（平台提供）：** `topic_id`（热点选题 ID）、`title`（标题）、`outline`（内容大纲）、`content_type`（内容类型）、`status`（热点状态）。

**主要结果（策划系统反馈）：** 本次同步处理结果及新增、更新、停用等处理数量。

**平台提供：** 热点内容、有效时间和当前可用情况，并按双方约定在热点槽位执行前完成更新。

**策划系统处理：** 将热点资料保存到本地，在对应执行时间为已规划的热点槽位确定具体选题；没有合适热点时按既定规则使用普通选题兜底。

**责任边界：** 平台提供热点内容及有效性事实；策划系统负责热点与账号、槽位的匹配及兜底处理。

### IF-05 策划结果查询

**方向：** 平台内容生产方发起查询，策划系统返回结果。

**主要字段（平台发起）：** `account_id`（账号 ID）。

**主要字段（策划系统返回）：** `account_id`（账号 ID）、`planning_cycle`（策划周期）、`planning_contents`（策划内容列表）；列表中主要包含 `planning_result_id`（策划结果 ID）、`publish_date`（投放日期）、`topic_id`（选题 ID）、`topic_type`（选题类别：普通/营销/热点）、`title`（标题）、`outline`（内容大纲）、`content_type`（内容类型）。

**平台发起：** 内容生产方按账号获取当前可生产的策划结果；正式发布前再次查询，确认选题仍是最新有效结果。

**策划系统返回：** 账号当前可生产的策划周期、投放安排、已确定选题及内容大纲等业务信息。尚未确定选题的热点空槽不作为可生产结果返回。

**责任边界：** 平台内容生产方负责按结果生产和发布内容；策划系统负责提供当前有效策划。查询不会锁定策划或禁止运营替换。

### IF-06 发布状态回传

**方向：** 平台内容生产方将实际发布情况回传给策划系统。

**主要字段（平台提供）：** `planning_result_id`（策划结果 ID）、`topic_id`（实际发布选题 ID）、`topic_type`（选题类别）、`publish_status`（发布状态）。

**主要结果（策划系统反馈）：** `current_publish_status`（策划系统核对后记录的当前发布状态）。

**平台提供：** 实际发布的选题和发布状态。该接口反映发布事实，不用于报告内容生成中的进度。

**策划系统处理：** 将回传内容与当前有效策划核对；一致时把结果更新为已发布，并关闭人工替换。信息不一致时不覆盖当前策划结果。

**责任边界：** 平台是实际发布情况的事实来源；策划系统负责核对策划一致性并维护结果状态。

### IF-08 选题正式使用次数查询

**方向：** 平台选题系统发起查询，策划系统返回次数。

**主要字段（平台发起）：** `topic_type`（选题类别：普通/营销/热点）、`topic_ids`（一个或多个选题 ID）。

**主要字段（策划系统返回）：** `topic_type`（选题类别）、`topic_id`（选题 ID）、`official_use_count`（正式使用次数）。

**平台发起：** 按选题类别，查询一个或多个普通、营销或热点选题的正式使用次数。

**策划系统返回：** 每个选题当前已同步的正式使用次数。若次数尚未取得，不能将未知显示为零次。

**责任边界：** 正式使用次数由独立业务统计来源维护；策划系统负责读取并返回已同步的次数，不根据策划次数、人工替换或发布回传自行计算。

## 4. 项目内部运营查询（不属于对外 IF）

### OP-01 普通选题批量打标效果查询（建议新增）

**用途：** 运营查看一批普通选题的标签识别进度和结果质量概况，确认哪些已完成、哪些仍在处理、哪些需要关注。查询只读取项目内部的标签任务和标签结果，不调用模型、不触发重试，也不修改标签。

**方向：** 项目运营页面发起查询 → 策划系统汇总并返回统计和选题明细。该查询由本项目内部页面使用，客户平台不调用，也不属于 7 个平台对接接口。

**主要查询条件：** 标签任务创建时间范围、打标状态（全部/待处理/处理中/已完成/失败）、选题 ID 或标题关键词；支持分页查看明细。由于当前标签任务按单个选题记录，系统根据筛选范围汇总成一批展示，不要求运营侧先提供一个尚不存在的批次编号。

**主要汇总结果：** 纳入统计的选题数、待处理数、处理中数、已完成数、失败数、完成率、最后更新时间。

**主要明细字段：** 选题 ID、选题标题、内容类型、标签状态、T1–T6 标签结果、失败原因（仅失败时显示）、任务创建时间、完成时间、标签体系版本。

**运营边界：** 运营可以查看筛选后的总体进度和逐条标签结果；标签识别与写入由项目内部任务执行器完成。重新识别、人工改标签或批量重试属于后续独立操作，不包含在本只读查询中。

## 5. 双方职责汇总

| 业务内容 | 平台侧 | 策划系统侧 |
| --- | --- | --- |
| 账号与内容资料 | 提供账号资料、账号状态、粉丝和原始互动情况 | 保存快照，计算阶段、趋势及策划所需指标 |
| 普通、营销与热点选题 | 提供选题内容、审核/有效情况及来源信息 | 保存各类选题，按策划规则筛选、匹配和分配 |
| 内容生产与发布 | 生产内容，提供实际发布结果 | 提供当前策划，核对发布回传并更新状态 |
| 正式使用次数 | 维护或确认次数的业务事实来源 | 查询并返回已同步次数，不自行推算 |
| 生命周期、标签、匹配与槽位分配 | 无需重复提供策划计算结果 | 由策划系统内部计算和维护 |

## 6. 需求沟通时建议确认

1. IF-01～IF-04 的数据由哪个平台团队提供，更新频率和完成时间如何安排。
2. IF-05 由哪一个内容生产方或 Agent 调用，发布前如何确保使用的是最新策划。
3. IF-06 由哪个发布流程回传，实际发布选题与策划结果不一致时如何协同处理。
4. IF-08 正式使用次数由哪个业务系统维护，多久同步一次；未知次数如何补齐。
5. 运营和客户会议材料按本稿使用 IF-08 表示“选题正式使用次数查询”；其他仍沿用旧 IF-08 标签查询编号的材料需一并校正。
6. OP-01 的运营页面是否需要增加标签体系版本、失败原因筛选或重新识别操作；本稿先按只读查询设计。
