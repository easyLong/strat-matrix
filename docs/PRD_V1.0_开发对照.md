# PRD V1.0 开发对照

基线文档：《多账号智能策划_PRD_V1.0.docx》（2026-09-30）。本页记录当前代码与正式 PRD 的对应关系，避免将演示数据和页面占位误认为正式业务闭环。

## 已有基础

- 四个运营页面、手动策划预览与提交、策划结果查询和人工替换页面已存在。
- 本地账号、选题、历史内容同步入口及投递事件表已存在；当前接口契约仍需按第 8 章调整。
- 配置模块版本、恢复与并发版本检查已存在。

## 本轮落地

- 每周策划日、自动策划调度时间、营销账号每周上限、热点槽位占比进入服务端账号配置模块，默认分别为周一/三/五、周二 22:00、1 条、20%。
- 生命周期阶段进入条件进入服务端经营策略模块；固定五阶段，按成熟度从高到低匹配，冷启验证期兜底。经营目标继续单独配置。
- 配置字段在服务端校验，随模块版本保存和恢复；无修改时页面禁用保存按钮。AI 自动策划页读取服务端当前配置。
- 周度规则策划已可由服务器命令或独立进程触发：按配置比例先规划热点空槽，再安排账号绑定的营销槽位，其余使用普通选题热度兜底；批次、槽位、结果版本和输入快照落库。操作方式见[周度规则策划首版](ORDINARY_PLANNING.md)。
- 独立调度进程已接入 Linux 启停脚本：按配置的北京时间为下周生成正式规则批次，失败一小时后重试；同周期由数据库锁和运行记录去重。
- 热点调度进程已接入 Linux 启停脚本：T-1 22:00 后处理正式热点空槽，按 IF-04 最新成功快照随机分配合法热点，候选不足时用普通最热选题兜底；更新结果版本、自动调整历史与周期状态。
- IF-05 / IF-06 本地 HTTP 契约已接入：按账号查询当前可生产、未发布的有效结果；发布回传校验结果版本、选题 ID 和类型，记录不一致事件并关闭已发布结果的人工替换。见[本地对接契约](IF05_IF06_本地对接契约.md)。
- IF-08 / IF-09 本地 HTTP 契约已接入：普通选题标签结果只读查询；三类选题正式使用次数从独立快照读取，并由内部入口按来源版本导入和留痕。见[本地对接契约](IF08_IF09_本地对接契约.md)。
- IF-03 本地全量快照入口已接入：营销选题与账号绑定、审核及有效期独立保存，空快照与尚未同步可区分。见[本地对接契约](IF03_营销选题同步契约.md)。
- IF-04 本地全量快照入口已接入：热点选题及有效期独立保存，空快照与尚未同步可区分。见[本地对接契约](IF04_热点选题同步契约.md)。
- IF-01 本地接口已接收账号别名、认证、营销资格、人设、粉丝数与近三个月帖子级互动；生命周期与手动策划流量趋势优先由同一份互动快照计算。IF-02 已接收普通选题热度及可用状态。两类接口均已支持原子全量快照、缺席记录停用、批次重传和旧增量字段兼容。见[本地对接契约](IF01_IF02_本地对接契约.md)。
- T1–T5 字典已把稳定 ID、启停状态和版本保存到服务端；改名保留 ID，停用保留历史。选题标签写入现在绑定 T1–T5 ID 与识别字典版本，并保存逐版快照；旧记录可唯一确定的 ID 已补录。见[标签字典治理](TAG_TAXONOMY.md)。
- 普通选题首次同步会创建离线标签识别任务；本地识别进程可领取首次入库快照和当前字典、调用按项目 JSON 契约配置的模型服务、校验并提交成功或失败结果。T6 候选按同模型向量余弦相似度严格大于 80% 复用已有标签，否则新增并绑定稳定 ID；旧标签按名称补 ID。租约过期与失败均可重试，已完成标签不因后续选题编辑重算。模型服务未配置时进程默认关闭。见[识别任务契约](TOPIC_LABEL_JOBS.md)。
- 已完成标签的正式普通选题会生成当前内容画像；画像字段变化使旧向量失效，但不重算 T1–T6。内部接口可按画像指纹领取准备任务、回写向量，并只查询标签和当前画像向量都有效的 AI 候选；具体向量服务尚未接入。见[选题画像与向量准备](TOPIC_PROFILE_VECTOR.md)。

## 待落地的正式业务闭环

1. **配置与账号数据**：T1–T5 字典与选题标签 ID 关联已落库；无法从旧数据唯一推断的标签 ID 不编造。近三个月帖子级指标已进入批次账号快照，仍需完整账号画像及向量准备。旧演示结果页的经营阶段仍使用演示推断值。
2. **上游数据接口**：IF-01/02 的核心字段及本地全量/增量语义已接入；客户最终分页、鉴权和调用协议仍需确定。IF-03 营销和 IF-04 热点选题已可按全量快照接收。
3. **自动策划引擎**：热点空槽先于营销槽位的规则规划已接入；普通选题首次标签任务、可配置的本地模型服务执行进程、T6 同模型相似度复用、选题画像版本与向量准备状态已接入，仍需确定具体向量服务、账号画像及正式匹配。当前普通内容使用热度兜底。
4. **内容生产闭环**：IF-05 / IF-06 / IF-08 / IF-09 已有本地 HTTP 契约；仍需客户确认正式鉴权与调用协议，接入模型标签识别和独立正式使用计数来源。既有内容生成进度接口仍独立存在。
5. **审计与权限**：补齐配置、标签及结果调整的操作日志和服务端授权；热点自动确定已保存调整历史，当前页面按钮权限仍以服务可用性控制。

优先顺序：先完成上游数据契约和状态/版本模型，再接入自动策划及热点任务，最后完成生产查询、发布回传和审计验收。涉及匹配评分、向量模型和调度实现的参数，以后续算法/技术设计文档为准。
