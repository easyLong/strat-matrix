# 多账号智能策划近期修改汇总

更新日期：2026-10-28。对应代码截至 `2c2a03a`，涵盖当日四次功能与样式提交。本文用于产品评审、开发交接和部署升级，记录当前最终页面行为。

当前一级页面为 **AI策划配置、人工策划、策划结果**。营销人工策划已调整为“单选选题、填写总分配数量、由外部系统分配账号”；确认仍为完整步骤页。非营销保留日期、账号和多选选题流程。

## 人工策划

### 营销与非营销的当前流程

| 环节 | 营销 | 非营销 |
| --- | --- | --- |
| 创建策划 | 填写任务名称，选择营销 | 填写任务名称，选择非营销及投放日期 |
| 选择账号 | 无此步骤，由外部系统后续分配 | 保留维度筛选和模板导入、计划账号数量、勾选及分页 |
| 选择选题 | 单选一个选题；选题列表全宽展示 | 多选选题，左侧展示已选，右侧展示可选列表 |
| 分配数量 | 选中选题后，在列表下方填写 1 至 1000 的整数；表示此选题待分配并生产的内容总条数 | 不显示此字段 |
| 确认策划 | 独立的第三步，展示任务名称、类型、分配数量及所选选题 | 独立的第四步，展示任务、账号、选题信息 |
| 提交 | 保存营销需求，初始为待分配，不预设账号或投放日期 | 复核所选日期的账号占用情况，通过预览及提交接口创建任务 |

营销步骤条为“创建策划 → 选择选题 → 确认策划”。已删除“每账号生产数量”，不再使用侧边抽屉确认。分配数量标签、必填标记、含义气泡和输入框同一行展示，选题保存后冻结，返回调整后可修改。

营销选题库默认筛选营销，也保留切换为非营销的既有能力；无论筛选哪种类型，一次任务只能保存一个选题。切换筛选、分页后仍保留单选值，选择另一个选题会替换原选择。

### 策划任务列表

- 批次放第一列，上方为名称，下方为批次号；列表保留创建人及时间信息。
- 新增分页，支持每页 10、20、50 个任务；本轮最终移除了任务列表筛选区。
- 操作名称保留“查看策划”和“查看内容流水”。已有正式批次的“查看策划”复用策划结果中的批次策划详情；尚无正式批次的营销需求打开营销任务详情。
- 新营销任务账号尚未分配时，账号数列显示“待分配”，详情可查看选题和分配数量。
- 内容生成由后台执行，任务列表不提供主动生成内容按钮。

分页当前作用于接口已返回的数据。营销任务列表接口默认返回最近 20 条，尚未实现跨全部历史任务的服务端分页。

## 策划结果

### 账号列表与时间列表

两个列表的筛选条件默认展开。账号筛选沿用已确认的账号信息维度；时间列表使用开始时间、结束时间以及批次号或批次 ID 查询，查询按钮与筛选项同行。

时间列表的策划周期只显示起止日期，不再显示“某年某月第几周”。列表的“策划总数”改为“账号数”，AI 自动策划和人工策划分别显示批次数及账号数。当前周期账号数按各批次账号数相加，同一个账号参与不同批次会分别计入，并非周期内去重账号数。

时间列表可展开本周期批次，进入单批次后可返回所属周期的全部批次；每行保留导出入口。失败数大于 0 时显示“查看失败详情”，最终操作顺序为：**查看批次 → 查看策划 → 导出 → 查看失败详情**。

### 失败详情与导出

失败详情展示账号名称、账号 ID、属主 UM 号、批次号及失败原因；有可用 UM 号时支持导出 CSV，并提示可转人工策划补充。只存在批次级异常、没有账号级失败明细时，展示批次级原因，不编造账号或 UM 号。

新增内部查询接口 `GET /api/planning-cycles/{cycle_id}/failures`，查询该周期全部策划方式的失败记录。原自动策划失败接口仍保留，并复用失败信息组装方法。

### 三类策划详情的统计

| 页面 | 概览指标 | 选题分类统计 |
| --- | --- | --- |
| 账号策划详情 | 覆盖批次、使用选题 | 12 种选题二级分类分布 |
| 周期策划详情 | 参与账号、使用选题 | 12 种选题二级分类分布 |
| 批次策划详情 | 参与账号、使用选题 | 12 种选题二级分类分布 |

概览指标名称附带含义气泡。“覆盖批次”为当前筛选结果的去重批次数，“参与账号”为去重账号数，“使用选题”为去重选题 ID 数。

选题二级分类采用紧凑的非柱状布局，按数量从高到低排列，同数量沿用固定分类顺序，0 值使用弱化颜色。分类统计按去重选题 ID 计算，不按策划条数重复累加。详情筛选默认展开，账号详情支持实际起止日期查询。

### 导出粒度

账号和时间入口的报表导出以每条策划明细为单位，包含选题 ID 和最新操作记录。账号导出支持选择时间范围，结合当前筛选结果导出。导出实现见 [PlanningExport.vue](../frontend/src/components/PlanningExport.vue)。

## AI策划配置与视觉规范

编辑配置时，生命周期阶段条件直接展开，不再要求对每个阶段另点“编辑”。条件按组展示，组内为且、组间为或，并区分添加条件与添加条件组。阶段经营目标及滚动窗口继续与生命周期判定放在策划规则配置中。

页面样式按数营平台规范调整公共主题色、字体栈、中性色、按钮、输入框、卡片边框及圆角，并收紧配置和列表间距。详细对应关系见 [数营平台UI规范与现有页面差异清单](数营平台UI规范与现有页面差异清单.md)。平台导航、登录及权限仍由宿主负责。

## 营销提交接口与数据库升级

### 当前请求

`POST /api/manual-plans/marketing-tasks` 是项目内部前后端接口，请求字段如下。对行内的同库能力定义仍需按双方约定的方法和表结构实施。

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `request_id` | 同一提交的唯一标识 | UUID；相同标识和相同内容重复提交只保存一次 |
| `task_name` | 任务名称 | 必填，去除首尾空格，最长 120 字符 |
| `topic_id` | 本次选择的单个选题 ID | 必填，最长 64 字符，提交时校验选题可用 |
| `allocation_count` | 此选题需要分配并生产的内容总条数 | 必填，1 至 1000 的整数 |

新请求不再传 `account_ids`、`topic_ids` 或 `content_per_account`，也不传投放日期。前后端必须同时更新，旧请求会被新接口拒绝。返回对象在既有任务摘要中增加 `allocation_count`，可用列表和详情接口读取已保存的需求。

### 数据保存和兼容

`godp_manual_marketing_task` 新增 `allocation_count`，附中文注释。迁移在旧表上为该字段设置默认值 0，历史营销记录继续按原账号快照及每账号条数读取。新任务则保存单个选题快照、总分配数量、空账号数组及“待分配”状态，历史兼容字段 `content_per_account` 写入 0。

本次已实现需求保存、幂等校验和详情查询。外部系统的真实接收、账号分配、分配结果回填、生产审核及正式排期尚未接入该营销任务表；“待分配”不表示已调用外部系统。

### 服务器升级

在仓库根目录更新代码，迁移前按现有运维方式备份数据库；在后端目录执行以下迁移，再重新构建并重启服务：

```bash
git pull --ff-only origin main
cd backend
python3 -m app.init_manual_marketing_db
cd ../frontend
npm ci --include=dev
npm run build
cd ..
./stop.sh
BUILD_FRONTEND=0 ./start.sh
./status.sh
```

命令中的 `python3` 应使用服务器实际运行后端的 Python 解释器。`init_db` 和 `init_workflow_db` 也已包含营销表迁移；本次升级只需执行营销专项迁移即可。前端运行于 Vite Preview 时读取 `dist`，仅更新源码不会显示新页面。
