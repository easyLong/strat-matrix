# 2026-11-11 资料查询接入与交接记录

本轮把既有 Java 资料查询入口与私有 MyBatis SQL 连接起来，复用账号、选题及内容事实契约。Vue 页面、Python 算法接口和业务表结构未改动。开发分支为 `feature/planning-v2`。

## 1. 提交内容

| 改动 | 行为 | 主要文件 |
| --- | --- | --- |
| 统一SQL装配 | 传入宿主资料数据源、对应事务管理器、私有XML和存储时区；不新建连接池、不执行DDL | `BankSourceSqlAdapter.java` |
| 账号互动查询 | 新增`accountInteractions` Mapper方法，账号分页后在同一只读事务内批量补齐互动；空页不查 | `BankSourceMapper.java`、SQL装配器 |
| 启动检查 | 检查11条SELECT，包括账号互动；私有文件缺失或占位未填写时不接受查询，不回退模拟资料 | `BankSourcePreflight`、SQL装配器 |
| 行外资料切换 | 默认fixture；显式选择sql时使用指定XML及现有开发业务数据源 | `LocalManualBusinessConfiguration.java` |
| 行内宿主装配 | 示例改为统一工厂，宿主仅绑定资料数据源、事务和私有XML | [BankSourceBindings](../java-backend/host-integration/BankSourceBindings.java.example) |
| 查询契约 | 更新至V0.3，统一装配说明、SQL条数及测试边界 | [BANK_SOURCE_CONTRACT](../java-backend/host-integration/BANK_SOURCE_CONTRACT.md) |

接口链路为：调用方 → Java内部资料POST入口 → `BankSourceFacts`请求校验 → 只读MyBatis查询 → 字段映射、分页及关联校验 → 返回现有契约。Java业务服务也可直接调用同一`SourceFacts`实例。

## 2. 接口范围

统一入口为 `POST /api/plan/internal/source/{能力}/query`，使用已有 `X-Integration-Token` 服务认证。没有新增GET兼容入口。

| 能力 | 本轮验证范围 |
| --- | --- |
| `accounts` | 资格过滤、账号去重、稳定分页、更新时间半开边界、本页近三个月互动批量组装 |
| `topics` | 普通/热点来源、营销/非营销类型、有效时点、更新时间、ID查询 |
| `marketing-contents` | 账号范围、过审内容关联、过审先后顺序及分页 |
| `effective-marketing` | 指定账号及日期的营销推送记录查询 |
| `production-status` | 截图所覆盖营销流水的状态映射 |
| `marketing-status` | 营销批次的完成数、失败数、账号数及聚合状态 |
| `marketing-allocations` | 指定营销需求批次下的过审内容及绑定账号 |

`topic-usage`继续使用已有策划业务库查询，不属于这7项原始资料能力，本轮没有重写它的来源。

## 3. 行外与行内的使用方式

行外本地显式选择以下配置，原有数据库及内部令牌配置仍沿用启动流程：

```properties
planning.source.mode=sql
planning.source.mapper-location=file:/absolute/path/BankSourceMapper.xml
planning.source.storage-zone=Asia/Shanghai
```

该行外SQL模式用于源表位于开发业务库的联调，不能直接视为行内数据源装配。未设置mode时仍为fixture。本轮未切换或重启正在运行的三个服务。

行内按[宿主装配示例](../java-backend/host-integration/BankSourceBindings.java.example)传入资料库数据源及对应事务管理器，部署已复核的私有XML。不要同时加载同一namespace的占位XML和私有XML，也不要对这些Mapper重复扫描。数据权限、真实数据库隔离级别及连接权限仍由宿主落实。

## 4. 验证结果

| 验证 | 实测结果 | 说明 |
| --- | --- | --- |
| Java全量回归 | 157项：152通过、5跳过、0失败、0错误 | 新增装配器测试，检查账号分页与互动组装、缺文件和未填XML拒绝启动；包含已有业务回归 |
| MySQL私有SQL验收 | 5个测试方法全部通过，耗时3.227秒 | 覆盖上述7类POST入口及实际MyBatis SQL执行、参数绑定、分页、时间和状态映射 |
| 内部入口负例 | 无令牌返回401；page_size=501返回422 | 在MySQL接口验收内执行；不代表完整安全扫描已通过 |
| 持久源表核查 | 本地8张源表合计0行 | 本轮测试未向它们写入持久测试数据 |

MySQL验收使用8张会话临时源表。由于MySQL临时表不能在同一SELECT中被重复引用，账号代表行子查询使用一张内容完全相同的临时镜像表；仅测试内替换该表引用，交付私有XML不作此替换。连接关闭后全部临时表消失。未调用真实模型，没有真实模型质量或耗时验收结论。

公共测试可在Java工程根目录执行：

```bash
mvn test
mvn test -Dtest='BankSource*Test'
```

本轮实际使用离线Maven及隔离工程目录，排除只存在于本地的私有MySQL测试类后执行全量回归，再单独运行私有SQL验收。详细本地证据位于忽略目录`run/bank-source-schema/`：`java-regression-summary.json`、`mysql-acceptance-summary.json`及合成资料响应`sql-http-results.json`；这些文件不随公共仓库分发。公共仓库中的H2合成测试可以重复运行，MySQL截图SQL验收需要另行交付私有XML、联调DDL及测试程序。

## 5. 私有材料及数据库边界

根据截图整理的私有XML、8张本地联调表DDL、测试脚本和原始测试日志保留在`run/bank-source-schema/`，不上传GitHub。公共提交只包含通用接口、装配器、占位模板、合成测试和不含行内SQL的说明。

本次提交没有数据库升级脚本，不变更已有14张策划业务表或Python算法表。已按用户要求创建的本地8张源表属于行外模拟现有资料表，其字段类型仍为联调推定，不能替代行内权威DDL和索引评审。

## 6. 待行内核对

- 组织类型过滤值：截图中枚举不可辨认，私有XML尚未推断补入该过滤项。
- 生产状态：截图只覆盖营销，流水号映射槽位ID且版本固定为1；普通/热点、替换后版本及真实流水关联尚未由本轮验证。
- 营销进度：需求任务号与内容批次号须贯通；现存记录全部过审不一定等于目标数量全部完成。
- 有效营销投放：当前截图以过审推送时回填的日期为准，不能当作平台实际发布回执已接通。
- 算法输入：当前账号SQL未提供人设、兴趣爱好及表达风格来源；查询成功不代表完整画像输入齐备。
- 真实资料与规模：关联表一对多、跨页一致性、机构权限、真实字段类型与索引性能仍需驻场数据验收。

本轮结论为资料查询接入代码及隔离验收完成，不能扩展为全量内容生产业务或行内上线验收完成。
