# 多账号智能策划前端问题与验收清单

核查日期：2026-10-28。代码基线：`8891ea4`。完整字段、排序、按钮、跳转和提示说明见 [前端页面全量逻辑核查](前端页面全量逻辑核查_2026-10-28.md)。

本清单记录当前发现，尚未实施修复。**浏览器确认**表示已在现有页面复现；**代码确认**表示调用或状态处理可明确推导；**口径待确认**表示当前实现明确，但应先确定业务预期再改。

P1 为结果、规则或业务范围可能错误；P2 为流程、状态或反馈不完整；P3 为一致性和可维护性问题。优先级用于安排修复顺序，不表示本轮已经发生生产数据事故。

## P1 优先修复

### F-01 生命周期界面分组与实际计算模式可能不一致

证据：**浏览器确认、代码确认、独立计算复核**。[配置草稿复制](../frontend/src/views/ConfigView.vue#L15)仅复制名称、条件和兜底标记，丢弃 `condition_mode`；自动展开后，原来负责切换 grouped 模式的编辑按钮已被隐藏，新增条件或组也不会设置 grouped。后端 [matches_rule](../backend/app/ordinary_planning.py#L44)在 grouped 和 legacy 下采用不同运算次序。

例如界面表达 `A 或（B 且 C）`，实际 legacy 会从左至右计算成 `（A 或 B）且 C`。当 A 真、B 假、C 假时，grouped 为真、legacy 为假；本轮独立计算已确认差异，不涉及数据库写入。

同一字段遗漏还影响整页 JSON 差异判断：本机服务返回5个带 legacy 标识的规则，刚点编辑、未改任何字段，保存配置按钮已经可用。页面可能误判存在未保存修改，并影响远端配置同步及离开确认。

修复目标：保留已保存的判定模式，在显式分组编辑时正确转换并保存 grouped，不能通过简单改文字来修复。验收至少覆盖“一个组”“多个组”“已有旧模式”“读取后不改直接保存”，确保展示、保存、再次加载、后台计算一致。

### F-02 人工确认账号字段被全局脚本改写

证据：**浏览器确认**。[确认页模板](../frontend/src/views/ManualView.vue#L811)声明“账号名称、属主 UM 号、账号类型”，但 [manualConfirmEnhancer](../frontend/src/manualConfirmEnhancer.ts#L110)运行时将表头改成“账号昵称、账号ID、账号类型”，并替换第二列数据。实测第二列出现 `KOS-SH-009` 账号 ID，原属主 UM 号不再展示。

脚本还按 UM 号取第一个账号再反查，一名属主有多个账号时可能把第二列填成另一个账号 ID。

修复目标：由 Vue 模板统一控制确认列，移除覆盖该表的旧脚本逻辑，按稳定账号 ID 取数据。验收须包含同一 UM 下两个账号、同名账号、跨页账号及悬浮全文。

### F-03 历史总配置没有包含标签体系

证据：**浏览器和代码确认**。[历史详情](../frontend/src/views/ConfigView.vue#L608)只有经营配置、阶段条件、目标和窗口，没有标签；标签保存走独立接口和版本。浏览器历史详情内未找到选题标签。

影响：用户把“历史配置”理解为当前整个配置页的历史时，无法查看、比较或恢复当时的标签体系；只改标签可能不新增总配置历史。

修复目标：明确总配置是否包含标签。若包含，应把标签版本关联到统一快照，详情与恢复使用同一组合版本；若保持独立，应在产品入口和恢复范围上准确区分。验收要对只改标签、同时改规则与标签、恢复旧版本分别检查。

### F-04 一次保存配置可能部分成功

证据：**代码确认**。[saveAll](../frontend/src/views/ConfigView.vue#L380)先写经营配置，再写标签。第二个请求失败时，第一部分已保存且无回滚；界面主要显示保存失败，没有准确列出已生效部分。

修复目标：统一保存的生效边界；优先通过后端事务或统一提交保证一致，也可明确展示部分成功并提供恢复路径。验收模拟规则成功、标签失败，反向重试和版本冲突，不能让用户误以为所有修改均未生效。

### F-05 列表分页掩盖接口截断

证据：**代码确认**。[任务加载](../frontend/src/views/ManualView.vue#L304)分别调用普通和营销接口，不传 limit，两类后端均默认最近 20 条；页面再对合并数据分页。账号、选题目录上限 1000，参与账号和批次最多 5000，账号历史也最多 5000。

影响：任务第 21 条及更早同类历史无法通过当前分页找回；选题和账号超目录上限时，筛选及导入识别可能提示不存在，实际只是未加载；账号历史可能不完整而页面未说明。

修复目标：服务端分页、返回 total 和明确筛选条件；导入按 ID/UM 查询真实目录，历史按所选时间范围服务端查询。验收须超过每种上限，不能只测试 100 个账号、600 个选题。

### F-06 搜索后的周期列表与详情范围不一致

证据：**浏览器确认**。[时间列表](../frontend/src/views/ResultsHubView.vue#L113)先按批次搜索归组，但周期详情使用 `allPeriods` 中完整周期，失败接口也只传周期。

实测搜索 `DEMO-FAIL-20261026-18`，列表显示“1 个批次”，点击查看策划后，周期详情的批次表显示“2 个批次”。

修复目标：按此前“筛选后进入详情只看筛选结果”的口径，把批次范围传递到详情、统计、失败查询和导出；或明确提供全周期入口并区分名称。验收比较列表、详情指标、批次展开、失败记录与导出是否同范围。

### F-07 批次内容状态仅凭完成数推断

证据：**代码确认**。[ContentProgress](../frontend/src/components/ContentProgress.vue#L4)只有 completed 和 total，没有生产中、失败和待定题信息。

影响：已开始生产但完成数仍为 0 时显示待生成；全部生产失败且 0 完成时也显示待生成。与任务列表和单条策划显示不同，用户无法准确判断是否需要处理。

修复目标：进度仍保留完成生产账号数 / 总账号数，但状态使用明确的生产运行及失败事实。验收至少包含未启动、已启动0完成、部分完成、全部完成、全部失败、部分失败、0账号及热点待定题。

### F-08 历史策划卡片与详情可能取不同版本的选题

证据：**代码确认**。[openPlanDetails](../frontend/src/views/ResultsView.vue#L428)优先使用当前目录或单选题详情结果；[选题信息模板](../frontend/src/views/ResultsView.vue#L819)再优先显示该结果的标题、大纲和分类。父日历卡片则使用策划明细中的历史字段。

影响：目录更新后，历史卡片仍为原方案，点开可能显示新版标题大纲，无法分辨当时究竟采用哪版。接口读取失败还会退到旧字段，造成同一记录前后显示不同。

修复目标：策划详情主展示采用时的快照；如需当前选题资料，独立标识其版本或读取范围。验收使用已确定策划后再更新选题的样本，检查卡片、详情、导出和操作记录一致性。

## P2 流程与反馈完善

### F-09 返回账号列表丢失筛选和页码

证据：**浏览器确认**。账号列表条件保存在 [ResultsView](../frontend/src/views/ResultsView.vue#L50)组件本地，进入详情时组件被卸载。实测按 `DEMO-P-H` 查询、查看策划、返回后搜索框变为空。

验收目标：返回保留已应用筛选、输入、页码、每页数量及滚动位置；列表条件和详情条件分开存储。

### F-10 非营销确认页不显示投放日期

证据：**代码和浏览器结构确认**。[确认摘要](../frontend/src/views/ManualView.vue#L804)只有名称、类型和账号数，缺少这次非营销最关键的日期。

验收目标：确认页能再次核对具体投放日期和星期，回到上一步后仍保留，不改变营销无日期的口径。

### F-11 人工策划的错误可能被任务轮询清除

证据：**代码确认**。[loadTasks](../frontend/src/views/ManualView.vue#L304)成功就清空共用 error；轮询只看任务状态，不区分当前是否正在创建。

影响：填写新任务或提交失败时，正在运行的其它任务触发列表轮询，可让用户尚未读完的错误消失。列表查询失败也可覆盖当前表单错误。

验收目标：表单错误、列表错误、提交结果分开管理；影响用户决策的错误保持到明确纠正或关闭，不被后台刷新清除。

### F-12 新建策划无离开和重复提交恢复保护

证据：**代码确认**。[返回任务列表](../frontend/src/views/ManualView.vue#L668)直接切换 mode，未检查 dirty 或 busy；只有配置页提供路由离开保护。非营销提交每次重新建立预览，未提供丢失响应后的查单恢复。

验收目标：明确任务草稿丢弃方式，提交中阻止误离开；网络超时后能确认是否已建任务，再决定是否重试。营销现有 UUID 不应因普通重试无意变化。

### F-13 选题保存后筛选条件仍可修改

证据：**代码确认**。[选择选题](../frontend/src/views/ManualView.vue#L771)仅禁用选择框、删除和营销数量，未禁用筛选输入和查询。

验收目标：按已确认“保存后条件冻结”的口径统一冻结；返回调整再开放。保存后展示的选题、数量和筛选范围应可理解，不能让用户以为新查询已替换保存值。

### F-14 粉丝量空值和起止校验不完整

证据：**代码确认**。账号筛选只检查 `null`，而 Vue `.number` 输入清空可变为 `''`；截止值 `''` 在比较时会转为 0。两个账号筛选也未显式验证负数和起始大于截止，可能直接空列表。

验收目标：空字符串统一归 null，粉丝起止为非负值且起始不大于截止，错误在输入处显示；清空后确实恢复不限，保留未知粉丝与真实0的区别。

### F-15 API 校验明细和超时反馈缺失

证据：**浏览器模拟和代码确认**。[request](../frontend/src/api.ts#L63)只解析字符串 detail，结构化数组落为请求失败422；没有统一超时或取消请求。

实测模拟营销数量字段的 422 明细，页面仅展示“请求失败（422）”，用户无法得知哪个字段不合法。

验收目标：结构化错误映射字段和中文原因，超时明确提示；读取可重试，写操作结合幂等与查单，不能简单自动重试所有 POST。

### F-16 账号历史及中心列表缺少及时刷新

证据：**代码确认**。结果中心批次清单 `loaded` 后不再主动加载；账号详情的轮询判断 [productionItems](../frontend/src/views/PlanningDetailsView.vue#L73)来自 details，账号模式仅填 historyItems，因此不触发内容状态刷新。无批次待分配营销任务也不触发任务轮询。

验收目标：账号日历、周期列表、批次指标和营销分配状态按业务时机同步；避免要求增加用户已明确删除的刷新按钮，可以采用进入页面、恢复焦点和有条件后台更新。

### F-17 详情元信息失败被默认为缺失或不限

证据：**代码确认**。账号目录失败被静默忽略；计划的单选题详情查询失败不提示，只保留已有资料；模板把缺失有效期显示成不限。

影响：用户无法区分真实未设置、历史快照缺失和接口未读到；“不限”可能被误认为确认过的有效期事实。

验收目标：区分无值、读取失败和业务不限；失败不抹掉已知资料，必要时提供可理解的重试或说明。

### F-18 失败账号统计与导出单位不一致

证据：**代码确认**。[失败抽屉](../frontend/src/views/ResultsHubView.vue#L369)把记录条数显示为账号数；同账号多个批次可重复，批次级异常也占一条。导出不去重，并静默跳过无 UM 行。

验收目标：区分失败记录数、去重账号数、可导出 UM 数和无 UM 数；确认导出是每账号还是每失败批次。受批次搜索范围影响的记录应与 F-06 一起统一。

### F-19 三类详情的账号信息完整性不同

证据：**浏览器和代码确认**。单条抽屉只有策划、选题、操作记录三块；周期、批次父页有账号 ID、UM、组织、平台、人设，账号父页却只有名称及 ID。

验收目标：遵循不重复展示账号信息的已确认口径，同时保证从账号详情进入时仍有途径核对 UM、类型、组织及人设。所属组织到二级分行的显示需要行内来源映射，当前前端仅直接输出 organization 文本。

### F-20 多批次详情首次加载成本与分页无关

证据：**代码确认**。[详情 load](../frontend/src/views/PlanningDetailsView.vue#L235)对周期所有批次完整明细并行读取，再在前端分页账号；导出还会按每条记录另取调整历史。替换候选和内容流水无前端分页。

验收目标：大账号、大周期和长历史下有明确的服务端分页、懒加载或聚合接口；统计不因只加载一页而失真，单批失败不应无差别抹掉全部可读结果。

## P3 一致性与业务口径确认

### F-21 状态名及数据单位尚未完全统一

证据：**代码确认、口径待确认**。单条使用生产中、生产失败；任务和批次使用生成中、生成失败，任务还会显示部分失败及营销待分配。时间内批次表头为内容进度，显示却是状态；任务表当前没有用户较早要求的完成数、失败数。

确认目标：固定策划状态、批次内容状态和单条内容状态三套字典及数量单位；明确是否补回任务完成失败列。已有用户最终确定的名称优先，不自行统一成另一套术语。

### F-22 已生产但未发布是否可替换仍需确认

证据：**代码确认、口径待确认**。前后端明确阻止生产中和已发布，但 generated 且未发布并不自动阻止。

确认目标：确定内容已完成后替换是否作废旧内容、是否需再次生产、如何保留正式使用次数与操作记录。没有明确规则前，不只从前端隐藏按钮来代替链路约束。

### F-23 弹层反馈和键盘操作不一致

证据：**代码确认**。配置确认、选题详情和内容流水有焦点圈定；失败详情、配置版本、导出、计划详情未统一；替换模式只有关闭整抽屉，没有返回原详情按钮。标题有自定义气泡，大纲和部分字段仍用原生 title。

确认目标：逐类定义 Esc、遮罩关闭、提交中关闭、焦点恢复和背景滚动；普通查看、未保存编辑、异步提交分别处理。长期错误保持可读，是否增加普通成功 Toast 由交互规范决定，不能把所有提示强制自动消失。

### F-24 旧页面分支和 DOM 增强增加回归风险

证据：**代码确认**。AutoView 未挂载，ResultsView 仍含旧批次/账号历史分支，main.ts 运行旧确认增强与标题点击脚本，App.vue 也用观察器修改节点。当前 TagCascader 没有主页面调用。

验收目标：先梳理真实调用关系，将仍需要的展示归回 Vue 组件；经回归后再清理死代码。不能看到旧文件里的控件就误认为当前页面有该功能。

## 建议处理顺序

1. 先处理 F-01 和 F-02，解决判定逻辑可能错误及确认字段被改写。
2. 接着处理 F-03、F-04、F-06、F-08，明确配置、筛选范围及历史快照的完整性。
3. 再处理 F-05、F-07、F-16、F-20，保证大量数据查全、状态可信及更新及时。
4. 最后统一提示、输入校验、离开保护、导出计数及弹层交互；业务口径项先逐项确认。

## 逐页验收清单

下面各项是后续整改验收用例，未勾选不代表当前一定失败。当前已运行的只读检查见全量逻辑核查文档末尾。

### AI策划配置

- [ ] 默认只读，不可直接改值；数据库不可用时编辑禁用，并明确当前数据来源。
- [ ] 周策划日至少1天，星期顺序正确；时间、上限、占比及窗口合法值可保存，非法值有具体提示。
- [ ] 每个阶段流量加转化等于100%；冷启动边界和阶段优先级符合已确认口径。
- [ ] 组内且、组外或在显示、草稿、保存重读及后台判定一致；旧配置模式兼容。
- [ ] 最后条件不可误删，新增条件和组不隐式改变其它组。
- [ ] 标签新增、改名、停用、启用、重名、最后启用项限制及取消草稿一致。
- [ ] 恢复当前配置的标签与规则范围准确；历史快照完整可查，恢复范围准确。
- [ ] 保存部分请求失败、版本冲突、失联和标签版本变化时，不发生静默覆盖。
- [ ] 取消与离开确认重点在右侧继续编辑，刷新原生提示与站内确认区分。

### 人工策划

- [ ] 任务列表字段、名称+批次号、创建人、日期及分页正确，完整历史可查。
- [ ] 查看策划保留原文案并复用正式批次详情；未分配营销按当前任务详情展示。
