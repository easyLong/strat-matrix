## 2. 交互与数据去向

### 自动营销引用

1. Java从真实提案的转化位置及业务配置识别营销优先位置，保留普通选题作为回退。
2. Java资料层查询当日有效营销投放；没有时查询该账号过审内容，按真实审核时间先后选择。
3. 引用现成内容ID，直接更新Java业务明细为已完成，不重新调用内容生产。
4. 没有可引用内容时恢复普通选题，进入待生产。重复扫描不重复引用。

分支验收覆盖：有效投放优先、最早过审优先、无库存回退及幂等。

### 热点T-1

1. 每天由宿主触发，Java只查询北京时间明天的热点空槽；没有则结束，不查询热点资料。
2. 从同一Java资料入口获取可用热点，再按每条明细的投放日判断有效期。
3. 定题写入Java业务库，明细版本递增，状态由待定题变为待生产；缺合格热点时使用冻结普通兜底。
4. 内容方读取明细和版本后生产，Java读取结果更新状态。已定题明细不重复替换，此任务不扫描过去日期，也不限制22:00。

由于业务不指定具体投放时刻，有效期按北京时间投放日是否有有效区间判定。当前选择方式为稳定ID排序后按槽位种子打散，不是热度优先或V19热点精判。

原分支验收覆盖旧22:00前后、次日才生效的热点、过期排除、热点容量占用、普通兜底和重复执行；最新回归已改为每日明日检查，验证只有明天被处理、无空槽不查资料、跨北京时间日期及分页；另验证缺失兜底时事务回滚、保留未定题及明确错误。

### 人工营销

1. 页面提交一个选题和总生成数量，Java保存需求和选题快照；没有预选账号或投放日。
2. 内容侧自行生产、审核及分配账号；本轮通过模拟文件明确提供状态及过审分配事实。
3. Java读取需求进度；读取过审内容与账号资料，确认认证账号和有效参与资格。
4. Java按过审时间安排投放日，避让已有有效营销日期及已占用日期，遵守现有策划日与周上限；正式明细写业务库。
5. 同一内容不重复引用，同一需求不超过生成数量。

本轮新增`SourceFacts.approvedDemandContents`读取边界。outside实现读取`marketing_allocations`，内部查询路径为`marketing-allocations/query`；未实现的宿主方法明确返回未接入错误。该内部实现能力不擅自调整客户已确认的IF/OP编号。

### 内容生产状态与计数

模拟内容方明确提供明细标识、版本、状态、内容ID、生产任务ID及更新时间；Java只读取这些事实，不代替内容方生成或审核。

本轮验证：待生产→生产中→生产失败→重试生产中→已完成；旧版本不覆盖新明细，已完成结果不被后续旧状态回退。只有生产完成且有内容ID的正式明细计入使用次数，重复扫描不多计。

业务分支中普通、热点、兜底选题各使用1次，人工营销选题使用2次。V19混合批次中普通、热点各使用1次，营销引用所替代的普通候选及其他未使用候选均为0。

## 3. 修复的问题

| 问题 | 修复 |
| --- | --- |
| 人工营销过审分配始终为空 | 接入可替换的资料读取方法，获取内容和账号快照；未知账号、不符合资格或错误需求不伪造成功 |
| T-1按扫描当天过滤，漏掉次日才生效的热点 | 取消当天有效时点预过滤，按各投放日与有效区间判断，并处理时区 |
| 营销失败数不允许下降，重试成功也不能完成 | 完成数仍不能倒退；失败数按当前未恢复失败处理，允许更新事实中的失败数下降，保留时间顺序及总数校验 |
| 人工营销按时间字符串排序，混合时区可能先后颠倒 | 改为Instant比较，审核时间相同时按内容ID稳定排序 |
| 验收可误与日常调度并行 | 健康检查暴露本地调度启用状态；真实验收入口在调度未暂停时拒绝执行，默认回归显式关闭真实验收开关 |

## 4. 复核和重跑

只读复核不调用模型、不创建任务，也不要求暂停日常调度：

```bash

python -m testing.live_verify run/full-chain/20261103145435

```

需要创建新的验收数据时，先停止当前Java，以原私有配置加`--planning.local-pulse.enabled=false`启动Java，确认没有其他活动Pipeline或未完成营销需求，再在仓库根目录执行：

```bash
# 从正式业务边界开始：会创建测试资料与业务结果，不调用模型
python -m testing.content_live --execute

# 从基础资料和真实V19开始：会调用模型，写两个开发库
python -m testing.live --execute --scenario mixed
```

两种验收都使用日常Java资料入口，不另起资料服务器。测试资料和状态加入同一个模拟文件，保留独立前缀；并非物理隔离的测试库。程序不自动停止/恢复日常调度、不自动清理失败记录；结束后用原参数恢复Java，并核查健康状态。

混合验收选择能同时覆盖转化和热点的空闲未来周期，使用独立业务快照：周一/三/五、营销上限1、热点占比34%。没有保存页面配置、修改V19阈值、改写冻结输入或人工替换模型匹配结果。恢复未完成任务时不能变更原scenario。
