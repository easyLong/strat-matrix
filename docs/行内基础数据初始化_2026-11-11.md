## 本次脚本位置与顺序

当前数据包：`run/initialization-current-20261111/`。包含实际配置及历史，仅保存在本地忽略目录，需单独随行内交付材料移交。

1. 按已有DBA发布包完成Java业务表、Python算法表建表；两库分别执行。
2. 在空的算法配置表执行 `01-algorithm-foundation.sql`。
3. 在空的Java配置表执行 `02-business-foundation.sql`。
4. `03-system-config-portable.sql` 是可选系统配置子集，目标表必须为空；若已通过其它初始化流程写入配置，应先逐键比较并单独编制合并SQL，不能直接执行。
5. 分别在算法库、业务库运行 `04-algorithm-check.sql`、`05-business-check.sql`，核对条数及版本。`manifest.json`记录文件SHA256。

这些是首次导入脚本，不做存量覆盖。原ID和唯一键会阻止重复导入；遇错须停止并回滚当前事务，禁止客户端忽略错误继续提交。导出时暂停配置编辑，导入时暂停调度和配置写入；双库分别提交，失败后保持停写并按已完成的部分核查。

密钥、内网地址、环境模式及调度开关按行内环境设置，不复制本地值。账号、选题、营销内容及互动资料通过行内查询能力获取；画像、向量、标签计算结果和策划任务不属于这次基础配置初始化数据。

## 重新导出

使用项目Python3.10及已安装依赖，在 `python-backend` 目录执行：

```powershell
python -m tools.content_planning.export_foundation_data --output ../run/initialization-current-new
```

工具只读取当前 `.env` 所指的双库，输出目录必须为空；不会打印连接凭据，不连接模型，不改源库，不自动执行生成的SQL。实际数据包不提交Git。
