# Java 无视图查询改造

日期：2026-11-10。当前要求：行内不创建、不依赖数据库视图。

## 已完成范围

原先三个 SQL 投影定义移入 `PlanningQueryMapper.xml`，通过 MyBatis `<sql>` / `<include>` 展开为直接查询普通业务表的 SQL。没有创建替代视图、物化结果表、存储过程或新的服务接口。

| 原数据库对象 | 当前代码片段 | 来源 |
| --- | --- | --- |
| `godp_planning_item_read` | `PlanningQueryMapper.itemRows` | 正式明细关联正式批次，提取冻结快照字段 |
| `godp_planning_batch_read` | `PlanningQueryMapper.batchRows` | 正式批次及其快照字段 |
| `godp_planning_task_read` | `PlanningQueryMapper.taskRows` | 普通人工任务、营销任务、历史归档的 UNION ALL |

这些片段是应用内 SQL 文本复用，运行时作为查询的一部分提交给数据库。`PlanningQueryMapper` 的16个相关查询和 `SlotCompletionMapper` 的3个查询不再访问上述数据库对象。

保留原有账号／周期／批次范围、筛选、排序、数据库分页、去重统计、12类分布、失败查询和报表导出。热点T−1、营销待衔接、营销引用计数复用同一明细片段。

`del_flag='N'` 和 `write_state='ready'` 保留在公共定义中。分批写入期间的 staging 批次不可被页面、统计、导出和扫描读取；正式发布后才整体可见。任务列表仍能显示尚未生成正式结果的人工任务，关联批次按发布边界读取。
