## 1. 工程归属

本项目的功能最终整合进行内宿主系统。**Java接入代码直接写入行内已有Java工程，不在本仓库创建另一个Java工程，再要求宿主引用。**

| 交付内容 | 本仓库处理 | 最终落点 |
| --- | --- | --- |
| Vue三个业务页面及组件 | 开发、构建、验证 | 并入宿主前端，或按宿主方式挂载 |
| Python业务、数据适配、算法及自有库 | 开发、运行、验证 | 行内托管的Python FastAPI服务及策划库 |
| Java通配转发、身份与权限适配 | 提供路径、请求响应和接入说明 | 行内已有Java工程 |
| Java宿主Job唤醒调用 | 提供调用约定 | 行内已有调度／Java工程 |
| Java资料与生产状态查询 | 提供方法及字段参考 | 行内Java工程内补SQL及对象映射 |

功能整合不等于将Python当作Java依赖编译；Java与Python继续通过内网HTTP调用。Python具体部署与进程管理由宿主规范确定。

## 2. 本仓库目录与交接要求

- 不保留根目录 `java-access` 模块、`src/main/java`工程、Maven/Gradle构建或Java启动入口。
- Java参考集中到 [docs/integration/java-host](integration/java-host/README.md)，方法及字段模板使用 `.java.example` 后缀，不参与应用编译或运行。
- Python保留面向Java资料查询的适配端口；真实Java地址、鉴权、SQL与字段映射在驻场接入。
- 前端保留Java访问路径预留，不能将路径配置当作Java已经实现。
- 应用构建和常规后端验证不调用JDK。交接包将Java材料标注为宿主参考，不作为应用模块或运行依赖。
- 具体类名、包名、Spring/Servlet版本、HTTP客户端及Job接口跟随行内工程，不在行外提前绑定。

## 3. 沿用的架构决定

V0.1中的业务边界继续适用：Vue只访问Java；Python保留策划业务和算法；双库隔离；资料及生产状态经Java查询；内容侧经授权只读策划结果；宿主触发，Python持久化任务并受控执行。

统一唤醒、线程池生命周期、恢复、监控及完整营销衔接等尚未完成的能力继续按V0.1计划推进。本次只调整工程归属和交付组织，不改变业务规则、不改数据库、不重启服务。

## 4. 后续版本

V0.2是V0.1的增量修订，两份一起构成当前备忘；本节涉及的工程归属以V0.2为准。后续修订继续新增版本，并记录改变的决定和影响范围。
