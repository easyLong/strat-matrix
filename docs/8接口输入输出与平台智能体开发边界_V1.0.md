# 多账号智能策划 8 个正式接口：输入输出字段与平台/智能体开发边界

版本：V1.0
依据：`多账号智能策划_PRD_V1.1_近期口径同步稿.md` 第 8.2 节及项目当前 IF 本地契约、后端数据模型。
用途：需求澄清会、接口分工确认、后续技术接口文档的字段底稿。

> 本文把“平台侧”定义为客户已有的账号、选题、内容生产及选题使用计数系统；把“策划智能体侧”定义为本项目的策划服务、数据存储、标签识别、匹配和结果管理。接口 URL 与字段以当前本地实现为底稿，客户最终的调用方式、鉴权和网络协议仍需双方确认。

## 1. 八个接口及责任总览

本期正式接口为 IF-01、IF-02、IF-03、IF-04、IF-05、IF-06、IF-08、IF-09。IF-07 已取消，不应作为本期新增接口建设；新增账号由 IF-01 同步后在策划侧识别。

| 接口 | 数据方向 | 调用方 | 接口提供方 | 平台侧开发责任 | 策划智能体侧开发责任 |
| --- | --- | --- | --- | --- | --- |
| IF-01 账号及互动数据同步 | 平台账号系统 → 策划系统 | 平台账号同步任务 | 策划系统接收端 | 组织账号池和近三个月帖子互动数据，按约定方式发送；保证账号 ID、时间和来源版本稳定 | 接收入库、幂等与版本校验；计算有效内容数、滚动互动、趋势和生命周期，不要求平台预先计算这些派生值 |
| IF-02 普通选题同步 | 平台选题库 → 策划系统 | 平台选题同步任务 | 策划系统接收端 | 提供普通选题基础信息、可用状态和可排序热度 | 接收入库、状态和有效性校验；维护本地普通选题目录与后续标签/画像任务 |
| IF-03 营销选题同步 | 平台营销选题库 → 策划系统 | 平台营销同步任务 | 策划系统接收端 | 提供营销选题、绑定账号、审核和有效期事实 | 保存独立营销选题快照；校验账号绑定、审核和有效期，供营销槽位使用 |
| IF-04 热点选题同步 | 平台热点选题库 → 策划系统 | 平台热点同步任务 | 策划系统接收端 | 提供热点选题、有效期和可用状态，并在约定的 T-1 22:00 前完成同步 | 保存热点快照；按北京时间为已规划热点槽位绑定热点或执行普通选题兜底 |
| IF-05 策划结果查询 | 内容生产方 → 策划系统 | 平台内容生产方/内容 Agent | 策划系统查询端 | 按账号查询可生产结果；正式发布前重新查询最新版本 | 返回最新有效周期中已确定选题且未发布的结果；不因查询锁定结果或关闭替换 |
| IF-06 发布状态回传 | 平台内容生产方 → 策划系统 | 平台内容发布流程 | 策划系统回传端 | 发布状态变化后回传实际发布选题及结果版本 | 校验结果 ID、版本、选题类型和选题 ID；一致时落库为已发布并关闭替换 |
| IF-08 普通选题标签查询 | 选题方 ← 策划系统 | 平台选题方/选题库 | 策划系统查询端 | 按普通选题 ID 查询标签；自行处理处理中/完成/失败状态 | 返回已保存的 T1–T6 标签；标签识别由策划侧完成，查询不触发识别 |
| IF-09 正式使用次数查询 | 选题方 ← 策划系统 | 平台选题系统 | 策划系统查询端 | 提交类型及选题 ID 列表；正式使用次数的事实来源由平台业务确认 | 按已同步的独立计数快照返回计数；不根据策划、替换或发布回传自行推算次数 |

## 2. 共用传输约定

- 当前本地对接入口使用 `Content-Type: application/json` 和 `X-Integration-Token`。正式环境的令牌由双方安全渠道配置；不得把令牌写进请求体、前端代码或文档示例。
- 时间使用 ISO 8601，并带时区；业务周期按北京时间计算。
- IF-01/02 使用同步批次封装，支持 `mode=full` 与 `mode=incremental`。增量批次每次 1–500 条；全量快照最多 5000 条。全量空数组表示确认当前集合为空，增量空数组无效。
- 同一批次重试必须保证内容一致。相同批次 ID 内容不同、版本冲突或回传结果与当前版本不一致时，策划侧返回冲突，不静默覆盖。
- 下文“必填”以当前本地数据模型为准；“可选”字段可省略或使用所列默认值。PRD 核心字段与本地工程封装不一致之处在第 4 节单列。

## 3. 各接口输入与输出字段

### IF-01 账号基础信息、人设与互动数据同步

**方向：** 平台账号系统调用策划系统。
**当前入口：** `POST /api/integrations/accounts/sync`

| 输入字段 | 类型 | 必填 | 含义/责任 |
| --- | --- | --- | --- |
| `source_batch_id` | string | 是 | 平台生成的同步批次唯一标识。 |
| `mode` | `full` / `incremental` | 否 | 同步模式，默认 `incremental`。 |
| `snapshot_at` | datetime | 否 | 全量快照时间；必须带时区，省略时由服务端记录接收时间。 |
| `records[]` | AccountFact[] | 是 | 账号记录。增量 1–500 条；全量最多 5000 条。 |
| `records[].account_id` | string | 是 | 账号稳定唯一标识。 |
| `records[].account_name` | string | 是 | 账号名称。 |
| `records[].account_alias` | string | 否 | 运营搜索别名，默认空字符串。 |
| `records[].account_status` | boolean / null | 否 | 账号当前是否有效；有值时作为正式状态字段。 |
| `records[].certification_status` | boolean / null | 否 | 账号认证状态。 |
| `records[].account_persona` | string / null | 否 | 账号内容定位、人设与表达方向，最多 500 字符。 |
| `records[].is_marketing_account` | boolean / null | 否 | 是否营销账号；有值时优先于兼容字段。 |
| `records[].marketing_eligible` | boolean | 否 | 兼容旧字段，默认 false。 |
| `records[].account_tags[]` | string[] | 否 | 平台已有账号标签，作为画像辅助信息。 |
| `records[].follower_count` | integer / null | 否 | 当前粉丝数，不能小于 0。 |
| `records[].interaction_data[]` | object[] / null | 否 | 本次提供的完整近三个月帖子数据；显式 `[]` 表示确认无帖子，省略表示不覆盖已有独立历史数据。 |
| `interaction_data[].content_id` | string | 否 | 帖子 ID；用于去重，默认空字符串。 |
| `interaction_data[].published_at` | datetime | 是 | 帖子发布时间，必须带时区。 |
| `interaction_data[].title` | string | 否 | 帖子标题，默认空字符串。 |
| `interaction_data[].red_star_count` | integer | 否 | 红星数，默认 0。 |
| `interaction_data[].favorite_count` | integer | 否 | 收藏数，默认 0。 |
| `interaction_data[].comment_count` | integer | 否 | 评论数，默认 0。 |
| `records[].updated_at` | datetime | 是 | 账号来源记录更新时间，必须带时区，用于幂等和新旧版本判断。 |
| `platform`、`organization`、`city` | string | 否 | 平台、机构/分支、城市等兼容扩展字段。 |
| `persona`、`target_audience[]`、`interests[]` | string / string[] | 否 | 兼容旧账号人设、人群和兴趣字段。 |
| `family_identity`、`expression_style` | string | 否 | 兼容旧家庭身份、表达风格字段。 |
| `certified`、`followers`、`enabled` | boolean / integer | 否 | 兼容旧认证、粉丝量、启用字段；正式字段有值时优先使用正式字段。 |

**输出字段：** `source_batch_id`（同步批次）、`received`（接收条数）、`inserted`（新增条数）、`updated`（更新条数）、`unchanged`（内容未变条数）、`stale`（旧版本条数）、`deactivated`（全量快照中缺席并停用的条数）。

**开发边界：** 平台提供账号事实和帖子原始互动数；策划侧据此计算有效内容篇数、滚动互动、流量趋势、生命周期和画像。平台无需提供“流量趋势”“生命周期阶段”计算结果。

### IF-02 普通选题同步

**当前入口：** `POST /api/integrations/topics/sync`，共用 IF-01 的同步封装与响应字段。

| 输入字段 | 类型 | 必填 | 含义/责任 |
| --- | --- | --- | --- |
| `source_batch_id`、`mode`、`snapshot_at`、`records[]` | 同 IF-01 | `source_batch_id`、`records[]` 必填 | 同步批次封装。增量 1–500 条；全量最多 5000 条。 |
| `records[].topic_id` | string | 是 | 普通选题唯一 ID。 |
| `records[].title` | string | 是 | 选题标题。 |
| `records[].outline` | string | 否 | 内容大纲/核心内容，默认空字符串。 |
| `records[].content_type` | string | 否 | 内容类型，直接继承平台选题库。 |
| `records[].topic_heat` | number | 否 | 普通选题热度排序值，默认 0。 |
| `records[].status` | boolean / null | 否 | 正式可用状态；非空时优先于 `enabled`。 |
| `records[].enabled` | boolean | 否 | 兼容可用状态字段，默认 true。 |
| `records[].updated_at` | datetime | 是 | 来源记录更新时间，必须带时区。 |
| `summary`、`source`、`category` | string | 否 | 摘要、来源、分类扩展字段。 |
| `applicable_cities[]` | string[] | 否 | 适用城市。 |
| `is_marketing` | boolean | 否 | 类型兼容字段，默认 false；IF-02 全量快照禁止包含营销选题。 |
| `product_or_activity` | string | 否 | 关联产品/活动信息。 |
| `generated_at`、`approved_at`、`valid_from`、`valid_to` | datetime / null | 否 | 来源生成、审核和有效期信息；提供时必须带时区。 |

**开发边界：** 平台提供普通选题事实和热度；策划侧维护本地目录、标签/画像准备状态、候选资格和策划使用记录。T1 标签中的营销语义不会把普通选题改成营销来源类型。

### IF-03 营销选题同步

**当前入口：** `POST /api/integrations/marketing-topics/sync`。每次请求是营销选题全量快照。

| 输入字段 | 类型 | 必填 | 含义/责任 |

| `snapshot_at` | datetime | 是 | 快照时间，必须带时区且晚于上次成功快照。 |
| `records[]` | MarketingTopicFact[] | 是 | 完整集合，最多 5000 条；空数组表示有效空快照。 |
| `records[].topic_id` | string | 是 | 营销选题唯一 ID。 |
| `records[].account_id` | string | 是 | 绑定的营销账号 ID。 |
| `records[].title` | string | 是 | 选题标题。 |
| `records[].outline` | string | 否 | 内容大纲，默认空字符串。 |
| `records[].content_type` | string | 否 | 内容类型。 |
| `records[].approval_status` | `pending` / `approved` / `rejected` | 是 | 审核状态。 |

**输出字段：** `source_batch_id`、`snapshot_at`、`received`、`inserted`、`updated`、`unchanged`、`deactivated`。

**开发边界：** 平台负责选题和审核事实；策划侧检查营销账号资格、绑定账号、审核通过状态和有效期，按规则使用或普通选题兜底。该接口不更新普通选题目录。

### IF-05 按账号查询当前可生产策划结果

**当前入口：** `GET /api/integrations/accounts/{account_id}/current-plan`。

| 输入字段 | 位置 | 必填 | 含义/责任 |
| --- | --- | --- | --- |
| `account_id` | Path | 是 | 平台内容生产方要获取结果的账号 ID。 |
| `X-Integration-Token` | Header | 是 | 服务间认证信息。 |

**成功响应字段：**

| 输出字段 | 类型 | 含义 |
| --- | --- | --- |
| `account_id` | string | 请求对应的账号 ID。 |
| `planning_cycle` | object / null | 返回结果所属周期；无可生产结果时为 null。 |
| `planning_cycle.start`、`planning_cycle.end` | date | 周期开始和结束日期。 |
| `planning_contents[]` | object[] | 本周期可生产结果；无结果时为空数组。 |
| `planning_contents[].planning_result_id` | integer | 策划结果 ID，供 IF-06 回传引用。 |
| `planning_contents[].slot_id` | string | 稳定槽位 ID。 |
| `planning_contents[].result_version` | integer | 当前策划结果版本，供发布回传校验。 |
| `planning_contents[].publish_date` | date | 计划投放日期。 |
| `planning_contents[].topic_id` | string | 当前确定的选题 ID。 |
| `planning_contents[].topic_type` | `普通` / `营销` / `热点` | 当前实际绑定选题的来源类型。 |
| `planning_contents[].title` | string | 选题标题。 |
| `planning_contents[].outline` | string | 内容大纲。 |
| `planning_contents[].content_type` | string | 内容类型。 |
| `planning_contents[].publish_status` | string | 当前发布状态，本期为“未发布”。 |

**开发边界：** 平台内容生产方负责调用、生产内容，并在发布前再次查询确认最新版本；策划侧按账号返回当前周优先、否则最近未来周期的有效未发布结果。查询不锁定结果。热点待确定槽位不返回。

### IF-06 发布状态回传

**当前入口：** `POST /api/integrations/publication-status`。

| 输入字段 | 类型 | 必填 | 含义/责任 |
| --- | --- | --- | --- |
| `event_id` | string | 是 | 平台生成的回传事件 ID，用于幂等重试。 |
| `planning_result_id` | integer | 是 | 引用 IF-05 返回的策划结果 ID。 |
| `result_version` | integer | 是 | 发布所基于的结果版本，必须与当前版本一致。 |
| `topic_id` | string | 是 | 平台实际发布的选题 ID。 |
| `topic_type` | `普通` / `营销` / `热点` | 是 | 平台实际发布选题类型。 |
| `publish_status` | `未发布` / `已发布` | 是 | 发布状态；已发布为终态，不允许回退。 |
| `occurred_at` | datetime | 是 | 状态发生时间，必须带时区。 |
| `content_id` | string / null | 否 | 平台内容 ID。 |
| `X-Integration-Token` | Header | 是 | 服务间认证信息。 |

**成功响应字段（当前实现）：** `accepted`（是否接收）、`applied`（是否实际更新）、`reason`（`applied` / `already_current` / `duplicate_event`）、`current_publish_status`（策划侧当前发布状态）。版本或选题不一致时返回 HTTP 409，响应含 `accepted=false`、`applied=false`、`reason=result_mismatch` 和 `current_publish_status`。

**开发边界：** 平台发布流程是“实际是否发布”的事实来源，并负责回传实际选题；策划侧校验结果 ID、版本、选题 ID 和类型，一致时将结果更新为已发布并关闭替换。IF-06 不承载开始生产、生成中或生成失败等生产进度。

### IF-08 普通选题标签查询

**当前入口：** `GET /api/integrations/topics/{topic_id}/labels`。

| 输入字段 | 位置 | 必填 | 含义 |
| --- | --- | --- | --- |
| `topic_id` | Path | 是 | 要查询标签的普通选题 ID。营销、热点和演示选题不在本接口范围。 |
| `X-Integration-Token` | Header | 是 | 服务间认证信息。 |

**输出字段：** `topic_id`（选题 ID）、`label_status`（`处理中` / `已完成` / `失败`）、`labels`（标签对象）。`labels` 在已完成时包含 `t1`、`t2`、`t3`、`t4`、`t5`、`t6` 六个单选字符串；处理中或失败时为空对象 `{}`。

**开发边界：** 策划侧生成、保存并版本化标签，查询只读且不触发模型；平台选题方负责按需请求并按 `label_status` 展示/处理结果。内部标签识别状态与本接口对外三态映射由策划侧负责。

### IF-09 选题正式使用次数查询

**当前入口：** `POST /api/integrations/topics/official-usage/query`。

| 输入字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `topic_type` | `普通` / `营销` / `热点` | 是 | 单次请求只允许一种类型，用于区分选题 ID 命名空间。 |
| `topic_ids[]` | string[] | 是 | 该类型下的选题 ID，1–500 个，不得重复或为空。 |
| `X-Integration-Token` | Header | 是 | 服务间认证信息。 |

**输出字段：** `topic_type`（本次查询类型）、`items[]`（逐选题结果）、`items[].topic_id`（选题 ID）、`items[].official_use_count`（当前正式使用次数，非负整数）。返回顺序与输入 ID 顺序一致。缺少某选题计数快照时返回 503，不把“未知”伪装成 0。

**开发边界：** 策划侧只提供查询和快照读取。正式使用次数由独立业务逻辑维护，不能由策划次数、IF-05 查询、人工替换或 IF-06 发布回传自行计算。平台侧需确认计数的事实来源、刷新频率及谁负责把计数快照提供给策划侧。

## 4. 需求澄清会需要确认的接口分工

1. **IF-01～IF-04 的传输方向：** PRD 描述的是平台数据进入策划系统；当前本地实现是平台向策划侧 `POST` 同步。若客户只提供可供调用的查询 API，则客户实现数据提供端、策划侧实现拉取客户端，字段语义不变但传输方式和鉴权方式需要重定。
2. **IF-01 的请求口径：** PRD 将核心业务请求字段标为“无”，当前本地实现则需要 `source_batch_id`、同步模式、记录集合及来源更新时间。需确认由谁生成批次 ID、采用全量还是增量，以及账号池分页完成标志如何表达。
3. **IF-03 审核字段：** PRD 字段表写 `audit_status`，当前契约使用 `approval_status`。确定正式字段名及审核枚举映射；不要让两套名称同时成为必填字段。
4. **IF-05 的 `slot_id`、`result_version`、`publish_status`：** 当前响应已包含这些字段，PRD 逐条核心字段表只列出部分。需确认生产方是否以 `planning_result_id + result_version` 回传，还是将稳定 `slot_id` 作为主关联键。
5. **IF-06 响应口径：** PRD 核心返回为 `current_publish_status`；当前实现另返回 `accepted`、`applied`、`reason` 并在冲突时用 HTTP 409。客户按业务状态还是技术处理结果判断成功需要统一。
6. **IF-09 计数提供方：** IF-09 是查询接口，但策划侧必须先拿到独立使用次数快照。明确事实系统、快照推送/拉取方式、修订号和未知值处理。
7. **服务身份与鉴权：** 谁签发/轮换平台到策划系统、策划系统到平台的凭证；内容生产方、账号/选题方是否使用不同服务身份。

## 5. 明确排除项

- **IF-07：** 不建设新账号变化通知接口；改由 IF-01 夜间同步后由策划侧识别新增账号。
- **历史运营数据独立同步：** 当前代码有本地历史内容同步入口，但不属于 PRD 本期八个正式接口；如客户需要该接口，另行确认用途、来源和字段，不能直接把内部落库模型当成客户契约。
- **内容生产进度回传：** 当前代码的 `content-status` 属于既有工程入口，PRD 本期不要求策划侧维护生产中/生成完成/生成失败状态；不应作为 IF-06 的字段扩展。
- **选题正式计数写入：** `PUT /api/internal/topic-official-usage` 是项目内部计数快照导入入口，不是 IF-09。外部正式接口 IF-09 只查询。
- **T1–T6 标签识别、账号/选题画像、向量生成、召回和分配：** 属于策划智能体侧内部能力，不是平台需要逐个调用的新增接口。
