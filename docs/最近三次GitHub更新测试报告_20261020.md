## 发现的问题

### 1. 营销选题可能在到期后投放：业务缺陷

复现使用真实 `load_marketing` 和 `build_final_plan` 函数，数据源通过测试替身提供：

- 策划时间：2026-10-20。
- 选题有效截止：2026-10-21 00:00 UTC。
- 目标周期：2026-10-26 至 2026-11-01。
- 实际组合结果：该营销选题被安排到 2026-10-28。

原因：`weekly_planning.load_marketing` 按当前时间生成 `valid`，同时没有将有效期保留到组合输入；`planning_result_commit.build_final_plan` 直接使用这个有效标记，没有按目标投放日期重新校验。

影响：提交当天有效、执行前到期的营销选题仍可能进入正式策划。现有 132 项自动测试没有覆盖该场景；本轮额外场景检查发现并记录了它。

建议在正式提交前按目标投放日期校验有效期。日期只有日粒度时，需要明确截止日包含关系和业务时区；不满足有效期的营销选题应沿用既定普通选题兜底规则。普通选题未来投放日期的有效性也应同时补查，本轮未复现其完整路径。

### 2. 当前数据库缺少新增迁移：运行阻断

只读查询确认缺少：

- `godp_planning_pipeline_run`。
- `godp_planning_stage_run`。
- `godp_matching_task.production_batch_id`。
- `godp_matching_task.operations_committed_at`。

真实服务检查：

| 请求 | 结果 |
| --- | --- |
| 前端 `/` | HTTP 200 |
| 后端 `/api/health` | HTTP 200，`service=ok`、`database=ok` |
| 未带令牌 GET `/api/internal/planning-pipelines` | HTTP 401 |
| 使用当前配置令牌 GET `/api/internal/planning-pipelines` | HTTP 503，数据库暂不可用 |

仓库已有迁移入口：`python -m app.init_pipeline_db` 和 `python -m app.init_result_commit_db`。应在应用相应迁移后，重新验证新增接口；本轮只测试，未对现有数据库执行 DDL。

健康检查目前主要检查既有表，未包含新增流水线表和正式提交字段，因此其返回 `database=ok` 不能证明新增模块可用。

### 3. 没有已批准匹配策略：业务启用前提缺失

当前 `godp_matching_policy` 中已批准策略数为 0。即使安装数据库迁移，真实向量空间及策略尚未确认时仍无法按正式契约运行新匹配链路。需要配置并人工批准与实际账号、选题向量空间一致的策略，再显式启用执行器和发起 Pipeline。
