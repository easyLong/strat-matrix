## 执行方式

在仓库 `backend/` 目录，使用已安装项目依赖的 Python：

```bash
python -m app.refresh_auto_demo
```

默认使用实际的 Asia/Shanghai 时间。复现本次时间场景可显式传入带时区的截止时间：

```bash
python -m app.refresh_auto_demo --as-of "2026-10-13T09:00:00+08:00"
```

脚本根据当前配置生成本周展示布局；热点比例、营销上限、投放星期和调度时间均读取已有策划配置。它不运行调度服务；后续展示进度需再次运行该脚本。正式自动策划仍由独立调度与执行链产生。

## 数据范围与备份

- 仅处理已存在的 `DEMO-` 自动策划批次，以及本周的展示批次；不更新正式批次、客户来源事实、手动策划任务或正式使用次数。
- 保留已有批次和条目 ID；只为缺少的日期补条目。
- 所有修改在同一数据库事务中提交，执行前将受影响的批次、条目、槽位及旧运行记录备份至仓库 `logs/auto-demo-before-*.json`。该目录不提交 Git。
- 原来普通兜底运行的输入快照不改写；对应演示运行记录软归档，避免把刷新后的布局解释为原来的算法产出。
- 若涉及正式引用、客户回执、本周人工调整或已尝试投递的本周事件，脚本拒绝更新。仅本周未投递且未尝试投递的展示事件可随备份软归档。
- 历史发布时间样例不会冒充客户真实发布状态；槽位只按“选题已确定 / 待热点确定”保存。

## 页面行为

当前批次优先选取本自然周，之后才是未来最近周期或最近历史周期。下周调度使用 Asia/Shanghai 计算：时间到达后若尚无批次，显示“等待策划结果”，不会在页面自行创建“已规划”记录。

页面每 10 秒刷新状态与批次；即使所有已存在批次都已完成，也会继续检查新结果。
