# UI 设计规范｜后台产品通用版 V1.0

> 适用范围：后台管理系统、运营平台、数据平台、策略配置平台、内容策划平台等 B 端 Web 产品。  
> 来源说明：本规范基于已提供的 UI 设计规范总图进行分区放大读取与整理。原图能够支持页面结构、组件类别、状态语义、使用原则等规则；但**无法可靠识别精确字号 px、间距 px、圆角 px、色值 HEX 等细粒度数值**，因此本文件不对这些数值做未经来源支持的补写。  
> 使用建议：后续原型、HTML、PRD、设计稿、开发验收，统一以本文件作为基础 UI 规范；若后续拿到原始 Figma / PDF / 高清规范页，可继续补齐 Design Token 数值。

---

## 0. 总体设计原则

### 0.1 视觉原则

1. **蓝色仅用于主操作、当前选中、重要交互反馈**，避免页面中大面积无语义使用蓝色。
2. **绿色 / 黄橙 / 红色必须固定承担成功 / 提醒 / 错误或危险语义**，不得在不同页面中随意更换含义。
3. **同类组件统一高度、间距、圆角、状态表现和对齐方式**。
4. 页面层级优先通过**网格、留白、字号、字重**建立，不依赖大量边框与装饰。
5. B 端后台产品以**表格、表单、筛选、状态、分页、反馈**为主要信息载体，结构稳定优先于视觉炫技。
6. 复杂说明默认不直接铺满主页面；根据重要程度使用 **Tooltip / Alert / Drawer / Modal** 逐级展开。
7. 所有可交互组件至少覆盖：**Normal / Hover / Focus 或 Active / Disabled / Error / Loading** 等状态。
8. 同一业务语义在整个产品中保持一致，包括：颜色、Tag、按钮样式、文案、图标和交互方式。

### 0.2 信息展示原则

- 页面只直接展示用户完成当前任务所需的信息。
- 技术字段、中间计算过程、内部算法参数默认隐藏。
- 解释性信息优先采用 Tooltip、说明气泡、抽屉或帮助入口。
- 高优先级状态必须能在 1~2 秒内被扫描识别。
- 复杂页面必须建立“页面 → 模块 → 区块 → 字段”的清晰层级。

# 01. 全局样式 Global Style

## 1.1 Layout 布局

### 规则

- 页面采用规则化栅格布局。
- 内容区左右边缘保持统一对齐。
- 同级模块的卡片、表单、表格应共享相同的起始线和结束线。
- 宽屏后台优先利用横向空间，不建议把所有内容无限拉成长单列。
- 模块之间必须存在明确分区，但避免为了分区大量加粗边框。
- 页面主内容区应形成稳定的阅读路径：**页面标题 → 筛选/操作 → 主体内容 → 分页/结果**。

### 推荐使用场景

- 左侧导航 + 右侧内容区
- 顶部导航 + 内容区
- 单栏表单页
- 左右双栏详情页
- KPI + 表格的数据页

---

## 1.2 Spacing 间距

### 规则

- 间距使用统一的间距体系，不允许页面中任意取值。
- 页面级间距 > 模块级间距 > 组件内部间距。
- 同级内容间保持相同距离。
- 不通过多个空行制造视觉层级。
- 表单 Label、输入框、帮助文案、错误提示之间间距保持稳定。
- 卡片之间、卡片内模块之间必须能够通过留白区分层级。

### 层级关系

- 页面外边距：最大
- 模块/卡片间距：中等
- 字段/控件间距：较小
- 图标与文字内部间距：最小

> 注：原图无法可靠识别具体 px 数值，暂不固化数值。

---

## 1.3 Alignment 对齐

### 规则

- 同类信息共享同一视觉基准线。
- 表单 Label 的宽度保持一致。
- 输入框、单位、帮助说明保持统一对齐。
- 表格数值列采用统一对齐方式。
- 金额、比例、数量、日期等数值型字段应优先保证可扫读性。
- 多列布局中，同一行组件高度一致。
- 不允许同一列表中因文字长短导致操作按钮位置漂移。

---

## 1.4 Typography 字体

### 信息层级

字体至少区分：

1. 页面标题
2. 模块标题
3. 重要数据 / KPI
4. 正文
5. 辅助说明
6. 次级信息 / Placeholder / 禁用信息

### 规则

- 页面标题 > 模块标题 > 正文 > 辅助说明。
- 正文不大面积使用粗体。
- 重点信息通过字重 + 色彩 + 空间共同强化。
- 数字/KPI 可以比正文更突出，但不要与页面标题竞争。
- 辅助文案必须降低视觉权重。
- 同级文本字号、字重保持一致。

> 注：精确字号、行高和字体族无法从原图稳定识别，暂不指定。

---

## 1.5 Color 颜色

### 颜色语义

| 颜色语义 | 使用场景 |
|---|---|
| 主色蓝 | 主按钮、当前选中、主链接、Focus 状态、核心操作 |
| 成功绿 | 成功、正常、完成、通过 |
| 警告黄/橙 | 风险、提醒、待处理、需要注意 |
| 错误红 | 错误、失败、删除、危险操作 |
| 中性灰 | 正文次级、边框、禁用、背景、占位信息 |

### 规则

- 不使用颜色作为纯装饰。
- 同一颜色在全产品中对应同一语义。
- 状态信息不能只靠颜色表达，应同时配合文字 / 图标 / Tag。
- 禁用态统一降低对比度。

> 注：原图不能可靠还原具体 HEX 色值。

---

## 1.6 Media 图片 / 媒体

### 规则

- 图片放置于固定比例容器中。
- 素材尺寸不应破坏页面布局。
- 图片加载失败时显示统一占位状态。
- 封面、头像、缩略图分别使用独立规范。
- 图片列表应统一宽高或固定比例。
- 不允许图片自然尺寸导致列表行高不一致。

---

## 1.7 Shadow 阴影

### 规则

- 普通卡片尽量弱阴影或无阴影。
- Dropdown / Popover / Modal / Drawer 等浮层必须与背景建立明显层级。
- 阴影只用于表达 Z 轴层级，不用于装饰。
- 页面中避免多种阴影强度混杂。

---

## 1.8 Button 按钮

### 按钮类型

- Primary 主按钮
- Secondary 次按钮
- Text / Link 文字按钮
- Danger 危险按钮
- Disabled 禁用按钮

### 规则

- 一个操作区域原则上只突出一个主操作。
- 主操作使用主色。
- 次操作弱化视觉权重。
- 删除、清空、覆盖等危险动作使用危险色。
- 禁用态必须明显不可操作。
- 同一页面同类按钮高度一致。
- 图标按钮必须有 Tooltip 或可理解的图标语义。

### 必备状态

- Normal
- Hover
- Active / Pressed
- Loading
- Disabled

---

# 02. 导航 Navigation

## 2.1 Navigation 一级导航 / 侧栏导航

### 规则

- 一级导航负责表达“当前在哪个系统模块”。
- 左侧导航支持展开 / 收起。
- 当前菜单必须有明确高亮。
- 父子菜单通过缩进或展开图标体现层级。
- 收起后保留图标识别能力。
- 一级导航不用于页面内部的轻量切换。

---

## 2.2 Tabs 页签

### 适用场景

- 同一页面任务下的多个视图
- 同一对象的不同信息维度
- 同级数据切换

### 规则

- Tab 不替代一级导航。
- 当前 Tab 使用主题色与下划线 / 背景高亮。
- 未选中 Tab 保持低视觉权重。
- Tab 数量过多时应考虑下拉、折叠或二级导航。
- 切换 Tab 不应造成上下文丢失。

---

## 2.3 Page Title 页面标题

### 推荐结构

- 左侧：页面名称 / 对象名称
- 中间或下方：说明、状态、Tab
- 右侧：主操作 / 次操作

### 规则

- 页面标题固定出现在内容区顶部。
- 页面标题和操作按钮保持同一水平层级。
- 页面标题下可放二级说明或 Tab。
- 避免标题、操作、筛选分散到页面不同位置。

---

## 2.4 Pagination 分页

### 规则

- 长列表统一分页。
- 当前页突出显示。
- 页数过多时中间页使用省略。
- 提供上一页 / 下一页。
- 需要时支持每页条数选择和跳页。
- 分页通常放在表格底部右侧。
- 切页后保持筛选条件。

---

# 03. 数据输入 Data Input

## 3.1 Input 输入框

### 类型

- 单行文本
- 搜索输入
- 密码输入
- 数字输入
- 带单位输入
- Textarea
- 前缀 / 后缀图标输入

### 状态

- Normal
- Hover
- Focus
- Filled
- Error
- Disabled

### 规则

- Placeholder 使用弱灰色。
- Focus 使用主题色边框。
- Error 使用红色边框，并就近显示错误原因。
- Disabled 使用灰色背景并禁止输入。
- 搜索、清空等图标位置保持统一。
- 单位应放在输入值之外，不混入用户输入内容。

---

## 3.2 Select 下拉选择

### 类型

- 单选
- 多选
- 可搜索
- 分组选项
- 带勾选的多选

### 规则

- Hover 项有背景反馈。
- Selected 项有主题色反馈。
- 多选必须明确展示已选择状态。
- 大数据量支持搜索。
- 下拉列表超出视口时滚动。
- 选中值必须可回显。

---

## 3.3 Cascader 级联选择

### 规则

- 多级菜单横向展开。
- 当前层级高亮。
- 有子级的选项显示层级箭头。
- 已选路径可回显。
- 长级联路径应支持搜索或快速定位。

---

## 3.4 Number Input 数值输入

### 规则

- 明确最小值、最大值、步长和单位。
- 加减步进按钮与输入框形成一个整体。
- 超出范围时必须提示。
- 比例、金额、数量等数值类型禁止模糊单位。

---

## 3.5 Switch 开关

### 规则

- 仅表达两个互斥状态。
- 开启使用主题色。
- 关闭使用中性灰。
- 禁用态降低透明度。
- 多选场景禁止使用 Switch。

---

## 3.6 Radio / Checkbox

### Radio 单选

- 用于互斥选择。
- 同一组只能选择一个。

### Checkbox 多选

- 用于多个独立选项。
- 支持全选 / 半选状态时必须准确表达。

### 通用规则

- Selected / Unselected / Disabled 状态清晰。
- 不允许两个控件视觉混淆。

---

## 3.7 Date Picker 日期选择

### 类型

- 单日
- 日期范围
- 月份
- 年份
- 多日期 / 多面板

### 规则

- 使用统一日历弹层。
- 当前日期、选中日期、范围日期状态必须区分。
- 不可选日期显示 Disabled。
- 日期格式全产品统一。
- 范围选择明确起点、终点与区间。

---

## 3.8 Time Picker 时间选择

### 规则

- 时 / 分 / 秒按列选择。
- 当前值高亮。
- 支持确认与取消。
- 时间格式全产品统一。
- 不允许同一系统同时出现多种时间格式。

---

## 3.9 Transfer 穿梭框

### 结构

- 左侧：待选
- 中间：转移操作
- 右侧：已选

### 规则

- 两边均显示数量。
- 支持搜索。
- 大数据量支持分页或滚动。
- 已选项不能在待选区继续被重复选择。

---

## 3.10 Tree / Tree Select 树形选择

### 规则

- 父子关系通过缩进 / 箭头表达。
- 支持展开 / 收起。
- 父子选中关系清晰。
- 多级树禁止无限展开导致页面过长。

---

## 3.11 Form 表单

### 布局

- 横向表单
- 纵向表单
- 多列表单
- 分组长表单

### 规则

- Label 宽度统一。
- 必填标识统一。
- 输入框高度统一。
- 错误提示紧贴字段。
- 长表单按业务分组。
- 操作按钮统一放在表单底部。
- 同一表单内不要混用过多布局风格。

---

# 04. 数据展示 Data Display

## 4.1 Avatar 头像

### 规则

- 用户 / 账号统一使用固定尺寸头像。
- 无头像时提供默认占位。
- 不同尺寸只服务明确的信息层级。
- 列表中头像尺寸保持一致。

---

## 4.2 Badge 徽标 / 角标

### 规则

- 用于未读、新增、异常等轻提示。
- 数字角标与对象绑定。
- 不单独漂浮使用。
- 数量过大可采用上限显示方式。

---

## 4.3 Carousel 轮播

### 规则

- 适合少量重点展示内容。
- 当前页有明确指示。
- 不用于核心业务操作流程。
- 不建议自动高速轮播。

---

## 4.4 Table 表格

### 表格结构

- 表头
- 数据行
- 状态列
- 操作列
- 分页
- 可选筛选 / 排序 / 固定列

### 规则

- 表头与正文层级明确。
- 同一列保持统一对齐。
- 状态优先用 Tag / 图标辅助。
- 操作列通常放右侧。
- 高频操作可直接显示，低频操作放“更多”。
- 长文本需要省略 + Tooltip / 展开。
- 空数据必须有 Empty 状态。
- 大列表必须配合分页。
- 表格不应塞入过多复杂表单控件。

---

## 4.5 Statistics / Charts 数据统计与图表

### KPI

- 优先展示核心数值。
- 包含值、单位、变化或状态。
- 同一行 KPI 结构一致。

### 图表选择

| 图表 | 适用场景 |
|---|---|
| 折线图 | 时间趋势 |
| 柱状图 | 类目对比 |
| 饼图 / 环图 | 构成占比 |
| 进度 / 仪表 | 完成度、状态 |

### 规则

- 图表服务数据问题，不为装饰。
- 图例、颜色语义统一。
- 图表与 KPI 不重复表达同一信息。

---

## 4.6 Tooltip 文字提示

### 规则

- 用于解释图标、缩写、复杂字段、被截断文本。
- Hover 触发。
- 内容尽量简短。
- 不在 Tooltip 中放复杂表单或多步骤操作。

---

## 4.7 Tag 标签

### 用途

- 状态
- 分类
- 属性
- 轻量筛选标识

### 规则

- 颜色语义稳定。
- 同一状态在不同页面使用同一颜色和文案。
- Tag 不承担主操作。
- 避免一个页面出现过多颜色 Tag。

---

## 4.8 Empty 空状态

### 使用场景

- 首次进入
- 无数据
- 搜索无结果
- 筛选无匹配

### 规则

- 不出现纯空白区域。
- 空状态包含：图形/图标 + 文案 + 可选下一步操作。
- 搜索无结果应提示调整筛选条件。

---

## 4.9 Loading 加载

### 类型

- 局部 Loading
- 表格 Loading
- 按钮 Loading
- 页面遮罩 Loading

### 规则

- 小范围请求使用局部 Loading。
- 仅全页面任务才使用遮罩。
- 加载时禁止重复提交。
- 页面结构尽量保持稳定，避免跳动。

---

# 05. 数据反馈 Data Feedback

## 5.1 Alert 页面提示

### 类型

- Info
- Success
- Warning
- Error

### 规则

- 用于页面内较长期存在的重要说明。
- 允许标题 + 描述 + 关闭操作。
- 颜色遵循统一语义。
- 不用于短时“保存成功”类反馈。

---

## 5.2 Message 全局短提示

### 适用场景

- 保存成功
- 操作成功
- 操作失败
- 简单提醒

### 规则

- 短时自动消失。
- 不要求用户做决策。
- 文案尽量一句话完成。
- 不承载长说明。

---

## 5.3 Notification 通知

### 规则

- 信息量大于 Message。
- 包含标题 + 说明 + 可选操作入口。
- 不阻断当前工作流。
- 适合异步任务完成、后台任务异常等信息。

---

## 5.4 Popconfirm 气泡确认

### 适用场景

- 删除
- 撤销
- 小范围危险动作

### 规则

- 就近依附触发按钮。
- 提供确认 / 取消。
- 不用于复杂说明。
- 高风险或不可逆操作升级使用 Modal。

---

## 5.5 Modal 对话框

### 适用场景

- 需要阻断当前操作
- 要求用户确认
- 复杂编辑
- 高风险动作

### 规则

- 标题固定顶部。
- 内容区独立滚动。
- 主操作通常位于右下。
- 危险操作说明影响范围。
- 复杂页面不要整页塞进 Modal。

---

## 5.6 Drawer 抽屉

### 适用场景

- 查看详情
- 编辑局部信息
- 保留当前列表上下文

### 规则

- 通常从右侧滑入。
- 关闭后保持原页面筛选和滚动位置。
- 详情页优先使用 Drawer，而不是频繁跳转新页面。
- 内容过复杂时仍应使用独立页面。

---

## 5.7 Progress 进度

### 类型

- 条形进度
- 圆形进度
- 步骤式进度

### 规则

- 仅表达可确定的完成比例。
- 正常使用主色。
- 成功使用绿色。
- 异常使用红色。
- 无法估计时使用 Loading，不展示虚假百分比。

---

## 5.8 Result 结果页

### 状态

- Success
- Error
- Warning

### 规则

- 适合大型任务完成后的明确反馈。
- 包含状态图标、标题、说明、下一步操作。
- 成功 / 失败 / 警告语义全产品一致。

---

# 06. 组件反馈等级

从轻到重，优先按以下顺序选择反馈方式：

```text
Tooltip
→ Message
→ Notification / Alert
→ Popconfirm
→ Modal / Drawer
→ Result
```

### 选择原则

- **Tooltip**：补充解释
- **Message**：即时结果
- **Notification**：非阻断通知
- **Alert**：页面内持续提醒
- **Popconfirm**：小型危险确认
- **Modal**：阻断式确认 / 编辑
- **Drawer**：保留上下文查看 / 编辑
- **Result**：大型流程结果

# 07. B 端后台页面标准结构

## 7.1 列表页标准结构

```text
页面标题 + 主操作
↓
筛选区
↓
KPI / 汇总信息（可选）
↓
表格
↓
分页
```

### 要求

- 高频筛选直接显示。
- 低频筛选可折叠。
- 主操作位于页面右上。
- 表格操作列固定右侧。
- 筛选条件切页后保留。

---

## 7.2 配置页标准结构

```text
页面标题
↓
配置分组
  ├─ Form
  ├─ Tooltip / 帮助说明
  └─ 状态提示
↓
配置记录 / 操作日志
↓
保存 / 恢复
```

### 要求

- 可配置项和自动计算项必须明确区分。
- 自动计算项只展示结果，不表现成可编辑控件。
- 复杂说明放 Tooltip，不占主页面。
- 所有配置修改保留日志和版本。

---

## 7.3 详情页标准结构

```text
返回 / 面包屑
↓
对象标题 + 状态 + 主操作
↓
核心摘要
↓
详情 Tabs / 信息分组
↓
相关记录 / 历史 / 日志
```

### 要求

- 用户先看到当前状态，再看技术细节。
- 低频排查信息默认折叠。
- 列表上下文重要时优先 Drawer。

---

## 7.4 表单页标准结构

```text
页面标题
↓
业务分组 1
↓
业务分组 2
↓
业务分组 N
↓
保存 / 取消
```

### 要求

- 单屏字段过多时必须分组。
- 错误信息就近提示。
- 保存按钮位置统一。
- 不让用户猜哪些字段必填。

# 08. 针对“多账号智能策划”项目的落地约束

## 8.1 一级页面

前端核心 Tab 建议保持：

1. **策划配置**
2. **手动策划**
3. **策划结果**

算法参数、技术链路、模型计算过程不作为运营端一级页面。

---

## 8.2 策划配置页

建议使用：

- Page Title
- 分组 Form
- Number Input / Percentage Input
- Tooltip
- Alert
- 配置记录 Table
- 保存 Button
- 恢复快照 Popconfirm / Modal

### 主页面只展示运营可配置项

- 特殊槽位占比
- 经营策略占比
- 经营策略阈值
- 滚动统计周期
- 互动量阈值
- 其他经确认可由运营调整的参数

### 不直接展示

- 模型分数计算过程
- Embedding
- Recall / Ranking 技术参数
- 算法公式
- 中间候选池

---

## 8.3 手动策划页

推荐结构：

```text
本次策划规划数量
↓
账号筛选条件
↓
筛选结果数量 / 缺口提示
↓
选题选择
↓
分配规则预览
↓
确认生成
```

### UI 组件

- Number Input
- Form / Select
- KPI 数字
- Warning Alert（不足）
- Success Alert（充足）
- Table / Checkbox
- Primary Button

---

## 8.4 策划结果页

推荐结构：

```text
周度筛选 / 内容类型筛选 / 状态筛选
↓
KPI
↓
账号结果表格
↓
查看详情
```

### 表格核心字段

- 账号名称
- 账号类型 / 属性
- 周期
- 本周内容数
- 内容类型分布
- 生成状态
- 操作

### 详情页核心字段

- 选题
- 内容类型
- 槽位类型

### 技术字段默认隐藏

- 版本链
- 内部分数
- 中间算法状态
- 结果范围
- 模型过程

需要排查时，通过 Drawer / 折叠区查看。

# 10. 文案规范

## 10.1 按钮

使用动词表达操作：

- 保存配置
- 查询
- 重置
- 查看详情
- 替换选题
- 生成内容
- 恢复版本

避免：

- 确定一下
- 下一步看看
- 点击这里

## 10.2 状态

状态文案必须明确：

- 策划完成
- 策划失败
- 待审核
- 已审核
- 已替换
- 已降级
- 已释放

避免模糊状态：

- 正常
- 异常
- 处理中（除非确实有异步任务）

## 10.3 Tooltip

- 一次只解释一个规则。
- 推荐 1~3 句话。
- 不放长篇产品说明。
- 长说明进入帮助文档 / Drawer。
