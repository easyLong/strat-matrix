## 本次复核补充

已完成页面资料查询入口的 Java 显式化，详见[页面资料查询迁移](页面资料查询Java迁移_V0.1.md)。仍留在旧通配路径的主要业务服务是：综合配置读写和版本恢复、自动周策划周期与失败结果、热点 T-1 衔接、部分历史结果查询与导出。迁移这些服务时应同步迁正式业务状态和持久化归属，不能只把旧 Python 路由改名包装。

自动周策划的触发、普通结果事务提交和确认重试已在 Java 可选模块实现，见[正式提交与确认](自动策划Java正式提交与确认_V0.1.md)。该模块尚未切入运行服务，热点／营销与综合配置仍待迁移。

## 本轮选择人工营销任务的原因

页面输入只有任务名称、选题 ID 和生成内容数量；业务事实与幂等规则完整，不依赖行内算法细节。迁入后前端仍调用同一 Java 路径，Python 旧表只作为历史读取来源。营销内容的账号分配和状态仍由内容系统负责，Java 仅按任务编号读取和投影。

4. 最后退出旧历史联合查询，实现单库分页和导出；算法侧配置、标签和向量继续留在 Python。
