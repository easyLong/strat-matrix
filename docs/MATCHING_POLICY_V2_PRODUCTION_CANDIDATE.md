# 普通选题 V2 策略候选方案

> 状态：评审草案。此文件没有写入策略库、没有批准策略，也没有启用 Worker。候选参数必须经过运营样本评审后，才能批准执行。

配套机器可读文件：[ordinary-main V2 候选 JSON](examples/matching-policy-ordinary-main-v2-candidate.json)

## 1. 方案目标与边界

V2 的目标是在账号的一个策划周期内，为每个普通内容槽位分配一个可解释、符合经营角色、整体不重复的选题。执行分为：

1. 用账号向量与选题向量召回候选。
2. 执行城市、历史使用、T2 经营作用等硬门槛。
3. 在单账号的多个槽位上联合优化相关性、标签覆盖、角色平衡和选题差异。
4. 只有普通候选无法满足槽位时，才使用满足同一硬门槛的兜底选题。
5. 任何槽位仍无合法候选时，将任务作为不完整结果处理，不生成可提交的部分策划。

本方案只定义普通选题匹配。营销资格、热点来源和内容生产接口各自遵循对应流程，不由普通选题 V2 越权决定。账号侧 T1–T6 兴趣映射尚未进入冻结画像，因此现阶段不能把 V2 描述成“账号与 T1–T6 全量标签匹配”；Fit 仅使用现有账号/选题向量余弦相似度。

## 2. 向量空间

| 配置项 | 候选值 | 采用条件 |
| --- | --- | --- |
| 向量模型 | `doubao-embedding-vision-251215` | 与本地系统配置及已准备的账号、选题向量一致 |
| 向量维度 | `2048` | 当前冻结样本实测维度 |
| 语义空间 ID | `doubao-embedding-vision-251215` | 与已批准 V1 声明保持一致 |
| 相似度 | 单位向量余弦相似度 | 作为语义 Fit；不解释为成功概率 |

调整模型、维度、账号/选题文本拼接方式或向量生成模板时，应建立新的语义空间版本并重新生成画像向量，不能只改策略字段后混用旧向量。

## 3. 匹配与组合规则

### 3.1 硬门槛

- **城市**：空城市按通用选题处理；明确城市不相容的选题排除。
- **账号历史**：90 天窗口内该账号已使用的选题排除。当前历史覆盖率未知时暂按 V1 同口径允许未知并记录审计；进入生产前应确认接口覆盖范围。
- **T2 角色**：先按冻结的生命周期目标计算每个槽位的“流量/转化”角色，选题 T2 必须与槽位角色相同。普通召回和兜底池都执行此门槛，禁止跨角色补位。
- **T2 缺失或异常**：该选题从候选中排除并计入审计，不因此把整批任务误判为系统故障；若因此留下无候选槽位，按无候选规则处理。
- **向量空间**：模型标识、维度和语义空间不一致时，任务阻断，不做混合比较。
- **单账号复用**：同一账号周期内，同一选题最多使用一次。
- **全局复用**：初始不设置跨账号硬容量，避免小选题池导致大量空槽；通过账号内组合目标降低重复，并观察跨账号复用分布。

### 3.2 召回和 Fit

- `min_cosine=0.0`：仅保留非负余弦相似度，不把它当作已经校准的业务相关性阈值。
- `top_k=100`：按账号和槽位角色分别取前 100 个候选，`topic_id` 用于稳定打破并列。
- `Fit = clamp(cosine, 0, 1) × 100`：展示为 0–100 分，不代表命中率或质量概率。
- `shortlist_per_slot=20`：MMR 从召回候选中筛出组合搜索候选，优先保留语义相关性，同时惩罚与该账号已选选题的相似度。
- `mmr_relevance_weight=0.70`：相关性系数；其余部分用于鼓励差异。它是排序参数，不是最终组合目标权重。

### 3.3 单账号组合目标

联合分配的初始权重：

| 目标 | 权重 | 解释 |
| --- | ---: | --- |
| 相关性 R | 0.55 | 槽位选题与账号画像向量的匹配程度 |
| 标签覆盖 C | 0.20 | 提高 T3/T4/T5 分类标签在本账号周期内的覆盖 |
| 角色平衡 B | 0.10 | 接近冻结配置产生的流量/转化槽位配比 |
| 差异性 D | 0.15 | 降低已选选题之间的向量相似冗余 |

四项权重合计必须为 1。该组合分数用于一次账号周期内的全局分配；MMR 是组合搜索前的候选裁剪，不是全局目标中的第五项。初始权重是可审计的起点，不能以小规模合成数据声称最优。

## 4. 兜底与无候选处理

兜底选题必须满足城市、历史、T2 角色、单账号复用及配置容量规则。满足条件时按已知热度优先、再按稳定 ID 排序。兜底不绕过角色约束，也不允许悄悄跨 T2 补位。

某槽位没有合法普通候选和兜底候选时，标记为失败并保留原因；由于正式提交要求完整槽位，包含失败槽位的提案不能被提交。模型或输入快照异常则按任务级错误处理，不能伪装成“没有匹配结果”。

## 5. 当前数据检查与限制

截至 2026-10-21 的本地只读检查：

- 10 个账号向量和 20 个选题向量均为 `doubao-embedding-vision-251215`、2048 维。
- 当前测试样本共有 30 个计划槽位。
- 20 个测试选题的 T2 全部为“流量”，而冻结生命周期目标存在转化槽位。
- 这批数据只能确认向量空间字段相容，不能用来校准组合权重、MMR 参数或最低相关性阈值。
- 因为加入 T2 硬门槛，当前样本的转化槽位会没有普通候选；若兜底池也没有 T2=转化选题，则会明确暴露无候选，不能为了演示成功率而放宽规则。

## 6. 批准前的评审步骤

1. 补齐真实、有效的流量与转化选题，确认 T2 值和生命周期槽位角色的业务定义一致。
2. 确认历史接口提供的 90 天覆盖率；若无法保证完整，应明确未知历史的风险接受人和退出条件。
3. 使用冻结输入跑影子评估，检查角色符合率、每槽候选数、无候选/兜底数、Fit 分布、T3/T4/T5 周期覆盖、账号内冗余、跨账号复用分布。
4. 由策划运营逐账号查看推荐结果并记录接受/替换理由；基于足量真实反馈再调阈值和权重，形成新策略版本。
5. 确认候选结果和失败处理后，再批准 V2。批准只表示策略版本可用于任务；是否启动 Worker 仍是单独的运行操作。

## 7. 推荐候选值

JSON 候选文件给出完整的版本字段和参数。主要参数如下：

| 参数 | 候选值 |
| --- | ---: |
| 账号历史窗口 | 90 天 |
| 历史/正式使用次数未知策略 | 沿用当前允许未知口径并记录审计 |
| Top-K / MMR shortlist | 100 / 20 |
| 最低余弦阈值 | 0.0（仅起始值） |
| 单账号周期内单选题上限 | 1 |
| 跨账号全局容量 | 不限制 |
| R/C/B/D | 0.55 / 0.20 / 0.10 / 0.15 |
| MMR 相关性权重 | 0.70 |
| 局部改进轮数上限 | 25 |

这些值是候选策略，不是生产效果承诺。
