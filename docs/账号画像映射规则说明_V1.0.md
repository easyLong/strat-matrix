# 账号画像映射规则 V1.0

2026-11-02。根据V19账号信息与映射规则方案，新增策划侧规则表和可复用解析方法。

后续进展：已在独立[V19适配质量验证策略](V19适配质量链路说明.md)中冻结并使用映射规则，未确认的长描述可走受限模型映射；原V2默认策略保持不变，下文保留最初建表阶段说明。

## 已交付与边界

- 当前MySQL已创建`godp_account_mapping_rule`，21个字段均带中文注释。
- 规则集版本1，绑定当前标签词表版本3；初始化50条规则，全部为`draft`。再次初始化新增0条，既有规则不会被覆盖或重新启用。
- 有5类人设：福利专家、车圈达人、信用卡专家、理财专家、信贷专家；还包括有娃、运动／旅游、性别和表达风格示例。
- V19中的示例权重及映射尚未全部业务确认，因此不作为已批准配置。未明确给出权重的场景及别名映射属于初始化建议，一并保留草稿状态。
- 缺少“用卡权益”真实词表节点，因此该条未入库；未新增标签，也未借用“产品权益”等近义节点代替。缺失项由初始化命令返回。
- **本轮完成映射数据层和解析服务，尚未把它接入当前生产匹配评分、画像冻结或五路召回。现有V2匹配规则没有改变。**

## 表中主要字段

| 字段 | 含义 |
| --- | --- |
| mapping_version / taxonomy_version | 绑定的映射规则版本和词表版本 |
| source_field / source_value | 账号原始字段及精确匹配值，例如persona／福利专家 |
| target_dimension / target_level | T3、T4、T5、T6或STYLE；分类、末级或文本 |
| target_node_id / target_name | 已发布词表的稳定ID及名称快照；实际展示以绑定词表为准 |
| relation_type / weight | CORE=1.00、ADJACENT=0.75、CONDITIONAL=0.45、OFF=0；独立文本为TEXT且无权重 |
| condition_text | 条件适配的使用条件，必须留给后续精判核实 |
| target_text | 人设的需求服务能力，或表达风格描述 |
| status | draft待确认、active生效、disabled停用 |
| source_reference / remark | 来源依据及待确认事项 |
| create_by / update_by / 时间 / del_flag | 创建维护记录和逻辑删除标记 |

该表属于策划自有库，不复制行内账号资料。它按人设、兴趣等**字段值**配置通用规则，不需要为每个账号建立重复规则。

## 解析逻辑

1. 读取指定规则版本和词表版本，原始字段按完整值精确匹配。“理财顾问”不会被自动当作“理财专家”，长描述也不会被擅自归类。
2. 默认仅使用`active`规则；只有显式预览模式才读取草稿，停用或逻辑删除规则均不生效。
3. 人设T3允许配置L2分类和L3例外；同一原始值按**L3优先于L2**解析，只输出末级标签值，不额外累计父级。
4. 人设T3规则优先于兴趣补充线索；明确OFF不会被兴趣加分恢复。CONDITIONAL输出0.45及条件文本，并标记`requires_precision=true`，不代表已通过精判。
5. T4／T5仅允许有依据的末级映射，不允许通过分类把所有子标签自动置为已知。原始数据缺失、无有效规则或存在未解决冲突时，输出UNKNOWN、`value=null`和`known_mask=0`。
6. T6需求能力、STYLE风格分别输出独立文本，不混入T3～T5标签树。未映射的原始风格保留在结果中，不自动推断。
7. 规则与词表版本不一致、目标不存在、目标或上级停用时不应用该规则，并输出忽略原因。
8. 输出包括稳定ID顺序、权重、Known掩码、条件、证据及映射指纹。指纹覆盖实际规则内容、相关原始值和词表结构，便于后续画像缓存和失效检查。

## 调用与初始化

在`backend/`目录执行：

```bash
python -m app.init_account_mapping
```

该命令只创建映射表并补齐缺失的初始规则，返回新增／已存在数量及无法对齐词表的项目。完整`python -m app.init_planner_db`也已接入同一初始化方法。仅执行[增量SQL](../backend/migrations/20261102_add_account_mapping_rule.sql)只建表；初始化数据仍由Python根据真实标签ID生成。

可复用调用：

```python
from app.services.account_mapping import resolve_account_mapping

result = resolve_account_mapping(
    {"account_id": "示例账号", "persona": "福利专家", "family_identity": "有娃",
     "interests": ["运动", "旅游"], "gender": "女性", "expression_style": "干货J人"},
    mapping_version=1,
    taxonomy_version=3,
    preview=True,
)
```

上例为合成预览输入，不代表这些字段都已从行内接入。目前行内账号DTO已有性别、兴趣、风格；家庭身份仍需后续确认资料来源，缺失时保持未知。

查看初始化数据：

```sql
SELECT source_field, source_value, target_dimension, target_level,
       target_name, relation_type, weight, condition_text, status
FROM godp_account_mapping_rule
WHERE mapping_version = 1 AND taxonomy_version = 3 AND del_flag = 'N'
ORDER BY source_field, source_value, target_dimension, id;
```
