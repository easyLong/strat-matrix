# 人工营销策划业务迁移 V0.1

日期：2026-11-02。本轮把“选一个选题、填写生成内容数量、提交营销策划任务”从 Python 业务表迁入 Java 业务库。账号由内容侧后续分配；创建时没有账号和投放日期，也不调用内容生产。

## 业务归属

| 能力 | 归属与现状 |
| --- | --- |
| 营销任务创建、幂等、可信创建人、任务列表及详情 | Java `MarketingTaskService`、`godp_manual_marketing_task`；页面原路径不变 |
| 选题资料 | Java `ManualPorts.Source.snapshot`；行外适配器暂从旧 Python 只读取数，驻场换行内查询 |
| 内容侧账号分配及生产状态 | 行内内容系统产生事实；Java `MarketingStatusSource` 查询并校验时间、数量和状态后投影到业务任务 |
| 历史营销任务 | 原 Python 表只读；Java 列表合并历史任务，旧编号详情经 `Transition` 查询 |

新表列均带中文注释；与旧 Python 同名表处于不同数据库，不跨库联表。新任务编号为 `JMAN-MKT-...`，旧 `MAN-MKT-...` 仍可查看。前端无需改请求地址或确认步骤。

## 接口与状态

- `POST /api/plan/manual-plans/marketing-tasks`：接收 `request_id`、`task_name`、`topic_id`、`allocation_count`。同一请求编号与同一内容重复提交返回原任务；同编号不同内容返回 409。服务端重新确认选题可用并冻结资料快照。
- `GET /api/plan/manual-plans/marketing-tasks` 和 `GET /api/plan/manual-plans/marketing-tasks/{code}`：返回新旧任务，详情包含任务、空账号列表及选题快照。
- `POST /api/plan/query/manual-tasks`：新营销任务并入现有人工策划任务列表；无投放日期的任务在按日期筛选时不出现。
- 新任务初始为“待分配”。宿主调度可以调用 `MarketingTaskService.reconcile(limit, afterId)`，由 `MarketingStatusSource` 提供内容方状态。服务拒绝范围外、重复、过期时间、倒退计数、超出分配数量及伪造的完成状态；不启动生产任务。

## 驻场替换与发布

迁入既有 `planning/manual` 业务包、`ManualMapper.xml` 与 `db/manual-business.sql`；使用宿主业务库的数据源、MyBatis 与同库事务管理器。宿主提供 `ManualPorts.MarketingStatusSource` 对接内容方查询；行外默认返回空观察，不会自动完成。旧任务尚在 Python 库时保留 `ManualPorts.Transition` 的历史查询实现。

本地 `run/java-backend.properties` 指向远端 RDS。本轮仅代码与 H2 隔离测试通过，未对远端业务库建新表或切换服务。发布时先核对目标库、发布新表和上一轮 `V3__result_slot_identity.sql`，再切换 Java 服务。切换前应让旧 Python 已受理的营销提交完成，避免同一 `request_id` 横跨两库重复创建。

## 下一批业务服务

1. 自动周策划的任务接收、结果确认与批次写入：Java 负责业务状态和正式结果，Python 仅计算。
2. 热点 T-1 定题与营销内容衔接：Java 负责排期与引用规则，Python 负责候选匹配。
3. 旧历史退出后的账号／时间列表单库分页，以及失败详情与导出的统一查询。

以上涉及行内业务资料和内容侧接口的部分只保留端口，不能在行外模拟为真实完成。
