# 全功能字段与状态清单（对接梳理稿）

用途调整：本文件保留为内部功能核查资料。发给行内确认的字段与状态，请使用[行内待确认字段与状态清单](行内待确认字段与状态清单_2026-10-24.md)。

日期：2026-10-24。依据当前前端、后端模型与计算代码、V1.14 接口文档、10 月 21 日会议及之后确认的人工策划双流程整理。本清单用于确定业务需要的数据，并交给行内核对来源；尚不替双方决定实际表名、SQL 或新增枚举。

## 一、标注与边界

- **行内事实**：行内维护，策划侧查询；不要求重复保存一套主数据。
- **策划生成**：运营填写或策划系统计算，保存至策划业务表、扩展表或结果快照。
- **待核对**：业务需要补充或代码能够接收，但未确认行内存在该字段，不能直接当作已承诺必填。
- 本文英文名沿用已有契约或作为建议映射名；多种旧字段只映射为同一含义，不要求行内重复提供。
- 行内账号 ID、选题 ID、内容 ID 与本项目数据库自增主键必须区分。属主 UM 号不能替代账号 ID。
- 下述功能范围覆盖页面和主要后台业务链路；底层日志、数据库连接等通用技术字段不逐行作为行内业务取数要求。

选题审核字段与营销成品内容审核字段是不同对象。普通/人工选题是否有独立审核状态、哪些值允许使用，须按行内选题库实际规则确认，不能强制所有选题走营销成品审核。

## 五、营销成品内容与人工营销生产需求

### 5.1 行内营销成品内容

| 必要字段组 | 字段 |
| --- | --- |
| 唯一关联 | 内容 ID、绑定账号 ID、原生产任务/来源需求 ID；存在选题时才有 topic_id |
| 内容展示 | 标题、正文、图片/素材引用、内容类型、关联产品/活动 |
| 审核事实 | 审核状态、审核通过时间；消保等子状态及关联凭证是否直接返回由行内确认 |
| 排期事实 | 当前投放日期/时刻、是否已占用、关联策划记录、排期版本或其他并发校验依据 |
| 可用性 | 当前内容状态、有效期、撤回/失效状态 |
| 时间及追溯 | 创建、更新时间、排序依据及源版本 |

审核通过且没有投放日期的成品才进入自动营销排期池。以上占用及版本字段是实现重复排期防护所需能力，实际存储字段由行内确认，不假定现表已有。

### 5.2 策划侧人工营销需求

任务 ID/编号、任务名称、幂等请求 ID、内容模式、计划账号数、实际账号 ID 集合、账号快照、每账号生产条数、总需求条数、创建人/时间、处理状态、关联行内生产需求 ID。总条数按实际账号数×每账号条数计算。

当前新表已保存实际账号数、账号快照及每账号条数，计划账号数在前端保留但没有独立落库字段；如要求任务详情追溯计划/实际差异，需要补充持久化。

营销需求提交时没有投放日期，也不要求先有选题 ID。后续内容生产、审核及审核后的排期为不同环节，当前生产对接尚未完成。

| T4/T5 | 目标客群/使用场景的标签集合及完整路径 |
| T6 | 用户需求文本、需求标签 ID、归并或生成来源 |
| 正式打标结果 | 选题 ID、对应选题版本/指纹、采用字典版本、标签结果、处理状态、失败原因、标签版本、处理时间 |
| 批量测试 | 输入topic_id/title/outline数组、逐条状态和标签、整体状态、测试时间；不覆盖正式标签 |

T3/T4/T5 应保存完整层级路径，不能只传末级名称；具体层级及多选数量由已确认标签规范约束。模型输出不等于行内原始事实。

### 7.2 内部准备与 V2 执行

| 数据组 | 字段 |
| --- | --- |
| 冻结输入 | 准备记录 ID、账号/选题 ID、源版本/指纹、读取时点、配置版本、冻结账号/选题/标签及历史数据、输入完整性 |
| 画像 | 画像内容、画像版本/指纹、采用的源及标签版本、生成时间 |
| 向量 | 实际模型标识、向量值、维度、语义空间/模板版本、就绪状态、失败原因、完成时间 |
| 策略 | 策略 ID/版本、批准状态、文档指纹、候选阈值/数量、门槛、复用与历史约束、组合权重 |
| 候选/分配 | 账号和策划记录、选题 ID、经营作用、相似度/Fit、排名、门槛通过/拒绝原因、组合评价、兜底原因 |
| 执行追溯 | 匹配任务 ID、绑定输入/策略版本、执行状态、尝试次数、领取与过期时间、错误码、提案、正式提交关联 |

当前 V2 已有向量相似度与组合目标执行链路；账号侧 T1～T6 全量特征适配在仓库仍有待评审草案，不能把这些推断标签当作行内必须提供的原始字段。

## 八、生产、审核、发布及使用统计

### 8.1 全链路关联字段

| 数据组 | 必要字段 | 维护/提供方 |
| --- | --- | --- |
| 来源需求 | 营销需求任务/需求项ID，或已排期策划slot_id、结果版本、批次ID | 策划 |
| 行内生产执行 | 生产任务 ID、内容 Agent 编码及必要版本、执行类型、开始/结束时间、状态、失败原因 | 行内；实际字段待核对 |
| 内容流水 | 内容 ID、原始/重试关联、来源需求/slot_id、内容类型、生成标题正文及素材、当前有效标识或版本 | 行内；支持一个来源多条内容 |
| 质检质控 | 技术执行状态、是否存在问题/是否通过、问题原因、重试次数、重试状态及时间 | 行内；不能只给一个含义不明的失败值 |
| 人工审核 | 审核状态、进入待审核时间、审核时间、驳回/撤回情况 | 行内 |
| 排期及发布 | 排期日期、实际发布时间、发布状态、发布记录/平台作品ID、失败原因 | 行内；页面隐藏不表示流程无需保留 |
| 使用事实 | 选题 ID、来源、账号、策划/slot_id、结果版本、有效内容关联、成功使用时点、去重键 | 策划维护统计；成功触发点待确认 |
| 查询统计 | topic_ids、可选或约定必填的时间起止、查询状态/时间、每题使用次数 | 策划；时间依据须确认 |

仅生产任务 ID 与成功/失败两个字段无法覆盖行内质检、多次生成、审核及删除重试的全部场景。完成状态与计数必须依赖明确的有效内容选择规则。

### 8.2 状态目录与确认程度

| 对象 | 当前状态/需要的区分 | 确认程度 |
| --- | --- | --- |
| 账号启停 | 启用、停用；缺失为数据异常 | 当前已用，行内原始枚举待映射 |
| 账号认证 | 认证、非认证；未取得认证信息 | 当前已用，缺失不能自动当作认证 |
| 营销资格 | 可/不可/无法判定 | 独立含义待核对，不擅自等同认证 |
| 生命周期 | 冷启动、流量增长、转化试探、转化放大、稳定经营 | 五阶段已确认，复杂条件分组仍仅备忘 |
| 选题可用性 | 可用、停用/撤回、未到有效期、已过期 | 来源状态与按日期判断分开；原始枚举待映射 |
| 标签启停 | 启用、停用 | 已确认；停用项折叠、历史保留 |
| 正式打标 | 待打标、打标中、已完成、打标失败；还需识别旧版本失效 | 原文档展示口径；当前不同模块中文/英文状态需统一映射 |
| 画像/向量 | 等待标签、待生成、生成中、就绪、失败、输入已变化不可用 | 业务区分；当前代码有pending/ready/failed/stale等，不能当作统一既有枚举 |
| 策划任务 | 已完成、生成中、生成失败 | 当前页面口径；与内容生产状态独立 |
| 新人工营销需求 | 待处理、待生产 | 当前只完成需求保存；后续执行状态还未接入 |
| 自动周期阶段 | 已规划、执行期热点待填充、已完成 | 原确认周期阶段；不是质检/审核状态；与最新策划结果状态的映射需整理 |
| 单条策划内容 | 待定题、待生产、生产中、已完成、生产失败 | 已确认展示词；“已完成”对应行内哪一步仍待确认 |
| 生产任务受理 | 未领取、已领取/处理中、结束、失败及重试中 | 需要区分，原始枚举由行内给出 |
| 质检技术执行 | 未开始、执行中、执行成功、执行失败 | 需行内核对，不是新增已定枚举 |
| 质检业务结论 | 未得出结论、无问题、有问题 | 与技术成功/失败分开；结论字段待确认 |
| 人工审核 | 尚未到达、待审核、通过、驳回及撤回/重审情况 | 需行内核对完整状态与流转 |
| 营销排期 | 待审核、审核通过未排期、已占用/已排期、撤回/失效 | 筛选/防重所需业务区分，最终字段与枚举待确认 |
| 内容发布 | 未发布、发布中、成功、失败等 | 行内枚举待核对，与生产完成分开 |
| 模板行结果 | 成功、重复、未识别、已投放不可选 | 当前已用；异常合计=未识别+已投放，成功账号可继续 |
| 查询反馈 | 成功有数据、成功无数据、请求/服务异常 | 空数组不代表查询失败，状态未知不作正常生命周期 |

生产状态、质检结论、审核状态须分别保留。当前内容进度有按完成账号数/总账号数的页面实现，而会议又提出按策划内容条数和失败条数展示；两种数量都应可计算，最终页面展示口径须单独确认。

### 8.3 状态规则还需要行内共同确认

1. 内容生成完成、质检通过、进入人工待审核、人工审核通过，哪一步对应策划页“已完成”。
2. 一个slot_id关联多条内容时，用有效版本、最新记录、成功记录或其他规则判定当前状态。
3. 自动重试、人工重新生成、重新质检是否新增内容ID，是否删除/覆盖原审核记录。
4. 重试尚有机会时如何显示；何时才算最终生产失败。
5. 成功后驳回、撤回或重生，完成状态和使用计数是否回退；重复尝试按什么键去重。
6. 营销成品排期是否属于“选题使用”，若没有topic_id，不能制造一个topic_id凑统计。
7. 时间范围统计按投放时间还是生产完成时间，是否需要两种口径。

## 九、需要行内提供与策划侧维护的总清单

### 行内提供的原始数据

- 账号完整资料、认证及启停、人设原始结构、组织、粉丝量及相关时间。
- 账号实际帖子及互动明细、采集覆盖范围和缺失说明。
- 统一选题库的完整选题详情、关联产品/活动/热点、可用性、有效期、类型字典、变化时间；热度来源单独确认。
- 已生产营销内容及审核、可用性、排期占用信息。
- 内容Agent实际生产所需参数字典，内容流水、质检、审核、发布及重试的字段与状态字典。
- 对应表结构、字段映射、稳定ID及关联关系、脱敏样例。

### 策划侧提供及维护

- 方法入参/返回对象；每字段类型、是否可空、原始值到业务值的映射规则。
- 指标和生命周期、配置与版本、正式标签、画像向量、匹配策略与执行任务。
- 人工/自动策划任务、批次和明细、营销生产需求、输入快照、替换及审计记录。
- 内容关联及汇总状态、去重使用事实与查询统计；依赖行内实际流程共同定口径。
- 扩展表设计及其与行内ID的关联；全部新建表和字段保留中文说明。

## 十、优先核对的问题

1. 账号人设结构及画像读取的客群、兴趣、家庭身份、表达风格，行内到底有哪些；不存在时如何保留缺失。
2. 认证、营销资格、启停与允许生产是否独立；各自的原始枚举。
3. 帖子是否完整覆盖统计窗口，缺失计数是否被误填为0；当前每账号最多1000条等旧限制能否覆盖真实数据。
4. 当前“有效内容”计算没有使用帖子下架/删除状态；业务有效条件需确认。
5. 选题与成品内容的类型字典、ID空间、有效期及上游热度是否齐全。
6. 当前标题大纲编辑后的正式重打标、旧画像失效，需要与行内编辑流程对接；仅有同库查询不会自动解决。
7. 一条策划与多条内容的关系，以及生产、质检、审核聚合到页面状态的规则。
8. 来源状态更新与正式历史快照分开，不让最新人设、大纲覆盖历史策划。

后续在本清单基础上逐项拆出IF-01等方法定义和扩展表映射。字段清单完整不表示所有字段都必须在每次查询中一次性返回，也不表示代码中已有接收字段已得到行内承诺。
