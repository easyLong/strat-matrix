# 人工策划双流程 · 2026-10-23

## 本次确认口径

| 环节 | 营销 | 非营销 |
| --- | --- | --- |
| 创建策划 | 任务名称、内容类型、每账号生产数量 | 任务名称、内容类型、投放日期 |
| 选择账号 | 仅认证账号；维度筛选填写计划账号数量，模板导入按文件行数计算 | 认证和非认证账号；保留原维度筛选、计划账号数量及导入 |
| 选择选题 | 无此步骤 | 选择非营销选题，保留多次筛选及勾选 |
| 确认策划 | 账号、每账号条数、总条数及选题区域 | 左侧账号，右侧已选选题；展示选题 ID、标题、大纲、内容类型，独立分页及滚动，长文本悬浮展示 |

营销不预设投放日期，也不要求提前选择营销选题。确认页按用户明确回复保留选题区域，但当前没有选题生成来源，显示“待生成”，不展示虚构选题。

## 已落地

- 营销为创建、选择账号、确认三个步骤；非营销为四步。
- 切换内容类型清除不兼容的账号及选题选择；营销筛选和导入均只允许认证账号。
- 非营销保留所选投放日期的重复人工策划校验；营销无投放日期，不借用当天日期套用该限制。
- 保存后冻结账号选择，营销展示实际账号数和每账号条数；返回后可调整。
- 营销的计划账号数量与每账号生产条数分别保留；点击查询后按计划数量选择账号，可继续手工勾选。保存后展示计划数、实际数及差异，确认页保留计划数；内容总条数按实际勾选账号数乘每账号条数计算。
- 按后续纠正，非营销确认页恢复已选选题列表，账号和选题左右展示，各自分页和滚动；不再采用先前“非营销确认页仅账号”的口径。
- 前后端共同阻止非营销任务选用营销选题；提交执行前再次检查选题类型。
- 营销按请求标识实现提交幂等，任务按账号信息快照和每账号条数持久化；任务详情可查看账号及数量。
- 任务列表沿用原表头及顺序：投放日期、账号数、选题数、策划状态、内容状态、批次、发起时间、更新时间、操作；不新增内容类型及每账号条数列。营销投放日期为空，每账号条数在任务详情查看。旧流程任务在数据层保留 legacy 标记，不擅自把历史混合任务标成非营销。

## 数据与接口

- 新表 `godp_manual_marketing_task`：营销生产需求，不写入有投放日期的正式排期槽位。所有字段及表均有中文注释。
- `godp_manual_preview.content_mode`：`non_marketing` 为新非营销流程，`legacy` 为原流程。
- `POST /api/manual-plans/marketing-tasks`：任务名称、请求唯一标识、账号 ID 数组、每账号生产条数；不接收投放日期或选题列表。
- `GET /api/manual-plans/marketing-tasks`：任务列表。
- `GET /api/manual-plans/marketing-tasks/{task_code}`：账号快照、生产数量及当前空选题列表。
- 原非营销流程仍使用 `/api/manual-plans/previews` 及对应 submit 接口。

升级时先执行 `cd backend && python -m app.init_manual_marketing_db`，再重启后端、构建前端。迁移为新增表及字段，保留历史数据；`init_db` 和 `init_workflow_db` 已包含此迁移。

## 当前边界

本轮完成页面双流程、校验及需求任务保存。营销任务初始状态为“待处理”、内容“待生产”；没有伪装已生产、已审核或已排期。行内营销 Agent 的实际执行、生成选题回写、审核和审核后排期尚未接入新任务表，需要结合行内生产参数及实际表结构继续对接。
