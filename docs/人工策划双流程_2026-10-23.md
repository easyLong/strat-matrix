# 人工策划营销与非营销流程

更新日期：2026-10-28。文件路径沿用最初版本，正文已替换为当前确认口径。近期页面、统计和部署变更见 [近期修改汇总](近期修改汇总_2026-10-28.md)。

## 当前流程

| 环节 | 营销 | 非营销 |
| --- | --- | --- |
| 创建策划 | 任务名称、选题类型 | 任务名称、选题类型、投放日期 |
| 选择账号 | 无此步骤，账号由外部系统分配 | 维度筛选或模板导入，可继续勾选，保留计划数量及实际数量 |
| 选择选题 | 全宽列表，单选一个选题 | 左侧已选选题、右侧可选列表，多次查询累加勾选 |
| 分配数量 | 选中选题后显示于列表下方，填写此选题的内容总条数 | 无此字段 |
| 确认策划 | 第三步，显示任务名称、类型、分配数量及选题 | 第四步，显示任务、账号和选题 |

营销采用“创建策划 → 选择选题 → 确认策划”，确认页为完整步骤页面。营销既不预设日期，也不选择账号；“每账号生产数量”已删除。分配数量必填，范围为 1 至 1000 的整数，标签、说明气泡和输入框同行展示。

营销默认查询营销选题，也保留切换非营销选题的既有能力，一次任务仍只能保存一个选题。非营销仅查询非营销选题。选择选题的筛选默认展开，点击查询后生效；营销没有左侧已选选题栏，列表使用单选框。

选题保存后进入已保存状态，营销分配数量冻结；点击下一步进入确认策划。返回上一步可调整原选择和数量，不丢失已填内容。

## 非营销账号选择

维度筛选和模板导入保持两种独立选择方式。筛选模式填写计划账号数量，点击查询后按当前条件选择账号，用户可继续勾选调整；模板导入支持属主 UM 号及账号 ID，计划数量按数据行数计算。

导入异常展示导入、成功、重复、异常数量及相应明细，成功识别的账号仍可继续策划。账号列表分页展示；保存后冻结条件，并显示计划数量、实际选择数量及差异。

重复人工策划限制按所选投放日期判断，已占用账号置灰并悬浮提示，提交时再次校验。营销需求无日期、无预选账号，不套用该限制。

## 策划任务列表及查看策划

当前列为：批次、投放日期、账号数、选题数、策划状态、内容状态、创建人、发起时间、更新时间、操作。批次列上方显示名称，下方显示批次号。

任务列表支持每页 10、20、50 条分页，暂不展示筛选区。分页作用于已从接口加载的数据；营销列表接口默认读取最近 20 条，全部历史的服务端分页尚待接入。

“查看策划”文案保持不变。有正式批次时进入复用的批次策划详情；没有正式批次的营销需求展示营销任务详情。内容生产由后台执行，有正式批次时可查看内容流水。新营销任务账号数显示“待分配”，投放日期留空。

## 营销请求与持久化

| 内部接口 | 当前用途 |
| --- | --- |
| `POST /api/manual-plans/marketing-tasks` | 提交一个选题及总分配数量 |
| `GET /api/manual-plans/marketing-tasks` | 查询营销任务列表 |
| `GET /api/manual-plans/marketing-tasks/{task_code}` | 查询任务摘要、选题快照及账号快照 |

创建请求只包含 `request_id`、`task_name`、`topic_id`、`allocation_count`，不再接收账号数组、选题数组、每账号数量或投放日期。

任务保存于 `godp_manual_marketing_task`，新增字段 `allocation_count` 带中文说明。新任务保存一个选题快照、空账号快照、总分配数量及“待分配”状态；旧字段保留以兼容历史任务。`request_id` 和请求指纹用于避免同一内容重复提交，并阻止用相同标识提交不同内容。

外部系统实际分配账号、回填分配结果、内容生产与审核及最终排期尚未接入新任务表。当前保存任务不会自动创建带日期的正式排期，也不会主动向外部系统发送需求。

非营销继续使用 `/api/manual-plans/previews` 和对应 submit 接口，保留选题可用性、日期及账号资格复核。

## 升级与核查

更新后在 `backend` 目录运行 `python -m app.init_manual_marketing_db`，使用部署环境的 Python 解释器；再构建前端并重启后端。该迁移新增字段、保留历史数据，`init_db` 和 `init_workflow_db` 也已包含此迁移。

当前版本通过前端 TypeScript 检查及生产构建、后端编译检查；本地数据库迁移已执行，新请求字段已通过运行中的 OpenAPI 核对。当前营销流程仍需浏览器交互验收和外部系统联调，历史版本的营销账号选择测试不适用于本版。

新建任务继续使用兼容局域网 HTTP 的 UUID v4 生成方法，避免依赖仅在安全上下文可用的 `crypto.randomUUID()`。
