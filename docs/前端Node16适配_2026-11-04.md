# Node16.13.0前端适配与验收

日期：2026-11-04。承接[Vue2迁移](前端Vue2驻场适配_2026-11-04.md)，本轮完成Node16.13.0实际验证，当前不再以Node24验收结果代替目标环境。

下表保留首次Node16适配验收记录。后续清理与修复后的最新结果为29项前端测试、20个浏览器场景通过，见[前端复核记录](前端复核与修复_2026-11-04.md)；同名浏览器报告会被最新验收覆盖。

## 已完成

- Node固定16.13.0，实测其配套npm8.1.0；package.json允许npm8.1至8.x，packageManager记录8.1.0。根目录和frontend目录增加`.nvmrc`。
- frontend启用engine-strict，安装、测试、构建、dev和preview增加Node版本检查，错误版本明确退出；已验证本机全局Node24会被拒绝。
- 重新生成并安装npm8的lockfileVersion2，包含完整packages与兼容dependencies信息。固定兼容的Browserslist及node-releases开发依赖；锁文件内声明Node版本约束的包均满足16.13.0。
- Node类型改为16.11.7，修正旧类型定义下悬浮提示定时器的可空清理检查。
- 测试改为Mocha10.8.2，按文件隔离并发数2，保留原业务断言；测试辅助提供Node16缺少的fixture克隆及Blob，不注入生产页面。响应式数组断言按实际内容和顺序比较，保留数量、选择和冻结限制校验。
- Axios请求层不依赖Node端的Headers和DOMException全局对象；浏览器Headers、普通对象及元组请求头均按统一边界处理，取消仍返回AbortError语义。
- 可选浏览器验收工具使用支持Node16的Playwright1.40.1，脚本查询改用其request API，不依赖Node内置fetch。
- Windows增加[项目命令入口](../scripts/frontend.ps1)，选择已激活的Node16.13.0或当前工作区独立运行时，执行后恢复PATH。它不下载软件或修改系统安装。

## 使用

行内已安装Node16.13.0时，在frontend目录正常执行`npm ci`、`npm test`、`npm run build`、`npm run dev`即可。先确认`node -v`和`npm -v`；统一Python回归入口也应在已激活此Node的PATH下运行。

本Windows工作区在仓库根目录执行：

```powershell
.\scripts\frontend.ps1 version
.\scripts\frontend.ps1 install
.\scripts\frontend.ps1 test
.\scripts\frontend.ps1 build
.\scripts\frontend.ps1 dev
```

独立Node位于忽略目录`.tmp-tools/node-v16.13.0-win-x64/`。它不是仓库自带依赖；其它机器需由IT提供/激活批准的16.13.0。Linux使用对应Linux运行时并重新安装依赖，不复制Windows node_modules。电脑全局Node保留原版本；当前前端进程和项目命令入口使用目标版本。

正式宿主的路由、请求包装、权限与样式仍按[迁入说明](../frontend/VUE2_INTEGRATION.md)联调。本轮没有调用真实模型、变更数据库或修改Java/Python业务规则。

版本参考：[Node16.13.0官方发行及下载](https://nodejs.org/en/blog/release/v16.13.0)、[官方SHA256清单](https://nodejs.org/download/release/v16.13.0/SHASUMS256.txt)、[Mocha10.8.2运行版本要求](https://github.com/mochajs/mocha/blob/v10.8.2/package.json)。
