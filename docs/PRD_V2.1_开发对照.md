# PRD V2.1 开发对照

更新时间：2026-09-29。开发基线为《多账号智能策划_PRD_V2.1_页面型精修评审稿》。本轮优先落地页面精修中不依赖客户最终接口字段的闭环要求。

## 本轮已实现

| PRD 规则 | 实现 |
| --- | --- |
| MAN-R06 / MAN-UAT-07~12 | 新增 `godp_manual_task`。每次正式提交先创建“执行中”任务，成功更新为“已完成”；账号/选题失效、预览过期或系统异常时保留“执行失败”及失败原因。 |
| 手动任务页面 | 手动策划页展示发起时间、投放日期、规划账号数、成功结果、失败结果、选题数、状态、最后更新时间；可跳转结果或查看失败原因。运行中任务每10秒自动刷新。 |
| GLOBAL-R02 / GLOBAL-R03 | AI 自动策划运行中周期每10秒刷新；批次列表展示最后更新时间。策划结果周期汇总增加最后更新时间。 |
| GLOBAL-R05 | 手动任务失败原因以摘要形式展示；选题大纲在选题搜索结果中保留摘要字段。 |
| CFG-R05 | 策划配置存在未保存修改时，切换页面会确认；浏览器关闭/刷新也会提示。 |
| CFG-R06 | 配置接口继续携带预期有效版本，冲突返回 409；模块历史恢复仍只影响所选模块。 |
| 结果统计 | 周度统计继续区分 AI 自动结果和手动追加，按当前有效策划分配计算选题使用次数。 |
| REP-R01~R03 | 结果条目返回 `publish_status`、`allow_replace`、`replace_block_reason` 和结果版本；满足状态可信、未触发生产、未发布的真实 AI 槽位才显示替换入口。 |
| 调整历史 | 新增 `godp_planning_adjustment`，人工替换会保留原选题、新选题、原因、版本和时间，并写入 `CONTENT_VERSION_CHANGED` 本地待投递事件。调整记录在替换抽屉中按时间倒序展示。 |
| 演示验收夹具 | `seed_prototype` 初始化运营原型验收数据：68 个账号、8 个示例选题、T1–T5 标签体系、5 个自动策划周期和 9/12/18/20/24 条手动任务；`seed_demo`、`seed_large_demo` 仍可用于通用小数据和大目录验收。脚本只处理 `DEMO-` 演示记录，不作用于真实业务编码。 |

## 仍需下一轮实现

- AI 批次启动时的配置模块版本、`data_cutoff_time` 和批次快照字段；当前尚无真实自动调度入口。
- 热点执行记录及只读详情抽屉；需要热点来源、目标数量、时间窗口和槽位状态输入。
- 策划结果中的策划时生命周期、经营作用、内容类型、选题大纲完整字段；当前本地目录部分记录还没有这些来源数据。

## 评审稿待确认项

业务时区和周边界、自动任务时间、发布计划到槽位展开、生命周期阈值和阶段优先级、营销“先来”时间字段、热点来源与优先级、内容生产触发点、发布状态权威来源、手动策划部分成功状态等仍按 PRD 第10章保留，不在代码中自行假设。
