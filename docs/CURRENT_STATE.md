## 2. 工程与数据归属

| 位置 | 负责什么 |
| --- | --- |
| 本仓库 `frontend/` | Vue三个页面、共用组件、状态和交互 |
| 本仓库 `backend/` | FastAPI页面业务、Java数据读取适配、任务和算法、自有库读写 |
| 行内已有Java工程 | 通用转发、登录权限、可信操作人、宿主Job及业务资料SQL查询 |
| 本仓库 `docs/integration/java-host/` | 方法、对象和空方法参考模板，使用`.java.example`后缀，不参与编译 |
| 行内业务库 | 账号、选题、营销内容、互动、审核、投放和生产事实 |
| 策划自有库 | 配置、标签、画像、向量、任务、正式结果、快照、状态投影和使用次数 |

目标调用关系为Vue → 行内Java → Python。Python经Java读取行内资料，不直接查询行内业务库。内容侧经独立授权只读策划结果并自行生产，状态由Java查询能力提供给Python。

## 4. 下一轮改造顺序

1. 固定宿主转发、资料查询与内部执行入口边界，按行内契约补字段映射。
2. 抽出有限的协调与任务执行入口，复用现有业务函数和任务记录。
3. 增加宿主唤醒及FastAPI内受控执行器，人工提交后立即尝试执行；重复唤醒不重复处理。
4. 补齐续租、重试、中断恢复、业务积压和失败监控；行内模式关闭自主轮询。
5. 先验收一个账号一个周期的普通选题正式闭环，再扩大规模并补齐营销、热点及权限范围验收。

合规、模型出网、部署进程、调度频率和资源额度仍以行内实际要求为准，不能把线程池或双库隔离本身当作已通过审查的证明。
