# 全流程测试与行内接入对照 V1.0

核查日期：2026-11-03。依据当前代码、运行资料与已保存验收证据整理。本文说明实际来源、处理、落点、测试方法及行内替换点；不将历史方案或预留接口当成已接通功能。后续已收敛日常与验收资料链路，未重新调用模型或创建策划任务。

后续另行执行了[营销/热点增量验收](营销热点与模拟内容衔接验收_2026-11-03.md)：Pipeline15真实模型混合闭环及5账号业务分支均通过，内容方仍为模拟事实。下文Pipeline14等数据保留各自验收时点。

## 1. 先分清三类数据、三个工程

| 数据 | 权威来源/维护者 | 本项目如何使用 |
| --- | --- | --- |
| 账号、互动、普通/热点选题、过审营销内容、有效投放及生产事实 | 行内原系统，Java负责查询和字段映射 | 分页查询，不另建一套基础资料同步镜像 |
| 页面业务配置、人工/自动任务、正式批次与明细、操作及内容状态投影 | Java业务模块；本地库为`strat_matrix_bus` | 业务事务、幂等、查询和导出 |
| 生命周期条件、阶段经营目标、标签树、映射规则、匹配策略、画像、向量、计算任务和提案 | Python算法模块；本地库为`strat_matrix` | 算法准备、计算、冻结、复盘及结果交接 |

Vue只有AI策划配置、人工策划、策划结果三个业务页面，所有请求先进入Java。Java业务模块与Vue最终并入客户已有工程，Python算法模块并入客户已有Python工程；行内入口、身份、权限、调度和部署由宿主管理。

运行时Python只连接算法库，经Java HTTP读取需要的行内事实。Java通过MyBatis操作自己的业务表，查询行内事实也由Java完成。内容方独立生成、审核和分配内容，策划侧读取其事实。

**任务快照是有意保留的数据。** 虽然不维护基础资料镜像，但业务明细和算法任务会保存本次使用的账号/选题快照、版本、输入指纹，才能复盘旧结果。快照范围与保留周期需在入场时确认，不能理解为“任何账号/选题字段都不落库”。

| 场景 | 基础资料怎么来 | 用途与边界 |

目前日常资料夹具有90个账号、57个选题；它与算法库中的历史处理资产数量不要求一致。完整验收每次生成1个账号、12个普通非营销选题，在计算前原子追加到同一模拟文件；即使验收失败也保留明确测试ID供排查，不覆盖其他资料。算法离线回放另用固定合成数据，见第8节。

| 7. 向量准备 | 账号画像、选题画像、T6文本；统一向量模型 | 生成/复用所需向量，校验模型、维度、语义空间和输入指纹 | Python账号准备、选题画像、T6资产及计算缓存 | 换模型通道时确认输入/响应协议；不同模型/维度不能混用 |

## 4. 算法输入究竟来自哪里

| 输入 | 来源 | 当前用途 |
| --- | --- | --- |
| 账号ID、属主UM号、组织、平台 | 行内账号资料；outside为夹具 | 关联、展示、筛选及未来权限；不应因为字段存在就全部塞入模型 |
| 人设、兴趣、性别、表达风格等 | 行内原始资料及本轮冻结快照 | 当前V19映射读取这些画像特征；缺少旧画像字段时从冻结`source_payload`取值 |
| 账号类型 | 行内事实 | 资格/营销条件；当前正式映射来源字段枚举不包含账号类型，不能说它已被单独做成映射特征 |
| 粉丝、已发布内容与点赞/收藏/评论 | 行内账号/互动资料 | 生命周期、经营目标及趋势计算；这些结果由算法侧维护 |
| 选题ID、标题、大纲、来源、一级/二级分类、有效期、热度等 | 行内选题资料 | 可用性过滤、打标、画像、匹配及详情；普通/热点共用来源区分，营销现成内容另行查询 |
| 标签树、生命周期条件、目标比例、正式映射、匹配权重 | Python算法配置 | 算法权威配置，不要求行内基础库生成 |
| 策划日、调度日期时间、营销上限、热点占比 | Java业务配置 | 通过业务快照进入计算；Python保留旧字段不代表旧字段仍是业务权威源 |
| 历史用题 | 当前读取账号互动；Java正式业务库也拥有本系统的账号—选题关系 | 现有互动实体没有选题ID，因此当前真实源的历史ID去重存在缺口，见第11节 |
| 选题使用次数 | Java业务库生产完成明细聚合 | Python通过Java读取，按任务冻结；旧Python计数表不能作为新正式结果的权威 |

两个模型类别在项目中共用：文本模型`MODEL_NAME`，向量模型`EMBEDDING_MODEL_NAME`。不是每个账号、标签单独配置一个模型。现有模型适配仍以豆包/Ark协议实现；模型名称通用化不等于已经支持任意厂商协议。

向量也有不同用途：账号/选题画像向量用于输入准备；V19的T6召回主要比较账号需求向量与选题T6需求向量；组合冗余使用选题向量。不是所有匹配仅算“账号整段画像与选题整段画像的余弦”。

当前正式策略为9，映射版本1，基础精判门槛0.65、主题门槛0.60、邻接主题门槛0.80。正式映射模式只读取启用规则；核查时规则表50条均为草稿，未知方向由受限模型补全，不能把它们称为已审核的50条正式规则。

## 6. 调度与状态必须分开测试

当前outside的`LocalJobPulse`模拟宿主调度：推进配置恢复、人工任务、热点/营销和状态，再按节奏唤醒Python。它不迁入行内。行内可用一个综合Job或多个Job，但不能只发Python唤醒而遗漏Java的业务推进。

热点单独按每日任务理解：宿主每天触发明日空槽检查，具体运行时刻由宿主配置。行外`LocalDailyHotspotCheck`在已有脉冲上模拟每天一次；分页结束后当天停止，异常可重试。重启后允许重新检查，已定题明细不会重复处理。营销、状态等其他推进频率保持原约定。

| 状态对象 | 应观察什么 | 不能混淆什么 |
| --- | --- | --- |
| HTTP受理 | 已保存任务、返回任务编号/受理状态 | 202/受理成功不是业务完成 |
| Python准备 | 等待、就绪、已冻结及具体缺失原因 | 资料存在不等于标签/向量已就绪 |
| Python匹配 | 排队、处理中、已评估、失败/失效；报告中是否有未分配位置 | 已评估不一定能形成完整正式批次 |
| Java自动业务任务 | 待发起、计算中、待确认、已完成或策划失败 | 计算完成不等于正式落库/确认完成 |
| 单条内容 | 待定题、待生产、生产中、已完成、生产失败 | 已规划选题不等于内容生产完成 |
| 批次内容进度 | 完成全部内容生产的账号数/总账号数 | 一个账号3条只完成2条时，该账号不能记为完成 |

Python通过服务内受控执行器推进持久化任务，租约、断点和缓存用于恢复；不需要另启一个独立Worker进程，也不由Python自行定时跑周策划。执行预算和模型超时不是“每批固定15秒必定完成”的保证。

| Python算法库 | `godp_system_config`、`godp_strategy_config`、版本及算法配置命令 | 运行配置、算法权威配置与回执；凭据不打印 |
| Python算法库 | `godp_topic_label_job`、标签/标签历史、`godp_t6_tag`、`godp_topic_profile` | 本次选题标签与向量是否就绪、有无失败及模型不一致 |
| Python算法库 | `godp_ai_preparation`、账号/选题准备、准备进度 | 当前自动任务的账号画像与向量主要在准备表，不应只查旧批次`godp_account_profile` |
| Python算法库 | 映射规则、策略、匹配任务/输入/尝试、质量报告与缓存 | 规则审核、策略指纹、模型依据、租约及未匹配原因 |
| Python算法库 | `godp_planning_pipeline_run`、阶段、`godp_algorithm_proposal` | 全阶段、不可变提案及Java确认 |

同名旧业务表可能仍留在Python库用于历史追溯，不代表当前正式写入归属。页面配置版本、业务配置版本、策略版本、词表版本和映射版本是不同对象，不要求编号相同，但必须记录彼此关联及实际内容。

## 8. 推荐实际测试顺序

### A. 先做离线回归：不访问真实模型/数据库

在仓库根目录：

```bash
python -m testing
python -m testing --suite algorithm --dataset scale
```

输入是`testing/data/small.json`的5账号/60选题/15位置，或`scale.json`的100账号/600选题/300位置；向量与模型响应为合成固定回放，只执行V19代码。输出`run/regression/<时间戳>/`，核查`summary.json`、`algorithm.json`和`report.html`。它能证明代码回归和固定约束，不能证明真实模型效果或服务闭环。

### B. 核查日常测试资料

```bash
python -m testing.complete_accounts
```

默认只检查；需补齐时才使用`--apply`，工具会备份并标记模拟补充字段。本轮90个账号资料已补齐。检查源实体字段、返回对象、页面字段三处，不以“JSON文件里有值”替代页面验收。

### C. 跑一个普通自动周期的真实模型与双库闭环

准备：outside、前端和Java页面服务可访问、两个库已发布、V19正式策略已批准、模型可用、无其他活动Pipeline/标签任务。**先暂停本地Java自动脉冲**，避免同库两个执行方竞争；可用`--planning.local-pulse.enabled=false`启动日常Java页面服务。验收工具目前不会自动完成暂停/恢复。

```bash
python -m testing.live --execute
```

工具生成新资料及空闲周期，先验证日常Java资料入口，再追加资料；模拟宿主时钟，启动Java验收驱动和隔离的Python计算进程，资料始终取自日常Java服务。实际推进画像、向量、V19、Java落库/确认、模拟内容、使用次数，再通过930前端代理核查页面与导出。会调用真实模型、写当前开发库，不是内存演练，也不是独立物理测试库。

每一步验收标准：1账号/12输入选题；所有输入就绪；3位置完整匹配；Java正式明细3条；Python确认成功；内容状态逐步推进3/3；账号内容进度1/1；3个选题使用次数各1；重复触发/状态读取不增加结果；CSV3条且有选题ID；XLSX格式有效。

本次已经通过：Pipeline14、匹配任务22、正式批次`2000000000004`。周期2027-02-22至02-28为避开旧数据选择的未来周期，模拟触发时刻是2027-02-16北京时间22:00，不是当前墙钟到期。业务配置是测试宿主注入快照，热点/营销均为0，**不代表已经真实验收了修改页面配置到自动取用新版本的全过程**。

### D. 成功后只读复核；未完成才恢复

```bash
python -m testing.live_verify run/full-chain/20261103122042
```

读取正式结果，经前端代理核查账号/周期/批次范围、状态、计数和CSV/XLSX，不再调用模型。

未完成任务且属于本工具时，才用`python -m testing.live --execute --resume run/full-chain/<目录>`继续原任务。存在`business.json`的任务不重新生产；输入/候选/策略有业务错误时不能通过修改冻结内容“恢复”。恢复工具尚未完全隔离其他活动队列，执行时仍须独占这轮开发验收。

结束后恢复原本的Java模拟调度，检查三个服务健康及有无遗留待确认任务。`summary.json`代表工具断言；浏览器逐页点击、弹窗、滚动、分页等仍要单独验收。现有XLSX断言只验证容器格式，不等于完整检查了工作簿内容、列及样式。

## 9. 进入行内：具体替换清单

| 层面 | 保留 | 必须替换/装配 | 验收方式 |
| --- | --- | --- | --- |
| Vue | 三页及业务组件、字段语义、交互 | 宿主菜单、路由、请求封装、统一响应、认证与下载 | 所有页面请求到宿主Java，不能直连Python |
| Java工程 | 业务Service、Repository、Mapper接口/XML、DTO | 宿主Parent/BOM、扫描、组件注册、MyBatis资源及同库事务 | Mapper能加载；回滚确实作用于本模块业务库 |
| 基础资料 | 既定实体/分页语义及`HostSourceAdapter`组合边界 | `AccountFacts`、`TopicFacts`、`SnapshotFacts`及必要资格查询：用行内表结构写SQL/调用现成服务 | 实际账号/选题对象与约定一致，分页稳定；不是把原始行内表名写进Python |
| Python取数 | `JavaHTTPSource`、DTO强校验、核心算法 | Java资料地址、鉴权、路径/字段适配；宿主提供对应查询入口 | 账号/选题/营销/状态查询返回正确实体，资料不经旧Python夹具 |
| 内容衔接 | Java补题、营销引用、投放日期及内容状态服务 | `PlanningContentPort`四类事实、`ContentStatusSource`、`MarketingStatusSource`；内容侧扫描/关联实现 | 真正读到生产、审核、分配、有效投放；空列表不能当成功 |
| 调度 | Java业务推进服务、Python持久化执行与唤醒客户端 | 客户Job调用入口、频率、游标、重试、监控和告警 | 同时观察Java业务状态与Python技术状态，不能只监控HTTP200 |
| 数据库 | Java业务表/查询视图、Python算法扩展与冻结设计 | 两库各自脚本发布、数据源权限、保留策略；确认数据库对JSON/视图SQL的兼容 | 无Python直连业务库；无需给行内资料造策划侧算法ID |
| 操作人/权限 | 业务校验及操作语义 | `ManualPorts.Actor`、宿主可信用户上下文、数据范围、审计 | 页面传来的UM不能覆盖可信操作人；跨组织越权被拦截 |
| 模型/网络 | 打标、向量、映射、精判的算法契约与输出校验 | 客户允许的模型通道、代理/鉴权、provider响应适配；必要时替换豆包适配 | 两类模型均可用，向量空间一致；改模型名不保证新协议自动兼容 |
| 运行部署 | 三工程模块边界和持久化恢复能力 | 宿主构建/部署/日志/健康检查和离线依赖 | 不携带本地启动壳、模拟Job、测试HTTP宿主、`run/`私有文件入生产 |

`standalone/**`、`adapter/local/**`、本地旧页面通配代理用于行外；inside明确排除这些装配。Java业务模块及Python客户端可迁入，不应继续把整个Java当作无业务的通配转发。当前Python仍保留部分算法页面兼容路由，宿主需要显式接入，不能复制local白名单就认定所有页面/OP已开放。

模式开关`PLANNING_ENV=inside`只负责选择/预检，不会生成未知SQL、登录上下文或内容事实。模型名称/Key等仍在算法库配置表；若宿主要求配置中心，应替换配置读取边界。本地数据库连接引导参数和私有Java启动文件不作为行内最终配置方式。

账号、选题、营销与内容事实是Java提供给本模块的查询能力，不再是本项目主动同步落基础表的一组接口。旧Word中的IF/OP编号与旧HTTP形式需要另外同步；这里按实际能力解释，不擅自增删已确认的业务字段。

内容状态关联需要读取本模块正式结果中的明细及版本，再与内容方任务/内容建立关系。这不等于要求行内原始账号、选题表预先拥有Pipeline、策略、准备任务等内部ID。
