# 策划内容配置：内容生产时间

日期：2026-11-05。按用户确认的普通、营销、热点三类分别设置内容生产时间与投放日期的关系，不按12种选题二级分类配置。

## 页面与规则

“AI策划配置 → 策划内容配置”增加“内容生产时间”，三类各一项，沿用默认只读、点击编辑后修改、统一保存的交互。

- T代表投放日期；T−x表示提前x个自然日开始生产。
- 允许0至365的整数，0表示投放当天；负数、小数及超出范围不能保存。
- 未填写显示“未配置”，不隐式采用T−0或其他默认天数。
- 问号气泡解释T、T−3和T−0。配置以已确定的投放日期为基准；人工营销需求尚无投放日期时，不能据此计算生产日。
- 历史详情逐类展示取值，并在修改摘要中列出差异。旧版本未包含此字段时显示“未记录”，不补造旧值；恢复旧版本后该项恢复为未配置。

已完成前端配置、Java持久化、历史恢复及业务快照兼容。后续已新增[到T−x日期写入内容流水的Java扫描服务](账号策划结果写入内容流水_2026-11-05.md)，每天由宿主调度3次；现成内容流水表的真实SQL映射仍待接入。内容实际生产由内容侧执行，Python不新建调度器。

## 数据归属与发布

页面字段为`content_production_lead_days`，对象键为`ordinary`、`marketing`、`hotspot`，值为整数或空。例如`{"ordinary":3,"marketing":0,"hotspot":1}`。键缺失或值为空均代表未配置。

该字段属于Java业务规则：综合配置发布时从算法配置参数中剔除，保存在业务配置及综合发布快照中。Python仅允许在Java业务冻结快照里接收该字段；缺少新字段的旧任务不补默认值，保持原有快照内容，避免恢复执行时指纹改变。

业务库两张表新增`content_production_lead_days_json VARCHAR(255) NULL`，均有中文注释：

- `godp_business_planning_config`：当前值。
- `godp_business_planning_config_version`：业务历史值。

新库使用完整`business-planning-config.sql`。存量库先备份并停止Java写入，再按[业务库V7迁移](../java-backend/godp-planning-services/src/main/resources/db/migrations/V7__content_production_lead_days.sql)执行；脚本执行一次，已存在列时不重复执行。算法库无新增表或列。

当前开发业务库已完成升级，原配置1行、业务历史4行的既有列指纹核对一致；未改变现有配置值和版本。受控备份及校验结果位于`run/backups/production-timing-20261105/`，不提交Git。共用同一数据库的阿里云实例无需再次执行V7；其他独立数据库须自行核查和发布。
