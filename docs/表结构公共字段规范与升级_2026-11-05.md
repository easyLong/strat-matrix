# 表结构公共字段规范与升级

日期：2026-11-05。依据客户截图中的六公共字段要求，范围为当前正式运行的25张Python算法表和14张Java业务表。完整逐表结果见[234项字段核查CSV](表结构六公共字段核查_2026-11-05.csv)。

## 1. 统一规范

```sql
id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID',
del_flag VARCHAR(1) NOT NULL DEFAULT 'N' COMMENT '删除标志：N正常、Y删除',
created_by VARCHAR(50) NOT NULL DEFAULT 'system' COMMENT '创建人',
updated_by VARCHAR(50) NOT NULL DEFAULT 'system' COMMENT '修改人',
created_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
updated_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
    ON UPDATE CURRENT_TIMESTAMP COMMENT '修改时间'
```

MySQL实际主键索引均为BTREE。新建SQL、实际字段元数据、默认值、非空约束、中文注释及主键共同校验，不能仅凭存在六个字段判定通过。

## 2. 兼容现有业务的处理

- 原本已有`id`的表保留全部ID值，非自增ID增加自增属性，不重新编号批次或明细。
- 原本使用业务编号或联合主键的表增加自增`id`；旧主键保留为唯一键，命令幂等、一个账号一天占用、资源引用等约束仍有效。
- `create_by/update_by/create_time/update_time`和`created_at/updated_at`等存量字段暂保留，继续承担已有接口、业务排序或兼容用途。规范字段已真实参与写入，不是替换前端返回字段名称。
- Python明确写入旧操作人字段时同步规范字段；Java统一从可信请求上下文或服务端参数记录UM，后台无操作人时为`system`。操作人超过50字符明确拒绝，不静默截断。
- 查询、任务领取、报表视图和使用次数统计过滤已删除记录。人工账号占用释放改为逻辑删除，再次占用可复用已释放行；仍有活跃占用时维持冲突保护。
- 新公共时间字段从历史日期或毫秒时间戳回填，原微秒业务/租约时间保留。没有可用历史审计时间的记录使用迁移时刻，不虚构历史时间。UTC转换在迁移会话内进行。
- 废弃的Python历史业务表不纳入正式39表发布集合，本轮没有删除这些历史表。

## 3. 新库与存量库发布

新库使用完整建表脚本：Python的`algorithm_schema.sql`；Java的`manual-business.sql`、`business-planning-config.sql`、`auto-planning-business.sql`、`slot-completion.sql`及查询视图。Python算法DDL生成和校验强制检查六字段，Java集成测试覆盖14张表。

存量库推荐在仓库根目录使用受控迁移工具。先停止Java调度及两侧后端，确认没有计算任务在执行，并按现场要求完成备份；不能在运行中的旧Java JAR上执行Maven打包。

```bash
# 默认只读预检和生成升级SQL，不执行ALTER
python python-backend/tools/migrate_table_audit.py --output /受控目录/audit-release

# 显式执行；算法与业务库均先通过预检，逐表保存原DDL、元数据和完整数据
python python-backend/tools/migrate_table_audit.py --apply --output /受控目录/audit-release

# 中断后使用相同原始备份恢复，不覆盖备份
python python-backend/tools/migrate_table_audit.py --apply --resume --output /受控目录/audit-release

# 升级后只读验收，存在不符合项返回退出码2
python python-backend/tools/migrate_table_audit.py --check --output /受控目录/audit-check
```

`--owner algorithm`或`--owner business`可分别发布两库。此工具仅用于部署，不由运行服务跨库调用；现场两库由不同人员发布时分别提供对应数据库权限。

工具使用数据库命名锁、操作人长度及删除标志预检、逐表备份、可恢复ALTER、历史回填、原业务字段SHA256核对，并重建业务查询视图。MySQL DDL自动提交，不能以事务回滚代替备份；出错时停止，修正问题后用原备份恢复推进。升级完成后重新执行不会重复增加字段或重编ID。

重复验收使用`--check`；新的发布使用新输出目录，中断恢复才使用原目录加`--resume`。工具拒绝覆盖已有备份，不能将恢复命令当作运行期间的日常修复命令。

供DBA评审的基线增量SQL：

- [算法库迁移SQL](../python-backend/migrations/20261105_standard_public_columns.sql)
- [业务库V6迁移SQL](../java-backend/godp-planning-services/src/main/resources/db/migrations/V6__standard_public_columns.sql)

静态SQL只适用于本轮升级前的完整基线，不能对已经升级或部分升级的库直接重放；这类环境使用上面的元数据迁移工具。备份含配置密钥或业务快照，应保存在受控目录，不上传GitHub或对外发送。
