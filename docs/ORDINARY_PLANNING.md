# 普通内容周策划首版

本版可由服务器命令或独立调度进程触发。它读取当前服务端配置和最近一次同步的账号、普通选题本地副本，为目标周的每个账号按“每周策划日”生成普通内容槽位。运营可在“AI 自动策划”和“策划结果”页面查询批次。

## 首次部署

在项目根目录执行结构更新；新表和新增字段均带中文注释：

```bash
cd backend
python3 -m app.init_db
```

若使用虚拟环境，将 `python3` 换为 `.venv/bin/python`。

## 触发下一周策划

已有演示数据时：

```bash
cd backend
python3 -m app.ordinary_planning --scope demo
```

使用正式同步数据时：

```bash
cd backend
python3 -m app.ordinary_planning --scope live
```

可用 `--cycle-start 2026-10-12` 指定目标周的周一日期。只允许策划下周或更晚的完整自然周。重复执行同一范围和周次会返回原批次，不会重复插入槽位；如果该周已有其他自动批次，命令会拒绝叠加。

## 自动调度

Linux 部署时 `./start.sh` 默认启动 `ordinary-scheduler` 独立进程；`./stop.sh` 和 `./status.sh` 同时管理它。调度进程每分钟读取服务端当前配置，按北京时间检查 `schedule_day` 与 `schedule_time`。到时为下一自然周执行正式数据范围的普通兜底策划；本周到时后启动也会补跑，过了本周不会为过去的周期补跑。同周多进程触发由数据库锁和唯一运行记录去重。

缺少正式同步账号或普通选题、数据库暂不可用等情况会写入 `logs/ordinary-scheduler.log`，一小时后重试。演示数据不会进入自动调度。可以设置 `.env` 中的 `ORDINARY_SCHEDULER_ENABLED=0` 并重启脚本，停用该进程。单次按当前配置检查可执行：

```bash
cd backend
python3 -m app.ordinary_scheduler --once
```

## 数据准入与结果

- 账号须有本地同步来源、账号档案处于启用状态，且来源记录未停用。演示与正式账号分开处理。
- 普通选题须有本地同步来源、目录可用、当前有效、未停用且不是营销选题；演示与正式选题分开处理。
- 选题按来源 `topic_heat` 从高到低排序，同热度按选题 ID 排序；同账号一周内优先使用不同选题。缺少热度时按 0 处理。
- 生命周期依据来源粉丝数和近三个月已发布内容计算；单篇互动数为点赞、收藏、评论之和，滚动窗口使用配置的篇数。结果保存策划时的阶段和经营作用快照。
- 批次、槽位、当前结果版本和输入快照在同一数据库事务中写入。批次备注明确标记为“普通选题热度兜底；未执行 AI 匹配”。

本版尚未运行向量匹配和营销/热点槽位规划；自动调度运行的是普通选题热度兜底，普通兜底结果不自动发送内容生产任务。正式结果查询和发布回传已有[本地对接接口](IF05_IF06_本地对接契约.md)，客户的最终技术协议仍待确认。
