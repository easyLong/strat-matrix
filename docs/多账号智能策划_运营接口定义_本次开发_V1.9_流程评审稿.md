# 多账号智能策划接口定义

V1.9 流程评审稿｜基于已修订的 V1.8 文档；本轮修正同步方向，重设内容生产提交与账号周期结果查询。

## 业务流程与责任

1. 策划系统生成账号的一周槽位，确定账号、投放日期和槽位类型。

2. 普通、营销槽位在当晚确定选题、大纲、内容类型及对应内容Agent后，逐槽位调用IF-05发起内容生产。

3. 热点槽位提前保留；投放前一日确定选题及生产所需信息后，逐槽位调用IF-05。未确定选题的热点槽位继续等待。

4. 内容方受理后异步调用指定内容Agent生成内容；受理成功只表示任务已接收。

5. 内容方通过OP-02回传对应槽位的生产结果。策划侧校验后更新该槽位的内容状态。

6. 槽位内容生产成功并经回传确认后，策划侧记录选题使用事实，供OP-03查询统计。

流程关系：槽位定题 → IF-05提交内容生产 → 内容Agent异步生产 → OP-02回传槽位生产结果 → 更新内容状态及选题使用统计。

OP-01是账号周期策划结果的辅助查询入口；IF-05主动提交生产所需的完整输入。OP-05用于独立测试打标效果；OP-04查询已保存标签。

| 参与方 | 负责内容 |
| --- | --- |
| 策划系统 | 固定槽位、确定选题和内容Agent、提交生产任务、接收回传、维护槽位内容状态和选题使用统计 |
| 平台内容生产方 | 提供IF-05，接收任务、调用指定内容Agent、管理生产执行、通过OP-02回传结果 |
| 行内选题方 / 运营 | 查询策划结果和统计，按需提交选题详情测试打标效果 |

## 状态与统计口径

| 状态 | 业务含义 | 是否计入选题使用次数 |
| --- | --- | --- |
| 待定题 | 槽位尚未确定选题，例如未触发的热点槽位 | 否 |
| 待生产 | 已确定选题及生产输入，尚未成功提交 | 否 |
| 生产中 | 内容方已受理，策划侧等待异步结果 | 否 |
| 已完成 | OP-02确认内容生产成功，该槽位完成本次生产闭环 | 是 |
| 生产失败 | 内容方回传生产失败，等待处理或重试 | 否 |

策划完成与内容生产完成分别记录。一周槽位已规划完成时，热点槽位仍可处于待定题，其他槽位可以先进入生产；一个槽位成功不会直接把整周内容标记为全部完成。

选题使用次数以“内容生产成功并确认回传”为统计时点，覆盖普通、营销、热点选题。初次成功的一个槽位形成一次使用；同一选题用于两个不同槽位并各自生产成功，计两次。任务受理、失败、查询、打标测试不计数；同一次成功结果的重复通知和接口重试不得重复计数。无需等待内容发布。

生产结果回传须对应槽位、结果版本和生产任务，当前有效成功回传对应的状态变更和使用事实应一起生效，避免状态已完成但统计遗漏。

同一槽位在生产中后，不准更换选题再生产。

## 接口总览

按接口提供方分类：IF由行内系统提供，OP由策划系统提供；调用发起方与接口提供方分别说明。接口按分类连续编号，共10个接口：IF-01至IF-05及OP-01至OP-05。

OP-01至OP-03依次为账号周期策划结果查询、槽位内容生产结果回传、选题内容生产使用次数查询；OP-04和OP-05为选题标签查询、选题批量打标效果测试，集中放在最后。

| ID | 接口名称 | 提供方 | 调用方 | 用途 |
| --- | --- | --- | --- | --- |
| IF-01 | 账号基础信息、人设及互动数据同步 | 行内账号系统 | 策划系统 | 获取账号事实 |
| IF-02 | 普通选题同步 | 行内选题系统 | 策划系统 | 按数据更新时间范围拉取普通选题详情 |
| IF-03 | 营销选题同步 | 行内营销选题系统 | 策划系统 | 按账号 ID 和数据更新时间范围拉取绑定营销选题 |
| IF-04 | 热点选题同步 | 行内热点选题系统 | 策划系统 | 按数据更新时间范围拉取热点选题，与 IF-02 结构一致 |
| IF-05 | 槽位内容生产任务提交 | 行内内容生产方 | 策划系统 | 按槽位提交策划、账号、选题与内容 Agent 完整信息，异步生产 |
| OP-01 | 账号周期策划结果查询 | 策划系统 | 行内平台 | 按账号和明确自然周查询全部批次、自动及人工策划与单条内容状态 |
| OP-02 | 槽位内容生产结果回传 | 策划系统 | 行内平台 | 回传生产结果，更新槽位状态 |
| OP-03 | 选题内容生产使用次数查询 | 策划系统 | 行内选题系统 | 查询生产成功形成的选题使用次数 |
| OP-04 | 选题标签查询 | 策划系统 | 行内选题系统 | 按选题ID查询已保存标签 |
| OP-05 | 选题批量打标效果测试 | 策划系统 | 行内选题系统 / 运营测试入口 | 提交选题详情并查看测试标签，独立于内容生产流程 |

## 接口定义

### IF-01 账号基础信息 + 账号人设 + 互动数据离线同步接口

| 接口用途 | 每日夜间离线同步平台账号池、账号基础信息、账号人设及近3个月历史互动数据，供AI自动策划、手动筛号、生命周期判断、账号画像及新增账号识别使用。账号基础信息包含账号ID、昵称、属主UM号、属主组织、业务线、平台、地域、粉丝量和账号状态。 |
| --- | --- |
| 调用时机 | 每日夜间离线任务执行时同步；自动策划和手动策划执行时不实时调用IF-01，直接读取策划系统最近一次成功同步的数据快照。 |
| 提供方/发起方 | 平台账号系统提供账号事实及近3个月互动数据；策划系统接收并计算策划指标。 |

| 请求字段 | 字段含义 |
| --- | --- |
| 无核心业务请求字段 | 默认同步当前账号池；全量/增量、分页等技术参数由后续接口文档定义。 |

| 返回字段 | 字段含义 |
| --- | --- |
| account_id | 账号唯一标识 |
| account_name | 账号昵称 |
| um_no | 属主UM号 |
| account_status | 账号状态，表示账号是否有效及是否可参与策划 |
| organization | 属主组织 |
| account_persona | 账号人设；描述账号内容定位、身份设定和表达方向，是账号画像、向量生成及选题匹配的核心输入 |
| business_line | 业务线 |
| platform | 账号所属平台 |
| region | 账号地域；当前本地数据层兼容映射为地域/城市字段 |
| follower_count | 账号当前粉丝量 |
| interaction_data | 账号近3个月帖子级互动明细：发帖时间、帖子标题、红星数、收藏数、评论数；用于有效内容篇数、滚动互动、流量趋势、生命周期判断和账号画像。流量趋势由策划系统基于该数据计算，不作为IF-01独立字段。 |

### IF-02 普通选题同步接口

| 项目 | 定义 |
| --- | --- |
| 接口用途 | 策划系统按时间范围主动拉取普通选题，保存至本地，供 AI 候选、人工选题及替换选题使用。 |
| 提供方 / 调用方 | 行内普通选题系统提供；策划系统调用。请求传查询条件，选题详情由行内系统返回。 |
| 调用时机 | 自动策划执行前完成同步；人工策划及替换选题直接使用最近一次成功同步的数据。 |

| 请求字段 | 字段含义 |
| --- | --- |
| start_time | 必填，数据更新时间范围的起点，包含该时刻；用于拉取此后新增或发生变更的选题。 |
| end_time | 必填，数据更新时间范围的终点，不包含该时刻，且须晚于起点；不表示选题有效期或计划投放日期。 |

| 返回字段 | 字段含义 |
| --- | --- |
| topics | 符合本次更新时间范围的普通选题数组；下述 topics[] 字段描述其中每条选题。无符合记录时返回空数组。 |
| topics[].topic_id | 选题唯一标识，沿用源系统已确认的选题 ID。 |
| topics[].title | 选题标题。 |
| topics[].outline | 选题大纲 / 核心内容。 |
| topics[].topic_type | 选题业务类型：营销 / 非营销，沿用已确认字段；不以普通、热点等来源名称替代该枚举。 |
| topics[].content_type | 内容类型，对应已确认的二级分类（12 种），直接继承源系统。 |
| topics[].topic_heat | 选题热度；用于候选排序及相应兜底规则。 |
| topics[].status | 选题当前有效 / 失效等可用状态；已失效或撤回的变更也须返回，供策划侧更新本地记录。 |
| topics[].valid_from | 选题有效期起点；为空表示起点不限制。与本次同步的 start_time 区分。 |
| topics[].valid_to | 选题有效期终点；为空表示终点不限制。与本次同步的 end_time 区分。 |
| topics[].updated_at | 该条选题在源系统的最后更新时间，也是本接口时间范围筛选所依据的时间。 |

同步口径：统一使用北京时间，时间表示为 YYYY-MM-DD HH:mm:ss，筛选区间为 start_time ≤ updated_at < end_time。每次成功同步后，下一次从上次 end_time 继续拉取；首次同步需覆盖双方约定的历史保留范围，不能只取当天新建选题。新增、标题/大纲/热度/审核/有效期等更新及失效变更均应更新 updated_at；硬删除需先转换为可同步的失效记录，避免本地保留已撤回选题。分页规则由技术对接补充，须完整拉取本时间段全部记录后再推进同步进度。

返回空数组仅表示本次时间范围没有变更，不删除策划系统已保存的选题。参数不合法、接口异常或同步失败须明确返回失败，不能以空数组表示成功。

### IF-03 营销选题同步接口

| 项目 | 定义 |
| --- | --- |
| 接口用途 | 策划系统按指定账号和时间范围主动拉取绑定该账号的营销选题及审核信息，保存至本地。 |
| 提供方 / 调用方 | 行内营销选题系统提供；策划系统调用。 |
| 调用时机 | 自动策划执行前，按参与策划的账号逐个同步；运行时读取本地最新成功同步数据。 |

| 请求字段 | 字段含义 |
| --- | --- |
| account_id | 必填，查询营销选题所绑定的账号 ID；本次仅返回该账号的记录，不传或为空不能解释为查询全部账号。 |
| start_time | 必填，数据更新时间范围的起点，包含该时刻；用于拉取此后新增或发生变更的选题。 |
| end_time | 必填，数据更新时间范围的终点，不包含该时刻，且须晚于起点；不表示选题有效期或计划投放日期。 |

| 返回字段 | 字段含义 |
| --- | --- |
| topics | 符合账号和更新时间范围的营销选题数组；没有符合记录时返回空数组。 |
| topics[].topic_id | 营销选题唯一标识。 |
| topics[].account_id | 该选题绑定的账号 ID，须与请求 account_id 一致。 |
| topics[].title | 营销选题标题。 |
| topics[].outline | 营销选题大纲 / 核心内容。 |
| topics[].topic_type | 选题业务类型，固定为营销。 |
| topics[].content_type | 内容类型，对应已确认的二级分类（12 种），直接继承源系统。 |
| topics[].status | 选题当前有效 / 失效等可用状态；不能用审核状态替代可用状态。 |
| topics[].audit_status | 审核状态：待审核 / 审核通过 / 审核驳回等；统一沿用原返回字段 audit_status，不再并列使用 approval_status。 |
| topics[].approved_at | 审核通过时间；未通过时可空。多条可用营销选题按该时间升序逐条优先使用。 |
| topics[].valid_from | 选题有效期起点；为空表示起点不限制。 |
| topics[].valid_to | 选题有效期终点；为空表示终点不限制。 |
| topics[].topic_heat | 营销选题热度，用于已确认的排序或运营筛选。 |
| topics[].updated_at | 该条记录在源系统的最后更新时间；审核、绑定关系及失效状态变更也须更新此时间。 |

时间范围、空数组、分页及异常处理口径与 IF-02 一致。查询范围包含绑定该账号的所有变更记录，不只返回当前审核通过的记录，避免本地遗漏撤审或失效变化；实际策划仍须同时校验绑定账号、有效状态、审核通过和投放日有效期。

绑定关系变更时，原账号须能获取解除绑定 / 失效记录，新账号须能获取新的绑定记录；各账号分别保存成功同步进度，单个账号同步失败不应推进其进度。

### IF-04 热点选题同步接口

| 项目 | 定义 |
| --- | --- |
| 接口用途 | 策划系统按时间范围主动拉取热点选题，供已保留的热点槽位在投放前一日确定具体选题。 |
| 提供方 / 调用方 | 行内热点选题系统提供；策划系统调用。 |
| 调用时机 | 目标热点槽位投放前一日 22:00 任务执行前完成同步，定题时读取本地最新有效热点。 |
| 与普通选题的一致性 | 请求条件、返回字段结构、时间范围及同步处理规则与 IF-02 一致，仅数据来源和用途不同。 |

| 请求字段 | 字段含义 |
| --- | --- |
| start_time | 必填，数据更新时间范围的起点，包含该时刻；用于拉取此后新增或发生变更的选题。 |
| end_time | 必填，数据更新时间范围的终点，不包含该时刻，且须晚于起点；不表示选题有效期或计划投放日期。 |

| 返回字段 | 字段含义 |
| --- | --- |
| topics | 符合本次更新时间范围的热点选题数组；下述 topics[] 字段描述其中每条选题。无符合记录时返回空数组。 |
| topics[].topic_id | 选题唯一标识，沿用源系统已确认的选题 ID。 |
| topics[].title | 选题标题。 |
| topics[].outline | 选题大纲 / 核心内容。 |
| topics[].topic_type | 选题业务类型：营销 / 非营销，沿用已确认字段；不以普通、热点等来源名称替代该枚举。 |
| topics[].content_type | 内容类型，对应已确认的二级分类（12 种），直接继承源系统。 |
| topics[].topic_heat | 选题热度；用于候选排序及相应兜底规则。 |
| topics[].status | 选题当前有效 / 失效等可用状态；已失效或撤回的变更也须返回，供策划侧更新本地记录。 |
| topics[].valid_from | 选题有效期起点；为空表示起点不限制。与本次同步的 start_time 区分。 |
| topics[].valid_to | 选题有效期终点；为空表示终点不限制。与本次同步的 end_time 区分。 |
| topics[].updated_at | 该条选题在源系统的最后更新时间，也是本接口时间范围筛选所依据的时间。 |

沿用 IF-02 的同步口径：按源数据 updated_at 范围拉取，不按选题有效期过滤同步记录；定题时再根据投放日校验有效期。已过时、撤回或失效的热点变更同样返回；无变更时返回空数组，接口失败须明确报错。

### IF-05 槽位内容生产任务提交接口

| 项目 | 定义 |
| --- | --- |
| 接口用途 | 策划系统把一个账号一个槽位的完整生产输入交给内容方，内容方按指定内容 Agent 异步生产。 |
| 提供方 / 调用方 | 行内内容生产方提供；策划系统调用。 |
| 调用时机 | 普通、营销槽位当晚定题后逐条提交；热点槽位投放前一日定题后逐条提交。未定题的热点槽位不提交。 |
| 任务粒度 | 一次提交只对应一个 slot_id 的一个策划结果版本。多个账号、多条槽位分别提交和回传。 |
| 交互方式 | 同步返回是否受理，受理后异步生产；最终成功或失败由内容方通过 OP-02 回传。 |

#### 请求结构

| 请求字段 | 字段含义 |
| --- | --- |
| production_task_id | 必填，本次生产任务的唯一标识，由策划系统提交前生成；内容方保存并在 OP-02 原样回传。 |
| planning_info | 必填，策划信息对象，见下表。 |
| account_info | 必填，账号信息对象，见下表；携带本次生产采用的快照。 |
| topic_info | 必填，选题信息对象，见下表；携带本次策划最终选定的标题、大纲、类型和标签。 |
| content_agent | 必填，内容 Agent 对象，见下表。 |

#### 策划信息 planning_info（对象内字段）

| 字段 | 字段含义 |
| --- | --- |
| slot_id | 必填，槽位唯一标识。同一账号同一天可以有多条策划，不能只用账号和日期定位。 |
| planning_result_id | 必填，该槽位当前策划结果的唯一标识。 |
| version | 必填，当前策划结果版本；替换选题形成新版本，生产回传必须对应本次提交版本。 |
| batch_id | 必填，所属策划批次的唯一标识。 |
| batch_code | 必填，批次编号，供业务查询及核对。 |
| batch_name | 批次名称；人工任务使用任务名称，自动批次使用自动命名。 |
| plan_type | 必填，策划方式：自动策划 / 人工策划。 |
| cycle_start | 必填，所属自然周起始日期，周一，YYYY-MM-DD。 |
| cycle_end | 必填，所属自然周结束日期，周日，YYYY-MM-DD。 |
| publish_date | 必填，计划投放日期，须在所属周期内。 |
| publish_time | 计划投放时刻，HH:mm；未配置具体时刻时为空，不补成虚构时间。 |

#### 提交与状态规则

提交前须检查账号可参与策划、槽位已定题、投放日期在选题有效期内，以及必填的策划信息、账号人设、选题大纲、内容类型和内容 Agent 齐备；营销选题同时检查账号绑定与审核通过。字段表未标必填的字段可空，但有值时须携带真实快照。

同一 production_task_id 的传输重试必须使用相同输入，并返回已有任务；相同任务号却携带不同槽位、版本、选题或大纲应拒绝，不能悄悄覆盖。即使换一个任务号，也不能对同一槽位同一版本重复创建正在生产的任务；输入相同时返回已存在及原任务标识，策划侧保存原任务关联；输入冲突时拒绝受理。

首次确认受理后，策划侧将尚未进入终态的该槽位置为生产中并锁定替换选题；若打开替换窗口后才开始生产，提交替换时也须校验并拒绝。晚到或重复的受理响应不把已完成或生产失败的当前状态退回生产中。未受理或网络超时不能记为生产成功；超时先以原任务号重试确认，不能另起任务导致重复生产。

内容方通过 OP-02 回传 production_task_id、slot_id、version 和实际选题，策划侧核对本次任务及版本后更新内容状态。受理响应不增加选题使用次数，生产成功经 OP-02 确认后才计数。

说明：同步接口的 topic_type 保留已确认的营销 / 非营销含义；生产与结果查询对象的 topic_info.topic_type 表示普通 / 营销 / 热点来源，与既有回传、使用统计接口保持一致。原营销 / 非营销值单独放在 business_type 中，两个口径不得混用。

#### 返回与展示规则

复用 IF-05 的对象字段定义，实际返回须展开完整对象，不能只回对象名称、说明文字或选题 ID。已提交生产的结果使用当次提交快照，不能因源选题改名或改大纲而无记录地改变生产输入。页头账号信息用于识别查询对象，历史策划中的账号信息以各条 account_info 快照为准。

热点待定题也必须返回 planning_info 中的槽位、账号、投放日期和批次，content_status 为待定题，topic_info 与 content_agent 为空，生产任务及内容 ID 为空。普通或营销选题尚未定题的异常不能伪装成正常待生产；接口应明确返回数据不完整错误并供策划侧排查。

按投放日期从周一到周日排序；同日按已配置的投放时刻排序，未配置时刻的排在该日有时刻记录之后，再按批次和槽位标识稳定排序。同一天同时有自动和人工策划时返回多条，日历逐条展示。每条策划都携带所属批次，不能只在周期顶部返回一个批次。

账号存在但本周没有策划时，返回账号信息、查询周期、全为 0 的汇总及空 planning_contents 数组；账号不存在、参数无效或系统异常须明确返回对应错误，不能与无策划数据混淆。

示例：同一账号周一有 1 条自动策划和 1 条人工策划、周三有 1 条待生产策划、周五有 1 条热点待定题，则本周返回 4 条策划；周一返回两条，不覆盖成一条，周五保留空槽并展示待定题。
