# 普通内容 AI 匹配算法与策略说明 V1.0 草稿

更新日期：2026-10-12。状态：评审草稿，参数尚未批准，不作为正式匹配的执行配置。正式业务依据为《多账号智能策划_PRD_V1.0.docx》（2026-09-30），主要对应第 3.4.6、3.5、3.6 节。

PRD 已确定处理流程、输入版本和结果语义；向量模型、维度、相似度、Recall Top-K、Fit 特征/权重和全局分配目标函数由本说明确认。以下待定项不提供隐含默认值。

## 已确定的业务约束

1. 普通选题首次入库完成 T1–T6 离线识别；后续内容编辑不触发再次识别。当前有效内容必须有对应画像及向量，失效向量不能进入新匹配。
2. 账号画像与向量使用同一批次读取的基础信息、人设、互动、生命周期和当前经营目标。同一批次各算法阶段使用同一份账号快照。
3. 主链顺序为：双侧画像/向量 → Hard Gate → Recall → Fit → Global Allocation → 组合编排。
4. T1 是普通选题内部的语义属性，不改变选题来源类型。不能因为 T1 包含营销语义就将 IF-02 普通选题转入 IF-03 来源池。
5. Hard Gate 排除违反明确业务约束的账号×选题组合；Recall 获取有限候选；Fit 评估适配程度；Global Allocation 综合所有账号和槽位统一分配；组合编排使生命周期目标作用于实际槽位。
6. 正常策略无结果时，从满足基础可用条件的普通选题中选择热度最高的 1 条兜底；仍无合法选题时，对应槽位失败。内部向量准备失败、调度异常和业务槽位失败分别记录。
7. 营销槽位按账号绑定、资格、周上限、剩余非热点槽位、审核与有效期处理；热点按 T-1 时机确定。两类槽位的普通兜底不能被混同为正式 AI 匹配成功。
8. 手动策划不进行 AI Fit 评分。正式使用计数不由匹配或策划分配次数替代。
9. 运营结果展示经营阶段和经营作用；向量、Recall、Fit、全局分配中间结果仅用于内部处理和审计。

## 需要确认的算法参数

| 编号 | 待定项 | 需要形成的明确规则 |
| --- | --- | --- |
| ALG-01 | 双侧向量空间 | 模型供应方、模型/版本标识、维度；账号与选题输入模板是否共享同一可比较空间；模型升级后的新批次与选题重建规则。仅字符串和维度相同无法证明语义空间相同，供应方须明确承诺。 |
| ALG-02 | Hard Gate 组合约束 | 城市适用范围、账号资格、人设/受众限制、标签关系等哪些属于必须满足的条件；字段为空、范围为空的处理方式。现有“来源可用”校验不等于完整 Hard Gate。 |
| ALG-03 | Recall | 召回信号、相似度计算、Top-K、是否有最低阈值、同分排序和小候选池处理。T6 标签复用的 0.80 阈值独立于召回规则，不能直接套用。 |
| ALG-04 | Fit | 账号/选题画像、T1–T6 关系、阶段目标等特征的定义、权重、归一化、缺失字段处理；是否涉及模型评估，评估失败如何处理。 |
| ALG-05 | 全局分配 | 优化目标、账号间公平性、选题复用约束、同账号去重约束、解不存在或超时时的降级方式、稳定同分规则。 |
| ALG-06 | 目标映射到槽位 | 流量/转化百分比映射实际 N 的取整规则；营销和热点槽位如何计入 N 和目标；缺少某经营作用候选时如何调整。 |
| ALG-07 | 历史与计数 | 账号历史选题的去重窗口、是否使用正式使用计数、计数来源未接入时的处理。未知计数不能直接按 0 使用。 |
| ALG-08 | 兜底资格与排序 | “基础可用条件”的完整清单；Hard Gate 各约束在兜底时是否保留；热度同分规则。同账号连续槽位是否可以复用唯一兜底选题。 |
| ALG-09 | 等待与异常 | 标签/向量尚未完成的等待时限，哪些情况允许进入热度兜底、哪些属于系统异常而重试；部分账号未就绪时是否允许部分运行。 |

每项确认后记录规则版本、确认日期和验收样例。阈值和权重进入版本化的算法配置；供应方地址、凭据留在服务端环境配置。[策略版本及执行任务](MATCHING_EXECUTION.md)已提供保存、确认和绑定能力，但没有预置或批准任何实际策略，也没有内置匹配执行器。

## 工程编排方案

当前规则策划在一次事务中先生成结果、再保存账号画像，账号向量随后异步准备。因此当前 `AUTO-RULE-*` / `AUTO-REG-*` 批次的就绪检查只用于准备诊断；输入就绪不会重新分配这些已产生的结果。

正式 AI 策划按以下编排推进。步骤1至3中的账号/配置冻结、等待向量、普通选题输入冻结已通过独立[准备流程](AI_PREPARATION.md)实现；已批准的算法策略版本和 ALG-07 等其他输入依赖仍待确定：

1. 调度启动时冻结账号与配置，建立准备记录；在任何 AI 分配之前形成该批次账号画像。
2. 等待本批次账号向量及有效选题画像/向量，记录输入尚未就绪的原因。
3. 在一个一致的数据读取中冻结正式匹配的选题、标签稳定 ID/版本、画像指纹、向量模型/维度及策略版本。此后各算法阶段使用同一份已冻结输入。
4. 执行已批准版本的 Hard Gate、Recall、Fit、全局分配和组合编排；单独记录每一步排除及降级原因。
5. 结果写入前复核选题资格和有效版本、槽位未发布状态及结果版本；输入过期时重新准备，避免提交过期结果。
6. 在一次事务中保存结果、槽位状态、结果版本和必要事件；达到业务定义的规划完成条件后进入“已规划”。运行准备状态保持在内部，不能直接映射成运营页面的策划完成状态。

新的正式编排不能把“现有规则结果已写入、账号向量后来就绪”解释为真实 AI 执行。准备检查也不代表候选已满足所有账号组合约束或全局分配一定有解。

## 输入准备接口与验收

当前已实现 [匹配输入就绪检查](MATCHING_PREPARATION.md)，校验批次快照完整性、当前选题版本、单位向量和模型/维度兼容性。检查不调用模型、不运行评分或分配。

规则确认后的验收至少覆盖：有效输入形成完整槽位结果、账号跨批次数据隔离、选题版本改变、账号之间的复用约束、流量/转化结构与 N 的映射、候选不足、合法兜底、无兜底槽位失败、系统异常重试、重复执行幂等、结果提交前发布/替换并发。中间算法值不会显示在运营前台。

基础普通兜底池、按显式窗口读取的历史引用与独立正式计数已接入[第二版补充输入快照](MATCHING_SUPPLEMENTAL_INPUTS.md)。未知热度、计数、历史引用及覆盖状态均保留事实语义，如何参与去重、降级及排序仍按ALG-07/08确认，不自动补零或猜测。

## 下一步依赖

提供 ALG-01 的模型服务和双侧向量空间说明，并确认 ALG-02 至 ALG-09。准备流程与版本化执行任务已可独立管理；正式评分和分配只有在相应规则明确后实现，执行提案须另行通过算法与完整业务验收后提交运营结果。具体模型服务尚未接入时，三个模型执行进程继续保持默认关闭；准备推进进程也默认关闭，启用后只处理已有准备记录。
