# 任务范围输入准备与V2匹配验收

日期：2026-11-02。范围：Python自动策划输入准备与普通选题V2匹配，页面和算法公式未调整。

## 已完成的改造

1. **固定本任务输入范围**：参与账号沿用准备记录的账号快照；候选选题在首次准备检查时确定，为当时可用的普通非营销选题集合。确定范围不等于提前执行召回或改变评分规则。后续新增选题不自动混入同一任务。
2. **限定模型处理范围**：任务打标、选题向量只查询上述选题ID；账号向量只处理本准备记录。无活动Pipeline时，主流程Worker不再顺带处理全局模型队列。独立打标与向量Worker仍保留各自显式入口。
3. **复用并校验**：已有效的标签、画像和向量继续使用。任务绑定文本模型、向量模型和标签字典版本；核查来源内容指纹、画像指纹、标签版本、稳定标签ID及向量模型和维度。已经冻结的任务不重新准备输入。
4. **分批推进**：默认每次最多检查24个作业，30秒后不再接纳新作业；进行中的模型请求仍由原模型客户端超时控制，因此这不是HTTP请求的30秒硬超时保证。每个作业结束即保存阶段和游标；已保存的有效模型结果在进度保存失败后也可复用。失败和退避作业在后续轮次重新检查。
5. **明确等待原因**：选题下架、内容变更、字典或模型变化、缺标签、缺画像、失败向量、不兼容模型或维度等均有对应原因。不会只因少数选题就绪就忽略范围内尚未准备好的候选并提前冻结。
6. **防止并发覆盖**：输入准备使用每任务数据库命名锁；继续沿用标签租约、画像版本和向量回写校验。断点持久化不代替完整的任务续租、崩溃恢复及宿主执行器。

首次确定候选仍需读取可用选题的元数据；本次消除的是模型准备阶段的全局队列遍历，并未宣称已经实现全量资料的分页索引或大规模性能优化。

## 存储及查询

新增策划自有表`godp_ai_preparation_progress`，当前开发库已创建，全部字段带中文注释：

| 字段 | 内容 |
| --- | --- |
| preparation_id | 准备任务ID |
| scope_json | 账号ID、候选选题ID及内容指纹、字典和模型版本，不保存密钥 |
| scope_hash | 固定范围的完整性指纹 |
| progress_json | 当前阶段、各阶段游标、轮次、最近一批统计、就绪数量和等待原因 |
| create_time / update_time | 创建和更新时间 |

已有准备记录详情返回新增`input_preparation`，可查看阶段、游标、账号数、候选数、绑定版本及最近一批就绪报告。原`last_report.waiting_reasons`保存推进检查的详细原因。正常准备仍沿用`waiting_inputs → inputs_frozen`；结构错误等沿用`blocked`。

部署时先应用[增量建表脚本](../python-backend/database/content_planning/migrations/20261102_add_ai_preparation_progress.sql)，或使用现有`python -m app.init_planner_db`初始化入口。该迁移只新增进度表，不删除旧数据。
